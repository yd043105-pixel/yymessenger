# 여양고 온라인 교무실

학교 내부 서버에서 운영하는 Windows 교직원 메신저입니다. 개인·부서·전체 메시지, 첨부파일, 읽음 확인, 검색, 알림, 임시 저장, 교직원 관리, 1:1·단체 채팅, 설문, 원격 지원, 교직원 웹 조회, 할 일과 파일 제출 수합을 제공합니다. 쿨메신저와 별도로 운영하며 기존 기록을 가져오거나 연동하지 않습니다.

학생·보호자용 **별도 외부 공지 서버와 .NET MAUI 휴대폰 앱 소스**도 제공합니다. 교직원 서버가 승인된 가정통신문·공지만 전송하며 개인 업무 메시지는 교내에 유지합니다. Windows의 ‘학교 공지’에서 작성·발송 대기·읽음 현황·회수를 확인합니다. Android APK는 시운행용이며 iPhone 빌드·서명과 실제 외부 운영·스토어 공개는 별도 준비가 필요합니다. [앱·외부 서버 운영 안내](docs/mobile-operations.md)를 참고하세요.

## 교사용 화면

남색 제목줄과 메뉴, 파란 선택 표시를 사용하는 여양 교무실 디자인입니다. 기본 창은 450×820 크기의 조직도입니다. 화면 높이가 작으면 작업 영역에 맞춰 줄어들며 직접 크기를 조절할 수 있습니다. 부서별로 교직원을 펼치고, 이름이나 부서를 검색하며, 체크박스로 여러 수신자를 선택합니다. 이름 첫 글자와 접속 상태 표시를 함께 보여주며 초록 점은 접속 중, 회색 점은 로그아웃 상태를 나타냅니다. 접속 상태는 서버 알림과 정기 조회로 갱신합니다. ‘전체·접속 중’ 필터와 접속자 우선·이름순 정렬을 제공합니다.

교직원을 우클릭하면 메시지 보내기, 파일 보내기, 채팅하기, 설문 보내기, 메시지 관리함, 사용자 정보보기, 즐겨찾기 메뉴가 표시됩니다. 접속 중인 다른 교직원에게는 원격 지원하기·지원받기도 표시됩니다. 로그아웃한 사람에게도 메시지와 파일을 보낼 수 있습니다. 더블클릭하면 해당 교직원에게 보내는 작성 창을 엽니다.

메시지함과 작성 창은 별도 760×640 창으로 열립니다. 왼쪽 메뉴에서 받은함·미확인·보낸함·채팅·설문을 열고, 왼쪽 아래 설정 메뉴에서 방해금지·알림 소리·비밀번호·관리자 기능·로그아웃을 조작합니다. 제목줄의 최소화·최대화·닫기 버튼과 창 크기 조절을 사용할 수 있습니다. 일정 생성·쿨알림톡·휴대폰 SMS·외부 메일 메뉴는 없습니다. 개인 쪽지는 메신저 내부 메시지 기능입니다.

## 채팅·설문·원격 지원

**채팅:** 조직도에서 ‘채팅하기’를 선택하면 1:1 대화방을 엽니다. 같은 두 교직원의 1:1 방은 재사용합니다. 왼쪽 ‘채팅’의 ‘새 대화방’에서는 여러 참여자와 방 이름을 지정합니다. 부서 전체 선택도 가능합니다. 참여자는 생성 시 확정하며 참여자 변경·방 삭제는 첫 버전에 없습니다. Enter는 전송, Shift+Enter는 줄바꿈입니다. 첨부 용량·검사·30일 만료는 쪽지와 같습니다. 오프라인 대화도 저장하며 다음 접속 때 조회합니다. 기록은 100개씩 불러오며 이전 대화를 추가 조회할 수 있습니다. 전송 결과 미확인 대화는 PC에 임시 저장하고 같은 요청 번호로 재시도합니다. 채팅은 쪽지함과 별도로 표시되며, 관리자도 참여하지 않은 방을 조회할 수 없습니다.

**설문:** 왼쪽 ‘설문’에서 새 설문을 만들거나 교직원 우클릭의 ‘설문 보내기’를 사용합니다. 교직원·부서를 선택하며 전체 발송에는 기존 전체 발송 권한이 필요합니다. 단일 선택 객관식·주관식 문항을 최대 20개 추가하고 필수 여부·마감 일시를 설정합니다. 첫 버전은 기명 설문입니다. 대상자만 응답하고 마감 전에는 수정할 수 있습니다. 작성자는 문항별 집계·응답자별 답변을 보고 CSV로 저장합니다. 대상자는 자기 답변만 조회합니다. 작성자가 종료하거나 마감 시간이 지나면 새 응답과 수정을 차단합니다. 익명 설문·복수 선택·설문 삭제는 첫 버전에 없습니다.

**원격 지원:** 접속 중인 다른 교직원을 우클릭합니다. ‘원격 지원하기’는 상대 화면을 보는 요청, ‘원격 지원받기’는 자기 화면을 공유하는 요청입니다. 상대가 수락해야 연결됩니다. 화면 공유자는 ‘마우스·키보드 제어 허용’을 선택하거나 해제할 수 있습니다. 자기 화면을 먼저 공유하는 요청에는 확인 창이 표시됩니다. 공유 중인 PC에는 맨 위에 지원 상태와 ‘지원 종료’ 버튼이 표시됩니다. 지원자는 상대 화면을 클릭한 뒤 마우스·스크롤·키보드로 조작합니다. 어느 쪽에서든 종료할 수 있습니다.

원격 지원의 화면과 입력은 두 교직원 PC 사이의 TLS 암호화 연결로 직접 전송합니다. 학교 HTTPS 서버는 요청·수락·인증서 지문 교환·권한·종료만 관리하고 화면과 입력을 받지 않습니다. 화면 공유 PC가 캡처·압축·입력 적용을, 지원 PC가 화면 복원·표시를 담당합니다. 승인된 두 PC의 임시 인증서 지문을 서로 검증하며 새 외부 서비스나 라이브러리는 사용하지 않습니다. 직접 연결이 차단되면 안내 후 종료하며 서버 중계로 우회하지 않습니다.

서버와 앱은 화면을 녹화하거나 파일로 저장하지 않습니다. 주 모니터만 최대 긴 변 1,280픽셀, 초당 최대 2장으로 공유합니다. 요청은 60초 내에 수락하며 활성 지원은 최대 30분, 계정당 동시에 한 건입니다. 지원 중 서버에 2초마다 권한을 확인하며 응답이 3초 안에 오지 않으면 종료합니다. 공유 PC는 입력마다 제어 허용과 권한 변경 번호를 검사하여 해제 전의 입력이 재허용 후 도착해도 적용하지 않습니다. 서버 또는 PC 직접 연결 끊김·로그아웃·계정 변경·비활성화 시 종료하고 자동 복원하지 않습니다. 잠금·UAC 보안 화면으로 전환하면 지원을 중단합니다. 관리자 권한 앱의 입력은 Windows가 차단할 수 있으므로 직접 조작해야 합니다. 다중 모니터 선택·클립보드 동기화·음성·영상 녹화는 첫 버전에 없습니다. [Windows 원격 입력 제약](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

개발 검증은 원격 요청·수락·접속 정보 보호·직접 암호화 전송·권한 해제·연결 끊김·계정 변경 종료와 서버 중계 메서드 제거를 포함합니다. 같은 PC의 WPF 앱 두 연결을 통해 실제 화면 전송과 별도 검증 창에 Windows 한글 키보드 입력이 도착하는 것도 확인합니다. 최종 원격 제어 사용성은 서로 다른 Windows PC 두 대에서 확인하세요. 학교 PC의 화면 배율·한글 입력기·여러 키 조합·네트워크 지연은 현장 확인이 필요합니다.

업데이트에는 서버와 교사용 앱을 모두 교체해야 합니다. 서버를 종료하고 기존 데이터 폴더를 보존한 뒤 새 서버를 같은 데이터 경로로 실행합니다. 기존 계정·쪽지를 삭제하지 않고 새 테이블을 추가합니다.

## 계정 신청·승인과 자동 로그인

교사용 앱의 로그인 화면에서 ‘계정 신청’을 열고 아이디·이름·부서·비밀번호를 입력합니다. 신청한 계정은 관리자 화면의 ‘계정 승인 대기’에 표시됩니다. 관리자가 승인한 뒤부터 로그인할 수 있으며, 승인 전에는 조직도·메시지에 접근할 수 없습니다. 반려되면 정보를 수정하여 다시 신청할 수 있습니다. 관리자가 직접 등록한 계정과 기존 계정은 이미 승인된 것으로 취급합니다. 승인만으로 관리자·전체 발송 권한이 생기지는 않습니다.

‘Windows 로그인 시 자동 실행’을 체크하면 현재 Windows 사용자로 로그인할 때 앱이 실행됩니다. 로그인 화면이나 설정 메뉴에서 해제할 수 있습니다. Windows 자체의 로그인 화면을 건너뛰는 기능은 아닙니다. 앱을 새 폴더로 옮긴 후 한 번 실행하면 자동 실행 경로를 갱신합니다.

‘이 Windows 계정에서 자동 로그인’을 체크하고 로그인하면 최대 30일 동안 비밀번호 입력 없이 다시 접속합니다. 로그인 정보는 해당 Windows 사용자 계정의 DPAPI로 암호화하며 비밀번호는 저장하지 않습니다. 서버가 늦게 켜지면 30초마다 다시 연결합니다. 로그아웃·비밀번호 변경·계정 비활성화·관리자 계정 수정 시 저장된 로그인 정보는 사용할 수 없습니다. 기간이 끝나면 다시 로그인해야 합니다. 두 옵션을 함께 체크하면 Windows 로그인 뒤 자동 실행·자동 로그인됩니다.

## 웹·할 일·파일 제출

교내 서버 주소 뒤에 `/office/`를 붙여 브라우저로 접속합니다. 예: `https://교내서버:7443/office/`. 기존 승인 계정으로 로그인하여 받은함·보낸함·참여한 채팅·설문을 조회하고 설문 응답, 할 일과 제출 파일을 관리합니다. 메시지/채팅 발송과 설문 작성, 원격 지원은 Windows 앱에서 사용합니다. 교내망·HTTPS 제한을 그대로 적용하며 외부 인터넷에 공개한 페이지가 아닙니다.

앱 왼쪽 ‘할 일·제출’ 또는 웹의 ‘나의 할 일’에서 새로 받은 요청의 후보를 확인합니다. 학교 서버의 문장·날짜 규칙으로 제출·작성·회신 등의 요청을 찾고, 본인이 제목·기한을 수정하여 등록하거나 제외합니다. 외부 AI에 본문을 보내지 않습니다. 복잡한 요청은 누락되거나 잘못 해석될 수 있어 원문을 함께 표시하며 직접 추가도 제공합니다. 이전 기록은 한꺼번에 추출하지 않습니다. 상대 날짜는 발송일의 한국 날짜를 기준으로 합니다. 다른 사람과 관리자는 개인 할 일에 접근할 수 없습니다.

쪽지 작성 때 ‘파일 제출 요청’을 체크하고 마감 날짜를 선택합니다. 수신 대상은 발송 시 확정하며 마감일의 한국 시각 23:59:59까지 정상 제출로 처리합니다. 발송 후 마감 날짜 변경은 첫 버전에 포함하지 않습니다. 수신자는 쪽지 상세의 ‘파일 제출 · 현황 보기’ 또는 제출 메뉴에서 파일을 올리며, 개인 할 일의 등록·완료 여부와 실제 파일 제출 여부는 별개입니다.

요청한 교사는 제출·미제출·지각·면제를 확인하고 최신 제출 파일을 교사별로 묶어 ZIP 다운로드합니다. 제출자와 요청한 교사만 파일을 다운로드할 수 있습니다. 재제출과 마감 후 지각 제출을 허용하며 요청을 종료하면 새 제출·재제출을 중단합니다. 파일당 100MB, 제출본 합계 200MB, 최대 10개이며 기존 백신·파일 유형 검사를 적용합니다.

마감 이틀 전부터 한국 시각 매일 오전 9시 이후 미제출자에게 시스템 쪽지를 하루 한 번 저장합니다. 서버는 1분 간격으로 확인하므로 정각 전송은 보장하지 않습니다. 제출·면제·요청 종료 때 중단하며 마감 후에도 미제출 상태이면 계속합니다. 로그아웃한 사람은 다음 로그인 때 확인합니다. 같은 날 재시작해도 중복 생성하지 않고, 지난날 알림을 몰아서 보내지 않습니다. 자동 알림의 버튼에서 원본 요청을 열 수 있습니다.

제출 파일은 **제출 확정 시각부터 30일 후 만료**합니다. 이전 제출본의 기한을 재제출로 늘리지 않습니다. 만료 후에도 제출 시각·완료 상태는 유지하며 ZIP에서 만료 파일을 제외하고 안내합니다. 장기간 요청에서는 일찍 제출한 파일이 마감 전에 만료될 수 있으므로 필요한 파일은 미리 내려받으세요. 첨부파일 백업은 현재 제공하지 않습니다.

## 학교 시간표

PC의 **시간표**에서 수업 담당자가 학기 기초표와 변경된 날짜의 엑셀을 미리보기 후 게시합니다. 해당 날짜·학급의 일자별 표를 우선하고, 나머지는 기초표를 따릅니다. 학생별 수강 명부 없이 교사는 본인 수업, 학생·보호자는 학급 시간표부터 확인할 수 있습니다. 앱·웹 조회, 담당자 권한과 담임 연결, 전달 대기·알림의 운영 절차는 [시간표 운영 안내](docs/timetable-operations.md)를 참고하세요.

2. `시작-로컬체험.cmd`를 실행합니다. 첫 실행에서 관리자 비밀번호를 직접 입력합니다. 12~128자를 사용하세요. 기본 비밀번호는 없습니다.
3. 서버 창을 켜 둔 상태로 `시작-교사용.cmd`를 실행합니다.
4. 서버 주소 `http://localhost:5080`, 아이디 `admin`, 앞서 입력한 비밀번호로 로그인합니다.
5. 브라우저에서 `http://localhost:5080`을 열고 관리자 계정으로 로그인해 교직원을 등록합니다. 관리자 화면은 교사용 앱과 별도로 로그인합니다.
6. 다른 교직원 계정으로 로그인하거나 자기 자신에게 메시지를 보내 기능을 확인합니다. 같은 Windows 사용자 프로필에서 여러 앱을 동시에 실행하면 임시 저장 설정을 공유합니다. 실제 운영은 교직원마다 별도 Windows 계정 또는 PC를 사용하세요.

로컬 체험은 이 PC에서만 사용할 수 있습니다. 개발 환경에서는 악성코드 검사가 생략됩니다. 교내 배포에는 아래 운영 설정을 사용해야 합니다. 실행 패키지는 .NET 런타임을 포함하며 인터넷이나 별도 .NET 설치 없이 실행됩니다. Windows x64용입니다.

## 학교 서버에 설치하기

정보담당자와 함께 서버 운영체제, 고정 IP 또는 내부 DNS, 교직원용 유선망·Wi-Fi 통신, 방화벽, 인증서를 확인하세요.

1. 배포 폴더를 서버의 고정 경로에 복사합니다. 서버 계정에는 데이터 폴더 쓰기 권한을 부여하고 다른 일반 사용자의 접근을 제한합니다.
2. 서버 이름과 일치하는 HTTPS 인증서를 Windows `로컬 컴퓨터 / 개인` 인증서 저장소에 설치합니다. 개인키가 있어야 합니다. 실행 계정에는 개인키 읽기 권한이 필요합니다. 교직원 PC에서 신뢰하는 인증서를 사용하세요. 인증서 검증을 끄는 기능은 없습니다.
3. 로컬 체험으로 관리자 계정을 초기화한 뒤 서버를 종료합니다.
4. 아래 명령에서 인증서 지문과 실제 교직원망 대역을 입력합니다. 예시 IP는 학교의 실제 주소로 바꾸세요.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Server.ps1 `
  -CertificateThumbprint '서버인증서지문' `
  -AllowedNetworks '192.168.10.0/24,192.168.20.0/24' `
  -DataDirectory 'D:\SchoolMessenger\data' `
  -BackupDirectory 'E:\SchoolMessengerBackups'
```

초기화와 운영에는 동일한 데이터 경로를 사용하세요. 새로운 경로를 지정하면 다른 서버 데이터가 생성되고 최초 관리자 비밀번호를 다시 입력해야 합니다.

서버는 HTTPS 7443 포트로 실행됩니다. Windows 방화벽에서도 이 포트를 실제 교직원망에만 허용하세요. 인터넷 공유기의 포트 포워딩을 설정하지 마세요. 프로그램 자체도 설정된 망 대역과 로그인 권한을 검사하며 다른 PC에서의 HTTP 접속을 거부합니다.

운영 모드에서는 Microsoft Defender의 `MpCmdRun.exe`로 첨부파일을 검사합니다. 운영 계정에 검사기를 실행할 권한이 필요합니다. 검사기 실행 실패, 60초 초과, 위험 파일 탐지 시 업로드를 거부합니다. 설치 경로가 다르면 `School__ScannerPath` 환경변수로 지정하세요. 학교의 다른 백신을 사용하는 경우에는 해당 검사기 연동이 필요합니다. 검사 성공을 위조하거나 파일 형식 검사만으로 악성코드 검사를 대체하지 않습니다. [Microsoft Defender 실행 조건과 옵션](https://learn.microsoft.com/en-us/defender-endpoint/command-line-arguments-microsoft-defender-antivirus)

교사용 PC에는 `client` 폴더를 복사하고 `SchoolMessenger.exe`를 실행합니다. 로그인 화면에 `https://학교서버이름:7443`을 입력합니다. 별도 설치 프로그램이나 자동 업데이트는 아직 없으므로 버전 교체 시 앱을 종료하고 새 폴더로 교체하세요.

## PC 직접 원격 지원 방화벽

원격 지원에는 교직원 PC끼리 TCP 49152~65535 범위의 임시 포트로 접속할 수 있어야 합니다. 정보담당자가 아래 스크립트를 검토한 뒤 원격 지원을 받을 각 PC에서 관리자 PowerShell로 실행합니다. 실제 `SchoolMessenger.exe` 경로와 교직원망 CIDR을 지정하세요. 여러 대역은 쉼표로 나열합니다.

```powershell
.\scripts\Configure-RemoteFirewall.ps1 -ClientPath 'C:\SchoolMessenger\client\SchoolMessenger.exe' -RemoteAddresses '192.168.10.0/24','192.168.20.0/24' -WhatIf
.\scripts\Configure-RemoteFirewall.ps1 -ClientPath 'C:\SchoolMessenger\client\SchoolMessenger.exe' -RemoteAddresses '192.168.10.0/24','192.168.20.0/24'
```

첫 명령은 적용 내용을 확인하고, 두 번째 명령은 방화벽 규칙을 적용합니다. 스크립트는 해당 프로그램·포트·교직원망만 허용하며 도메인·개인 네트워크 프로필에 적용합니다. 대역을 생략하면 같은 서브넷(`LocalSubnet`)만 허용합니다. 공용 프로필로 설정된 학교 PC는 정보담당자가 학교 네트워크 정책을 확인하세요. 앱 경로가 바뀌면 같은 명령으로 규칙을 갱신합니다. 제거는 `Configure-RemoteFirewall.ps1 -Remove`입니다. 배포나 앱 실행만으로 방화벽을 변경하지 않습니다.

VLAN 사이의 경로, 교내 Wi-Fi 단말 격리, 별도 보안 제품도 PC 간 통신을 허용해야 합니다. 인터넷 포트 포워딩은 필요하지 않습니다. 학교 서버에 직접 접속하는 구성이며 역방향 프록시를 쓰면 서버가 관측한 주소가 프록시 주소가 되므로 현재 직접 연결 대상에 맞지 않습니다. 원격 지원이 차단되어도 쪽지·채팅·설문은 기존처럼 서버로 사용할 수 있습니다.

## 서버 자동 실행

첫 실행과 HTTPS 접속을 확인한 뒤 Windows 작업 스케줄러에 시작 작업을 등록합니다. 전용 운영 계정을 사용하고 ‘사용자 로그온 여부와 관계없이 실행’, ‘시작 시’, ‘실패하면 1분 후 다시 시작’을 선택합니다.

- 프로그램: 배포 폴더의 `server\SchoolMessenger.Server.exe`
- 시작 위치: 같은 `server` 폴더
- 인수 예시:

```text
--urls https://0.0.0.0:7443 --School:DataDirectory D:\SchoolMessenger\data --School:BackupDirectory E:\SchoolMessengerBackups --School:CertificateThumbprint 서버인증서지문 --School:AllowedNetworks 192.168.10.0/24
```

경로에 공백이 있으면 값을 큰따옴표로 감싸세요. 최초 비밀번호는 초기화 후 자동 실행 인수에 넣지 않습니다. 운영 계정으로 인증서 개인키, Defender, 데이터 폴더, 별도 백업 장치 접근을 확인하세요. `ASPNETCORE_ENVIRONMENT=Development`는 운영 작업에 설정하지 마세요.

교사용 PC의 시작 프로그램 폴더에는 앱 바로가기를 넣을 수 있습니다. 창 닫기는 알림 영역으로 숨기며 메시지 수신을 계속합니다. 완전히 종료하려면 앱 메뉴의 ‘프로그램 종료’를 선택하세요.

## 데이터와 보관 규칙

- 메시지를 서버 DB에 저장한 뒤 전송 완료를 표시합니다. 상대방이 오프라인이면 다음 로그인 때 조회합니다. SignalR 실시간 알림과 30초 주기 조회를 함께 사용합니다.
- 같은 요청 번호와 내용으로 재전송하면 한 번만 저장됩니다. 임시 저장된 전송 결과 미확인 메시지는 수정하지 않고 동일 요청으로 재시도합니다.
- 한 달은 전송 완료 시각부터 **30일**입니다. 생산 환경에서는 이 기간을 테스트 설정으로 줄이거나 늘릴 수 없습니다.
- 만료 즉시 신규 다운로드를 차단하고, 정상 운영 중 매시간 물리 파일을 삭제합니다. 서버 시작 시에도 먼저 정리합니다. 이미 시작한 다운로드와 교사 PC에 저장한 파일은 회수하지 않습니다.
- 전송되지 않은 서버 임시 첨부파일은 24시간 후 정리합니다. 서버에는 파일당 100MB, 메시지당 합계 200MB, 최대 10개, 계정별 미전송 첨부 합계 500MB 제한을 둡니다.
- 메시지 본문과 파일명·만료 기록은 자동 삭제하지 않습니다. 학교의 본문 보관 기간을 확정한 뒤 별도 삭제 정책을 추가해야 합니다.
- DB는 `school.db`, 첨부파일은 `files`에 저장됩니다. DB에는 파일 내용이 들어가지 않습니다.
- DB를 시작 시와 매일 백업하고 최근 14일분을 유지합니다. 기본 백업은 같은 데이터 폴더의 `backups`이며 **디스크 장애 대비용이 아닙니다**. 운영에서는 별도 장치에 `School__BackupDirectory`를 지정하세요.
- **현재 버전은 첨부파일을 백업하지 않습니다.** 파일 디스크 장애 시 첨부파일은 복구할 수 없습니다. 첨부 복제·백업을 추가하려면 원본과 동일한 만료일에 모든 서버 복제본을 삭제하는 정책이 필요합니다.

## DB 복원

1. 서버와 자동 실행 작업을 종료하고 실행 중인 서버 프로세스가 없는지 확인합니다.
2. 현재 데이터 폴더를 별도 위치에 보존합니다.
3. 복원할 백업 DB를 데이터 폴더의 `school.db`로 복사합니다. 기존 `school.db-wal`, `school.db-shm`은 서버가 정지한 상태에서 따로 보관한 뒤 원래 위치에서 제거합니다. 오래된 WAL을 새 DB에 섞지 마세요.
4. 현재의 `files` 폴더를 유지합니다. 백업 이후 메시지는 복원 시 사라질 수 있고, 이미 만료·삭제된 첨부파일은 되살아나지 않습니다. 앱은 없는 파일을 다운로드할 수 없다고 표시합니다.
5. 서버를 다시 시작하고 로그인, 메시지 조회, 만료 차단을 확인합니다.

.NET SDK 10.0.401, Node.js 24 이상을 사용합니다. SDK는 프로젝트의 `.tools/dotnet` 또는 PATH에서 찾습니다. SDK와 라이브러리 버전은 `global.json`과 NuGet 잠금 파일로 기록합니다.

## 업데이트 배포

현재 버전은 **1.0.0**입니다. 학교 담당자가 배포를 지시할 때까지 표시 버전과 안내 순서를 유지하며, 태그·릴리즈를 만들거나 공개하지 않습니다. 배포 승인 후 `v1.0.0` 태그를 GitHub에 올리면 검사 후 Windows x64 ZIP과 SHA-256 해시가 담긴 릴리즈 초안을 생성합니다. 자세한 버전 생성·기존 데이터 보존·수동 업데이트 절차는 [릴리즈 안내](docs/releases.md)를 참고하세요. 앱 내 자동 업데이트는 아직 없습니다.

2026-10-08 Windows x64 독립 실행 배포본을 `node tests/smoke.mjs --ui --package`로 검사하여 **55개 통과, 보류 0개**를 확인했습니다. 직접 TLS 화면·입력 패킷 전송, 인증서 지문·크기 검사, 실제 Windows 한글 키보드 입력, 제어 권한 해제 후 입력 차단과 연결 종료, 할 일 소유자·동시 수정, 제출 파일 권한·최신 ZIP·만료, 한국 날짜 기준 알림·중복 방지와 실제 Windows 업무 화면을 포함합니다. 이 PC의 실제 방화벽 규칙은 변경하지 않았습니다.

로그아웃 쿠키 재사용 차단, 계정 변경 후 기존 실시간 연결 종료, 브라우저 출처 검사와 비밀번호 해시 강화를 추가했습니다. **로그아웃하면 같은 계정의 다른 PC·웹 로그인도 만료됩니다.** 운영 모드에서 백신이 없거나 실패하면 업로드를 거부하는지 확인했습니다. 상세 범위와 한계는 [보안 검사 보고서](docs/security-audit-2026-10-08.md)를 참고하세요.

메시지 DB와 서버 첨부파일은 현재 애플리케이션 수준에서 암호화하지 않습니다. 운영 시 서버·백업 폴더 접근 권한과 디스크 암호화를 적용해야 합니다. 이번 검사만으로 모든 보안 위험이 없다고 보장할 수는 없습니다.

검증 범위는 로그인·계정 승인·자동 로그인·자동 실행 설정, CSRF, 교직원 권한, 파일 검사·만료, 중복·동시 전송, 알림·읽음, DB 백업·서버 재시작, 채팅 권한·기록·읽지 않은 수, 설문 응답·마감·집계, 원격 수락·직접 TLS 연결·권한 해제·종료, 실제 WPF 화면과 Windows 키보드 입력입니다. 교내 실제 100명 부하, 인증서·방화벽, 운영 백신, 알림·수업 중 사용성은 학교 시범 운영에서 확인해야 합니다.

## 현재 제외된 기능

교직원 웹·할 일·제출 기능의 [설계와 구현 범위](docs/web-tasks-design.md)를 참고하세요. 별도 학생·보호자 공지 서버는 배포 ZIP에 포함하며, 모바일 앱 소스와 Android 테스트 빌드 방법은 [앱·외부 서버 운영 안내](docs/mobile-operations.md)에 있습니다. 실제 외부 공개와 스토어 배포는 별도 준비가 필요합니다.

스마트폰 스토어 공개, SMS·외부 메일, 기존 쿨메신저 기록 가져오기, 자동 업데이트, 첨부파일 백업, 본문 보관 기간 자동 삭제는 포함하지 않습니다. Android 시운행 APK와 iPhone·iPad 앱 소스는 구현했으며, iOS의 Mac 빌드·시뮬레이터 검사와 실제 iPhone 서명 준비는 [iOS 운영 안내](docs/ios-operations.md)를 참고하세요. 일반 관리자 화면에는 개인 메시지·타인 대화 열람 기능이 없습니다. 서버 OS와 DB 파일에 직접 접근할 수 있는 운영자는 별도 권한 관리가 필요합니다.
