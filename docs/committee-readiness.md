# 앱 전용 교무실의 학교운영위원회 검토 준비안

2026-10-24 업데이트: 아래는 초기 검토 기록이다. 현재의 별도 교사용/학생학부모용 앱, 서버 EXE 설치와 보안 근거는 [최신 학운위·에듀집 검토 자료](committee-security-evidence-2026-10-24.md)를 먼저 확인한다. 아직 심의·등록 완료를 의미하지 않는다.

2026-10-09, 버전 1.0.0 개발 단계. 실제 심의 완료·에듀집 등록·도름스 마크 발급을 의미하지 않는다. 아래는 학교가 검토·확정할 초안과 프로그램 개선 제안이다.

## 사용 목적과 운영 범위

교직원은 Windows 메신저와 교사용 휴대폰 앱을 사용한다. 학생·보호자는 가족용 휴대폰 앱으로 허용된 가정통신문·공지·변경 시간표를 확인한다. 브라우저 업무 화면을 사용하는 운영은 목표에서 제외한다. 앱 통신을 위한 HTTPS API 서버는 유지한다.

2026-10-13부터 교사/가족 앱의 별도 설치 ID, 교직원 초기 활성화, 네이티브 PC 관리, 학사일정·특별실·분반 명부 기능을 추가했다. [교직원 운영 안내](teacher-office-operations.md)에 구현 범위와 남은 작업을 명시했다. 빌드·가상 데이터 검증은 실제 학교 서버 운영 승인이나 스토어 출시를 의미하지 않는다.

교육부는 교육자료로 선정하는 학습지원 소프트웨어에 대해 개인정보 필수 기준과 교육 효과·환경·접근성·지원 체계 등 선택 기준을 안내한다. 이 프로그램은 업무 메신저와 가족 공지 기능을 함께 포함하므로 **학습지원 소프트웨어 선정 기준의 적용 범위는 학교와 관할 교육청이 확인할 사항**이다. 업무 앱이라는 이유로 심의가 면제되거나, 도름스 점검만으로 기준을 충족한다고 단정하지 않는다. [교육부 기준 안내](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=294&boardSeq=105007&lev=0&m=020), [2026년 적용 대상·선정 기준 설명](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=340&boardSeq=105576&lev=0&m=0206&opType=N&page=8&s=moe).

## 현재 개인정보와 보관 현황

| --- | --- | --- |

| 쪽지·채팅·설문 응답·할 일·제출 현황 | 교내 업무 처리 | 첨부와 달리 본문·메타데이터의 전체 보유 종료 자동 처리 없음 |
| 학생 이름·아이디·학급·번호·승인 시각·비밀번호 해시 | 외부 서버 가입·학급 권한 | 자동 졸업/전학 삭제 없음. 학교가 소속·활성 상태 관리 |

| 첨부 내용·파일명·소유·만료 정보 | 각 서버 전달/제출 | 내용 30일 후 물리 삭제. 외부 미게시 내용 24시간. 메타데이터와 내려받은 사본은 별도 |
| 교사 수업·학급 시간표·변경 이력 | 교내 게시, 범위 제한 외부 조회 | 학기 종료 자동 삭제 없음. 실제 수강 명부는 아직 수집하지 않음 |
| 인증 세션·연결 키·암호화 키·백업 | 접속·서버 연결·복구 | 세션 만료/회수, 공지 DB 일일 백업 14일. OS 권한과 키 백업은 운영 책임 |

이 표는 공개 개인정보처리방침의 완성본이 아니다. 처리방침에는 학교가 정한 책임자·문의처·항목·목적·근거·기간·권리 행사·제공/위탁 여부를 반영한다. 개인정보 포털의 [처리방침 공개 항목과 권리 행사 안내 사례](https://m.privacy.go.kr/front/contents/cntntsView.do?contsNo=408)를 참고하되 다른 기관의 기간·담당자를 그대로 복사하지 않는다.

학교 승인과 학부모의 자녀 번호 입력은 개인정보 동의의 대체 절차가 아니다. 만 14세 미만을 대상으로 확대하면서 동의를 근거로 처리하는 경우에는 별도의 법정대리인 동의 확인 흐름도 검토해야 한다. 현재 대상이 고등학교라고 생년월일·주민번호 수집을 추가하지 않는다. [개인정보 포털 법정대리인 역할 안내](https://www.privacy.go.kr/front/contents/cntntsView.do?contsNo=75).

## 적용 전에 검토할 프로그램 개선안

보안 관련 근거와 변경은 [보안 점검 보고서](security-audit-2026-10-09.md)에 먼저 제시했다. 아래 제안은 아직 적용하지 않았으며 기존 데이터·호스팅은 유지한다.

1. **앱에서 학교 관리 완결:** PC 관리자 창과 교사용 앱에 계정 승인·학급·담임/담당교사·보호자 관계·번호 재발급·서버 상태 기능을 제공한다. 현재 API와 서버 권한 검사를 재사용한다. 기능이 검증된 뒤 브라우저 업무 화면을 종료한다. 정책 안내 페이지까지 무조건 차단하지 않는다.
2. **교사·가족 앱 분리:** 공통 코드에서 다른 패키지 ID·이름·시작 화면으로 빌드한다. 가족 앱에는 교무실 모드·관리 기능을 제공하지 않는다. 화면 숨김만으로 권한을 대신하지 않는다. 기존 시운행 앱의 세션은 다른 앱으로 자동 복사하지 않는다.
3. **가입 전 안내·설정의 개인정보 메뉴:** 학교가 확정한 처리방침을 가입 전과 로그인 후 모두 앱 안에서 읽는다. 서버에서 정책 버전과 적절한 고지/동의 확인을 기록하며 요청 변조도 거부한다. 필수·선택·철회 가능 여부는 학교의 처리 근거를 따른다.
4. **가족 연결 사실 확인:** 요청했던 8자리·즉시 정회원 전환은 유지한다. 학생과 담당자가 연결 사실을 확인하고 의심 관계를 학교에 신고할 수 있게 한다. 기존 보호자 관계까지 감지되었다고 소급 알림하지 않으며 번호 원문은 알림·로그에 넣지 않는다.
5. **권리 행사와 변경 이력:** 앱에서 개인정보 요청 접수·진행 상황을 제공하고 승인·관계 변경·번호 재발급 이력을 관리자만 확인하게 한다. 전체 개인정보 삭제는 학교가 정한 보존 범위와 함께 설계한다. 관리자 기록도 무기한 수집하지 않는다.

별도 완료 과제는 설치 마법사 EXE, 실기기 시험, 공개 도메인 점검, FCM/APNs 푸시, 급식 연동, 버그/개선 접수와 배포 서명이다. 푸시·신원확인 사업자·호스팅을 새로 사용하는 경우 개인정보 흐름과 비용을 다시 검토한다.

## 시범 운영 통과 기준 초안

- 학생 A/학부모 A/해당 담임은 허용 공지·첨부·시간표만 보고, 타 학급·타 가족은 차단된다.
- 자녀 연결·다자녀·번호 재발급·관계 해제·전학·졸업 처리 후 접근 권한이 예상대로 바뀐다.
- 두 PC 원격 지원은 상대 수락·제어 허용·종료를 지키며 외부 공지 서버가 화면을 중계하지 않는다.
- 서버 재부팅·연결 끊김·인증서 오류·백신 실패·첨부 만료·중복 전송이 누출이나 잘못된 완료 표시를 만들지 않는다.
- 설치·로그인·개인정보 안내·요청 처리·삭제·복구는 담당자가 실제로 수행하고 증빙을 남긴다.
- 앱을 사용하지 못하는 가족도 학교 공지를 받을 대체 경로가 있다. 자동 푸시 미구현 상태에서는 도착 알림을 보장하지 않는다.

학교가 확정할 결정: 도입 목적/대상, 책임자·문의처, 실제 서버/운영 계약, 처리 근거·방침, 항목별 보유 기간, 보호자 확인·분실 대응, 대체 수단, 시범 기간·배포 승인. 개발 단계 검증과 위원회 심의 결과는 각각 기록한다.
