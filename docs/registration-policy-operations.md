# 앱 회원가입 약관·개인정보 확인

2026-10-20 갱신 기준. Windows PC 메신저와 교사용·학생/학부모용 Android/iOS 네이티브 앱에서 약관을 확인한다. 웹앱·WebView·브라우저 약관 팝업을 새로 만들지 않았다. 프로그램 버전은 배포 전 1.0.0이다.

## 학교 홈페이지 문서를 반영한 검토안

학교가 제공한 `회원약관.txt`(2013년 시행 문구)와 `개인정보 수집 및 이용 동의.txt`를 앱에 맞게 수정했다. [서비스 이용약관 검토안](policies/서비스%20이용약관%20검토안.txt)과 [개인정보 수집 및 이용 동의 검토안](policies/개인정보%20수집%20및%20이용%20동의%20검토안.txt)은 `config/registration-policy.draft.json`의 두 전문과 일치한다. 문서 버전은 `2026-10-20-draft.6`이며 프로그램 버전과 구별한다. 운영 주체는 여양고등학교, 문의처는 여양고등학교 교무실 061-689-5870이다. 학생은 재학 기간 보유·졸업 시 자동 탈퇴와 파기를 적용하고, 학부모는 마지막 재학 자녀 졸업 시 함께 탈퇴·파기한다. [졸업 예약과 파기 안내](graduation-retention.md)를 따른다. 새 전문은 두 서버의 내장 약관에 포함되고 PC와 두 학교 앱의 기존 전문 보기·체크 화면에서 표시된다.

목적·항목·보유기간·거부 영향을 나누고 동의와 다른 법적 근거의 안내를 구분한다. 학생·연결 학부모의 기간과 교무실 문의처는 반영했다. 교직원·미연결 임시계정·전학·직접 탈퇴 기준, 처리 근거·위탁·대체 공지 수단·만 14세 미만 법정대리인 확인 절차 등 남은 정책은 학교가 확정해야 한다. 기본 약관의 `approvedForProduction: false`는 유지하며 실제 운영 가입은 차단된다.

법령 검토 기준(2026-10-13 확인): [개인정보 보호법 제15조·제16조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1006183947), [제22조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335519), [제22조의2](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398523), [약관법 제6조·제7조·제12조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1025032407). 학교의 실제 처리 근거와 약관법 적용 판단에 대한 확정 법률 의견을 대신하지 않는다.

도름스 검사 명령은 운영자용 보안 점검이다. 회원에게 검사 도구 이용·코드 검사·마크 신청을 강제로 동의시키는 조항으로 넣지 않았다. 이번 점검은 [2026-10-13 보안 보고서](security-audit-2026-10-13.md)에 구분하여 기록한다.

## 가입 화면과 기록

학생·학부모의 개별 가입, 학교 초대 가입, PC 교직원 계정 신청에 적용한다. 처음에는 체크하지 않은 상태이며 각 문서의 `전문 보기`를 열면 해당 체크 항목을 사용할 수 있다. 전문에는 문서 버전·운영 주체·문의처·본문과 초안 여부를 표시한다. 전문을 여는 것만으로 동의하지 않는다.

필수 항목을 체크해야 가입할 수 있다. 선택 항목은 체크하지 않아도 가입할 수 있으며 현재 초안에는 선택 수집 항목을 넣지 않았다. 실제 선택 동의를 추가하면 목적·항목·기간을 문서에 적고 `required: false`로 설정한다. 약관 체크와 운영체제의 알림·파일 권한 요청은 별개의 절차다.

서버는 문서의 내용에서 계산한 `revision`과 체크한 문서 ID 목록을 검사한다. 누락, 필수 미체크, 중복 또는 임의 ID, 예전 버전은 거부한다. 가입 정보와 확인 기록은 같은 DB 트랜잭션으로 저장하므로 확인 기록 저장 실패 시 계정 생성·초대 사용도 취소된다. 기록에는 서버 시각을 사용하며 클라이언트가 지정한 시각이나 다른 사용자 ID를 신뢰하지 않는다.

각 서버의 `RegistrationPolicies`에는 당시 전문·문서 버전·확인/동의 구분·운영 안내의 사본을, `RegistrationAgreements`에는 가입 대상 ID·revision·체크한 항목·서버 시각을 저장한다. 학생은 승인 전 신청 계정 ID, 교직원은 가입 신청 ID에 기록하고 승인 후 같은 대상 ID를 사용한다. 반려 후 다시 신청하는 교직원은 새 신청 ID로 새 확인 기록을 남긴다. 기록을 외부 공지 연결에 복제하지 않는다.

앱의 약관·개인정보 안내 메뉴와 PC 설정에서도 현재 문서를 다시 열람할 수 있다. 가입 전 이미 만들어진 계정이나 관리자가 직접 만든 계정에 동의 기록을 임의로 만들어 넣지 않는다. 졸업 자동 파기는 별도 예약·영속 작업으로 구현했다. 기존 회원 문서 변경 시 재동의·직접 동의 철회/탈퇴 및 모든 자유 입력 자료의 개인정보 삭제 흐름은 별도 과제다.

## 학교 검토용 초안

`config/registration-policy.draft.json`은 **학교 검토용 자료**다. 실제 개인정보 처리방침이나 최종 동의서가 아니다. 각 서버 실행 파일에 같은 초안을 내장해 개발 환경에서 앱 가입 시운행에 사용할 수 있다. 학교가 정하지 않은 항목별 보유 기간·처리 근거·담당자·연락처를 확정한 것처럼 적지 않았다.

서버의 `Production` 환경에서는 기본 초안으로 **신규 가입을 차단**한다. 기존 계정 로그인과 관리 기능은 유지한다. 초안 사용은 Development의 가상 계정 시험에 한정한다. 약관이 확정되지 않았다고 교직원 서버를 인터넷에 공개하거나 운영 서버를 Development로 바꾸지 않는다.

운영 준비 순서:

1. 학교 개인정보 담당자와 이용약관, 처리 주체·문의처, 역할별 항목·목적·법적 처리 근거, 보유 기간·거부 영향·권리 행사·제공/위탁을 확정한다.
2. 초안을 복사해 각 서버용 `registration-policy.local.json`을 만들고 실제 내용으로 교체한다. 이 파일은 Git에서 제외한다. 교직원 서버와 공지 서버의 처리 항목이 다르므로 동일 문서가 적합한지 각각 확인한다.
3. 문서마다 새 `version`을 지정한다. `terms`, `privacy` ID는 필수 항목으로 유지한다. 추가 문서는 전체 최대 10개이며 파일은 128KB, 문서 본문은 각각 40,000자 이하이다.
4. 개인정보를 동의로 처리하는 문서는 `action: consent`, 다른 처리 근거에 대한 안내를 확인하는 문서는 `action: acknowledgment`로 구분한다. `required`는 가입 시 체크 필요 여부이며 법적 동의 근거를 대신하지 않는다. 필수/선택 판단은 학교가 확정한다.
5. 학교가 내용을 확정한 파일에만 `approvedForProduction: true`를 설정한다. 이 값은 운영자의 설정 표시이며 학교 심의나 법률 검증을 자동 수행하지 않는다.
6. 각 서버의 보호된 실행 환경에 `Registration__PolicyFile`을 해당 파일의 절대 경로로 지정하고 재시작한다. 작업 스케줄러 실행 환경에도 같은 경로를 제공한다.

```powershell
# 학교가 검토·확정한 파일을 운영 계정에서 지정한 뒤 서버 시작 스크립트를 실행한다.
$env:Registration__PolicyFile = 'D:\YyMessengerConfig\registration-policy.local.json'
```

문서 내용·버전·확인 방식이 달라지면 revision도 달라진다. 서버 재시작 전에 열어 둔 옛 가입 화면은 거부되며 앱에서 화면을 다시 열어 새 문서를 확인해야 한다. 예전에 저장한 전문과 확인 기록은 덮어쓰지 않는다.

초기 기본 관리자 생성은 운영 서버 초기화 절차이고 공개 회원가입이 아니다. 약관 준비를 위해 기존 관리자 로그인까지 차단하지 않는다. 학생과 마지막 자녀 졸업 시 탈퇴하는 학부모의 확인 기록은 졸업 파기에 포함한다. 교직원 등 다른 역할의 확인 기록 기간은 학교가 확정해야 한다.

## 앱 전용 전환 범위

외부 서버의 브라우저 가입 메뉴는 숨겼다. 약관 확인과 신규 가입은 설치 앱에서 진행한다. 서버 API 주소가 필요하다는 것은 웹앱이라는 뜻이 아니다. 일부 기존 웹 관리자·정적 파일은 남아 있으므로 이번 약관 변경을 모든 웹 제공 종료로 보고하지 않는다. 제품 구분은 PC 메신저, 교사용 학교 앱, 학생·학부모용 학교 앱이다.

개인정보 안내는 [개인정보 포털의 처리방침 자료](https://www.privacy.go.kr/front/bbs/bbsList.do?bbsNo=BBSMSTR_000000000049)와 [동의 없이 처리하는 항목의 고지 구분에 관한 설명](https://talk.privacy.go.kr/)을 참고했다. 학교의 실제 문서·처리 근거에 대한 승인을 대신하지 않는다.

## 검증

`node tests/registration-policy.mjs`로 두 서버의 누락/위조/예전 버전/CSRF 차단, 선택 항목, 문서 원문·서버 시각 보관, 저장 실패 롤백, 초대 소비, 재시작 후 이력, Production 초안 차단과 승인 파일 활성화를 확인한다. 가상 계정만 사용한다. 기존 기능 검증용 fixture는 최신 필수 문서 확인 정보를 명시적으로 보내도록 갱신했으며 부정 확인 시험에는 그 helper를 사용하지 않는다.

iOS 시뮬레이터 시험은 필수 미체크 거부, 앱 내부 전문과 버전 표시, 문서에서 돌아온 후 체크·가입까지 포함한다. Android/iOS 실제 기기와 스토어 심사 확인은 별도다.

선택과목 신청의 계정·학급·과목 선택·처리 시각과 확정 분반을 검토안에 추가했다. 학생 본인 신청과 지정 담당자 조회, 정원 없는 접수, 재학 중 보유 및 졸업 시 관리 백업을 포함한 파기를 안내한다. 외부로 내보낸 CSV는 학교가 별도로 관리해야 한다. 학교 승인 전 운영 가입 차단은 유지한다.

## 학교별 운영 후속 보완 (2026-10-24)

관리자 화면에서 학교별 약관 초안을 만들고, 운영 JSON의 registrationPolicyFile에 파일의 절대 경로를 지정할 수 있습니다. 작업 스케줄러가 이 값을 자식 서버의 Registration__PolicyFile로 전달합니다. 개발자와 각 학교의 개인정보 보호책임자는 구별하며, 일반 사용자가 학교별 운영 정보를 변경하지 않습니다. 상세한 절차는 [학교별 설정·에듀집 등록](edzip-registration-guide.md)을 참고하세요. 앱/PC의 권리 요청 기능은 [접수·회신 안내](privacy-rights-operations.md)를 따릅니다.
