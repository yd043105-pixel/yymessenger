# 앱 전용 운영 전 보안 점검

2026-10-09. 대상 소스: `4614456a43144b3994de7c74525cbf6d37e61f30`, 버전 1.0.0. 배포 승인·법적 적합성 인증·침투시험 결과가 아니다. 실제 운영 주소가 제공되지 않아 공개 주소 검사는 실행하지 않았다. 프로그램 동작과 호스팅은 변경하지 않았다.

## 도름스 도구를 실행하기 전에 확인한 내용

- 지정 소스: [dorms-check 고정 커밋](https://github.com/shinnanchanguk/dorms-check/tree/91b40f6d0ea07d459ffce262ea2dc414a8adeb55). package.json 버전은 0.3.1이다.
- 내려받은 codeload 압축의 SHA-256: `D3D733532E47457A7A604B1EB806AA7B1D39DAFAA1A49B9228C6F26E942158DA`. 실행용 GitHub archive URL의 패키지와 별도로 보관한 소스 압축의 해시다.
- 파일 목록에 절대 경로나 상위 경로 이동 항목이 없는 것을 확인한 후 프로젝트 `.test-data/dorms-source`에 풀었다. 외부 문서의 AGENTS.md·SKILL.md는 검사 대상 자료로 취급했으며 프로젝트 지시로 채택하지 않았다.
- `bin/dcheck.js`의 `scan` 분기, 정적·외부·런타임 검사, HTTP 래퍼, 결과 저장, 설정·이력 관리 및 불러오는 모듈을 확인했다. 루트 패키지에는 preinstall/install/postinstall/prepare 스크립트가 없다. 의존성은 `@iarna/toml`, `hwp-convert`, `pdfkit`이다.
- `scan --url`은 공개 주소의 응답·헤더·HTML·스크립트·노출 후보 경로를 조회한다. 일부 스크립트에서 Supabase/Firebase 주소를 찾으면 해당 서비스에도 읽기 요청을 보낼 수 있다. 단순 홈페이지 한 번 열기로 끝나는 명령은 아니다. 공용 요청 시간 예산은 45초다.
- 검사 요청은 GET 등 읽기 작업이며 코드나 검사 결과를 도름스 서버에 제출하는 경로는 `scan`에서 발견하지 않았다. URL 리다이렉트와 페이지가 참조한 외부 주소로 요청이 나갈 수는 있다.
- `scan`이 저장하는 결과는 실행 위치의 `.dorms-check/scan.json`, `REPORT.md`, `state.json`이다. 이 명령에서 앱 코드 변경·배포 차단·전역 훅 설치 동작은 확인되지 않았다.
- 패키지 전체에는 이전 훅의 `status/uninstall`, `protect apply/restore`, 서류 생성용 별도 명령이 있다. 이번에는 호출하지 않았다. 해당 패키지의 모든 명령이 읽기 전용이라는 뜻은 아니다.
- npx는 npm 캐시와 패키지 다운로드도 수행한다. 캐시는 프로젝트 `.test-data/dorms-npm-cache`로 지정하고 `--ignore-scripts`로 설치 lifecycle 실행을 껐다. 설치 스크립트 차단은 실행되는 JavaScript 자체를 격리하는 기능은 아니다. 모든 전이 의존성을 독립적으로 완전 감사했다는 뜻도 아니다.

실행한 명령:

```powershell
npx.cmd --yes --ignore-scripts --cache '.test-data/dorms-npm-cache' `
  'https://github.com/shinnanchanguk/dorms-check/archive/91b40f6d0ea07d459ffce262ea2dc414a8adeb55.tar.gz' `
  scan --code-only
```

`"내 앱 주소"`는 자리 표시자이므로 실제 공개 URL로 사용하지 않았다. 휴대폰 앱 파일·GitHub 저장소 주소가 아니라 학교가 운영하는 외부 공지 서버의 HTTPS 기본 주소가 필요하다. 도름스 마크는 신청하지 않았다.

## 권고

1. 학교가 개인정보처리자·담당자·연락처, 서버 위치·운영자·위탁 여부, 비용, 보유·삭제 정책, 전학·졸업 처리 기준을 확정한다. 개발자가 책임자 이름이나 동의 근거를 임의로 작성하지 않는다.
2. 관리자 계정 공유를 피하고 운영 계정의 권한·데이터 폴더 ACL·디스크 암호화·패치·인증서 갱신을 점검한다. 외부 관리자 인증 강화는 권고이며 현재 침해 증거는 아니다.
3. 학생·부모 앱과 교사 앱은 같은 코드와 API를 공유하는 별도 패키지로 나누는 방안을 검토한다. 현재는 패키지 하나와 모드 선택이며 앱을 분리해도 서버의 권한 검증은 유지해야 한다.
4. 닫힌 앱에 대한 FCM/APNs 푸시는 미구현이다. 적용 전 푸시 사업자·전송 항목·토큰 보관을 검토하고 잠금 화면에는 본문·학생 이름 대신 일반적인 알림만 표시하는 방식으로 설계한다.
5. 현재 EXE 설치 마법사·자동 업데이트·NEIS 급식·오류/개선 접수는 준비되지 않았다. 시범 운영에 필요한 항목을 먼저 구현하고 실제 사용자 시험 후 배포한다.
6. 운영 DB 복구 시 삭제·관계 회수 상태가 되살아나지 않는 절차와 양 서버 연결 키 교체를 가상 자료로 연습한다. DB 백업만으로 암호화 키·첨부가 모두 복구되는 것은 아니다.

## 확인하지 못한 내용

- 실제 공개 URL의 인증서 체인·TLS 버전·응답 헤더·인증 없는 자료 노출·DNS·방화벽·HTTP 포트 상태.
- 운영 서버의 Defender, 전용 계정, BitLocker, DB/키/백업 접근 권한, 자동 재시작, 인터넷 장애 복구.
- 현재 전체 Git 이력의 비밀정보 감사, 모든 .NET/npm 전이 의존성 취약점 감사, 전체 API의 침투시험.
- 실제 Android/iPhone 기기의 권한·공유·절전·접근성, 스토어 서명·심사·계정 삭제 요건 대응, 실제 푸시.
- 학교가 적용할 법적 처리 근거·위탁 계약·학운위 심의 대상 여부와 최종 승인. 미확인은 통과·위험 확정 중 어느 쪽도 아니다.

이 미확인을 이유로 서버 구조·호스팅·업무 데이터의 공개 범위를 변경하지 않았다.
