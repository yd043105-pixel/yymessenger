# 시험 배포 전 최종 연결 점검

2026-10-24 · 버전 1.0.0 유지 · 학교 운영 서버 변경 및 공개 릴리즈 없음

## 확인하고 수정한 사항

- **배포 파일과 안내의 불일치:** 최신 전체 ZIP과 달리 서버 전용 ZIP·고정 경로 설치 EXE·APK가 예전 빌드로 남을 수 있었다. 서버 전용 ZIP을 빌드 과정과 향후 릴리즈 첨부 목록에 포함하고, 기기별 실제 전달 사본·해시 목록을 만드는 `Prepare-TestDelivery.ps1`을 추가했다. 서버 ZIP은 `server/`, `announcement-server/`, `scripts/`, `config/`, `docs/`가 바로 나타나는 구조다. 릴리즈의 기존 승인·초안 정책은 유지한다.
- **사용하지 않는 배포 자산의 재포함:** 기존 publish 폴더를 재사용하면 소스에서 삭제한 파일이 출력에 남을 수 있었다. 생성 폴더·링크·비밀 파일 여부를 확인한 후 관리 대상 출력만 비우고 다시 생성한다. 운영 DB·첨부·키가 있는 경로는 정리를 중단한다.
- **휴대폰 초기 로그인 정보:** 로그인 직후 사용자 상태를 확인하기 전에 초기 세션 쿠키가 저장될 여지가 있었다. 정상 로그인 사용자임을 확인하고, 활성화·비밀번호 변경이 완료됐으며, 서버가 실제 만료 시각을 지정한 인증 쿠키만 SecureStorage에 저장한다. 초기 로그인 정보와 만료 없는 쿠키는 저장하지 않는다.
- **초기 비밀번호 계정의 백그라운드 처리:** HTTP 접근 제한과 별도로 예약 메시지 작업·교사 연결 검증도 개인 비밀번호 설정 여부를 검사하도록 공통 계정 판정을 일치시켰다. 과거 공통 비밀번호 프로필도 준비 미완료로 판정한다. 예약 발송 시점에 초기 상태인 계정은 전송하지 않는 회귀 검사를 추가했다.
- **오래된 실행 안내:** 서버 시작 스크립트에서 브라우저를 열라는 문구를 관리자 메신저 로그인 안내로 바꿨다. 첫 서버 시작→관리자 로그인→자동검색·자동 구동 설정 순서로 문서를 정리했다.
- **테스트 DB의 동시 접근:** 졸업 파기 검증 도구가 살아 있는 정리 작업과 동시에 DB를 수정할 때 즉시 잠금 오류를 냈다. 테스트 연결에도 서버와 같은 30초 대기 정책을 적용했다. 서버의 보호 트리거를 완화하지 않았으며 졸업·마지막 자녀 보호자·관리 백업 파기를 재검사한다.
- **설치 도구 캐시:** 공식 Inno Setup의 버전 메타데이터가 `0.0.0.0`인 경우 재빌드가 중단됐다. 식별되지 않는 캐시는 고정 SHA256·게시자 서명 검증을 거친 공식 설치본으로 다시 준비한다. 검증을 생략하지 않는다.

## 정리 범위

최신 산출물로 대체됐고 현재 실행에 쓰이지 않는 **생성된 이전 배포 ZIP·중복 publish 파일·이전 수강신청 시험 APK** 12개, 합계 685,257,648바이트(약 653.5MiB)를 확인했다. 자동 승인 검토가 일괄 영구 삭제를 차단했고 구체적인 이유는 제공하지 않았다. 삭제를 우회하지 않고 `artifacts/retired-generated/2026-10-24`로 이동해 전달·설치 경로에서 격리했다. **이 12개는 삭제하지 않았고 공간 확보량은 0바이트다.** 원래 경로·보관 경로·파일별 해시·용량은 `artifacts/final-cleanup-2026-10-24.json`에 기록했다.

`installer-client`는 기본 설치 빌드에서 다시 생성 가능한 중간 출력이며 최신 설치 제작에는 검증된 전체 패키지의 client 폴더를 사용한다. 이전 통합 APK는 개발용 `tests/mobile-ui.mjs` 참조가 있어 유지하되 전달 폴더에서는 제외한다.

업무 DB·첨부·실제 사용자 계정, 약관 동의 기록, 졸업 파기 기록, 키·백업, 개발 도구, 디자인 참고 자료, 무관한 `sites` 프로젝트는 삭제 대상이 아니다. 문자열 검색에 잡히지 않아도 XAML·직렬화·리플렉션·정적 리소스로 연결되는 소스는 무조건 미사용으로 판단하지 않는다. 실제 운영 DB는 이번 작업에 연결하지 않았다.

## 검증

가상 사용자·격리된 데이터·루프백 서버를 사용해 인증과 권한, 쪽지·채팅·설문·첨부·제출·예약·할 일, 상담·특별실·학사 시각, 수강신청, 공지 전달, 약관·가입·자녀 연결·졸업 파기, 백업·복원·동시 저장, 운영 작업과 자동검색을 점검한다. 세부 결과는 `artifacts/*checks.json`, `artifacts/*test-results.json`, `artifacts/test-results.json` 및 최종 `artifacts/final-review-results-2026-10-24.json`에 남긴다. 실행되지 않은 검사는 통과로 기록하지 않는다.

APK 서명 도구는 두 시험 APK 각각에서 JAR 방식의 `META-INF` 메타데이터 90개에 대한 서명 보호 경고도 출력했다. v2/v3 검증 결과는 true이며 도구 종료값은 0이다. 이 경고를 숨기거나 서명 실패가 없다는 이유로 모든 파일이 모든 Android 버전에서 동일하게 검증된다고 해석하지 않는다. 원문과 서명 방식별 결과는 `artifacts/final-android-builds-2026-10-24.json`에 남겼다. 정식 Android 배포 전 최소 OS 범위·스토어 서명·실기기 검증을 별도로 확인한다.

## 남은 확인과 권고

- 실제 학교 PC의 알약·V3·Defender·Genian GPI·Zombie ZERO·FTP Utility 충돌 여부, 방화벽/VLAN·인증서·UDP 검색·실제 재부팅·SMTP 수신은 학교 환경 시험이 필요하다. 보안 제품을 끄거나 규칙을 일괄 완화하지 않았다.
- 서버 RAM 8GB 중 기존 사용량이 높은 자료가 있으므로 실제 서비스별 메모리·동시 접속·파일 전송을 측정해야 한다. low-memory 설정은 자원 사용 상한·처리량 조절을 돕지만 용량 보장은 아니다.
- 외부 서비스의 역할 격리·학교 승인·공개 HTTPS·Cloudflare·별도 암호화 백업·UPS·약관 확정은 배포 준비 조건이다. 미확인이라는 이유로 호스팅이나 학교 망 구조를 임의 변경하지 않았다.
- Android APK는 Debug 시험용이다. 실제 휴대폰의 실행·절전·네트워크 전환은 별도 확인한다. iOS는 최신 소스를 정리하며, 이번 Windows 작업에서 새 iOS 빌드·실기기 검증·서명 IPA 제작을 완료했다고 보지 않는다.
- 종료된 앱의 OS 푸시·NEIS 급식·대량 학생 등록 등의 미완료 기능을 이번 안정화 작업이 완성했다고 보지 않는다.
- 학교 배포자 코드서명, 스토어 등록과 정식 릴리즈는 별도 절차다. 자동 시험 통과가 취약점 부재나 운영 보안을 보증하지 않는다.

실제 작업 순서와 파일 위치는 [시험 설치 안내](final-test-runbook.md)를 따른다.
