# 교직원 계정·앱·백엔드 구성 재점검

작성일: 2026-10-13. 상태: 최초 점검 때 작성한 설계 근거. 이후 계정 활성화·일정·예약·분반·설치 앱 분리를 구현했다. 아래 표는 변경 전 상태이며 최신 동작과 남은 범위는 [운영 안내](teacher-office-operations.md)를 따른다. 배포 전 버전은 1.0.0을 유지한다.

## 사용자 요청과 현재 구현

교사의 좌석에는 고정 IP가 있고, 교사는 이름/IP를 이용하여 로그인하며 최초에는 공통 임시 비밀번호를 사용한다. 학생·학부모 가입은 이전에 합의한 절차를 유지한다. 교사용 앱에서 메시지, 개인 시간표, 분반 공지, 학사력·행사·일정, 특별실 예약을 이용한다. Windows·Android·iOS 설치 앱을 기준으로 설계한다.

| 기능 | 현재 코드 기준 | 추가할 내용 |
| --- | --- | --- |
| 교직원 로그인 | 영문·숫자 중심 아이디, 개인 비밀번호, 신청 후 관리자 승인 | 학교 사전 등록, 이름 로그인, 좌석 IP 연결, 초기 활성화 절차 |
| 최초 비밀번호 변경 | 로그인 후 비밀번호 변경 API 있음 | 임시 비밀번호 상태에서는 업무 자료와 실시간 연결 접근 차단 |
| 교사용 모바일 메시지 | 받은/보낸 메시지·첨부 조회 | 요청한 메시지 확인 기능을 유지하고 계정 활성화 정책 적용 |

| 종료된 앱 알림 | OS 푸시 미구현 | FCM/APNs 연결 및 권한 회수 후 알림 처리 |

기존의 관리자 웹 화면을 교사용 앱 기능으로 간주하지 않는다. 이번 요청에 따라 새 운영 기능은 PC/네이티브 앱에서 처리하는 방향으로 설계한다. 관리자 화면의 네이티브 이전은 별도 남은 작업이다.

## 교직원 계정과 좌석 IP

관리자가 학교 명부로 교직원 계정을 사전 등록한다. 서버가 발급한 변경되지 않는 교직원 ID를 메시지·시간표·예약의 연결 기준으로 사용한다. 이름과 좌석 IP는 그 계정에 연결하는 속성이다. 자리 이동 시 이전 교사의 메시지나 시간표를 새 교사에게 넘기지 않는다.

이름은 한글을 지원한다. 동명이인은 부서 또는 학교가 지정한 구분값으로 로그인 이름을 구분한다. 같은 로그인 이름을 두 계정에 연결하거나 서버가 첫 검색 결과를 임의 선택하지 않는다.

로그인 입력 방식은 사용자에게 확인 중이다: 이름으로 로그인하고 IP를 별도 관리할지, 이름/IP를 각각 로그인 별칭으로 허용할지, PC에서 이름과 접속 IP를 함께 확인할지 확정해야 한다. 권장안은 이름 로그인과 좌석 IP 별도 관리다. 휴대폰은 동일 교사 계정의 개인 비밀번호로 로그인하며 좌석 IP를 요구하지 않는다. 내부 교무실 접속은 기존 교내망/VPN 조건을 따른다.

IP는 좌석 또는 네트워크를 식별하는 보조 정보이며 본인 인증을 대체하지 않는다. 다른 사람이 같은 PC를 사용할 수 있고, VPN·프록시를 통과하면 보이는 IP도 달라진다. IP 정책을 적용할 때 서버가 확인한 접속 정보만 사용한다. 클라이언트가 보낸 IP 필드나 임의의 전달 헤더로 권한을 부여하지 않는다. 프록시를 쓰는 구성에서는 신뢰할 프록시와 허용할 전달 정보를 명시해야 한다.

## 공통 임시 비밀번호의 사용 범위

공통 임시 비밀번호는 첫 설정을 시작하는 값으로만 사용한다. 관리자 계정에는 별도 비밀번호를 사용하고 추가 인증을 적용하는 것을 권장한다. 임시 비밀번호 원문을 저장소·앱·로그에 넣지 않으며 계정마다 별도의 솔트가 적용된 비밀번호 해시로 보관한다.

권장 흐름:

1. 학교 관리자가 교사 명부와 좌석을 등록한다.
2. 교사는 로그인 이름과 공통 임시 비밀번호를 입력한다.
3. 관리자 최초 본인 확인 또는 교사에게 개별 전달한 일회용 활성화 번호로 계정 소유자를 확인한다. 구체적인 본인 확인 방법은 아직 확정하지 않았다.
4. 활성화 확인과 개인 비밀번호 설정이 모두 끝나면 일반 세션을 발급한다.
5. 이후 PC 자동 로그인과 휴대폰 로그인은 그 교사의 일반 세션을 사용한다.

공통 비밀번호와 알려진 이름만으로 다른 교사의 초기 계정을 먼저 활성화할 수 있으면, 비밀번호 변경을 강제해도 계정 가로채기를 막지 못한다. 좌석 IP 확인만으로도 이 문제가 완전히 해결되지 않는다.

초기 세션은 약관 확인·활성화·비밀번호 설정·로그아웃만 허용하고 메시지, 파일, 시간표, 예약, SignalR 연결 등 모든 업무 경로에서 서버가 차단한다. 초기 자격 증명과 활성화 번호에는 만료·시도 제한을 적용한다. 설정 완료는 트랜잭션으로 처리하고 초기 세션을 무효화한다. 관리자가 비밀번호를 초기화하면 모든 기기의 기존 세션을 회수하고 다시 활성화 상태로 전환한다. 기존 정상 계정을 근거 없이 초기화하지 않는다.

## 교사용 앱 화면과 분반 공지

홈에는 오늘의 내 수업, 읽지 않은 메시지, 예정된 학교 일정, 나의 특별실 예약을 표시한다. 주요 메뉴는 메시지·시간표·공지·일정·예약으로 구성한다. 별도 교사 앱을 설치하더라도 서버는 매 요청에서 교직원 여부와 해당 자료의 권한을 확인한다.

분반은 일반 학급과 별도 관리한다. 학년도·학기·과목·분반 코드·담당 교사·수강 학생을 저장하고, 학생 수강 명부가 오기 전에는 실제 수강 학생을 추측하지 않는다. 명부 없는 분반은 학생/보호자 대상 게시를 막고 준비 상태로 표시한다. 기존 학급 공지는 계속 사용할 수 있다.

분반 담당 교사는 자기 분반에 게시하고, 학교가 별도로 권한을 준 담당자만 다른 분반 또는 전체 대상에 게시한다. 학생 대상과 보호자 대상은 발송 시 명시한다. 대상 학생의 담임도 수신한다는 기존 정책을 적용한다. 여러 학급의 학생이 있는 분반이면 관련 담임을 중복 없이 산정한다.

서버가 명부와 현재 자녀 관계로 수신 대상을 계산하며 클라이언트가 제출한 역할·대상 배열을 그대로 신뢰하지 않는다. 대상 밖 계정에는 목록, 제목, 본문, 첨부, 읽음 통계를 제공하지 않는다. 게시 당시 대상과 현재의 접근 자격을 함께 검사하고, 전학·계정 중지·보호자 관계 해제 등으로 자격이 사라지면 열람을 회수한다. 새 학생이나 보호자를 기존 비공개 공지에 임의 추가하지 않는다.

## 학사력·행사·일정

학사 담당자가 학사력·학교 행사를 등록하고, 일정 담당 권한을 가진 교직원이 업무 일정을 등록한다. 시작·종료, 종일 여부, 장소, 설명, 담당자, 첨부, 대상 범위를 저장한다. 학교 시간은 Asia/Seoul 기준으로 표시한다.

교직원 전용 일정과 학생/보호자에게 게시할 일정을 구분한다. 외부 게시를 명시한 일정만 기존 학교 소식 서버에 전달한다. 내부 일정과 예약 정보를 일괄 외부 복제하지 않는다. 수정·취소도 전파하고, 게시 권한 변경과 접근 회수를 서버에서 처리한다.

## 특별실 예약

관리자가 특별실, 사용 가능 시간, 운영 담당자를 등록한다. 교사는 날짜·교시 또는 시작/종료 시각을 선택하고 자기 이름으로 예약한다. 일반 교사는 자기 예약을 변경·취소하고, 특별실 관리자는 관리 대상 특별실 예약을 조정할 수 있다. 변경 사유와 처리자를 기록한다.

같은 특별실에서 활성 예약 A와 신규 예약 B가 `A.Start < B.End && B.Start < A.End`이면 충돌이다. 끝나는 시각과 다음 예약 시작이 같으면 연속 예약을 허용한다. 예약, 시간 변경, 관리자의 조정 모두 같은 검사 규칙을 적용한다.

현재 SQLite 구조를 유지하면서 쓰기 잠금을 확보한 트랜잭션 안에서 중복 확인과 저장을 함께 수행한다. 동시 요청은 한 건만 성공하고 나머지는 충돌 응답을 받는다. 정확히 같은 시작 시각에만 고유 제약을 두는 방식으로 부분 시간 겹침을 처리하지 않는다. 재시도 요청 번호로 중복 예약 생성을 막고, 변경 버전으로 오래된 화면의 덮어쓰기를 방지한다. 실패한 작업은 일부만 저장하지 않는다.

특별실 예약은 교직원 기능으로 운영한다. 학생/보호자에게 교사의 예약 목적이나 업무 내용을 공개하지 않는다.

## 백엔드 보호와 검증

기존 교내 서버·외부 학교 소식 서버의 경계를 유지한다. 새 기능은 기존 인증·저장소·발송 대기열을 재사용한다. 외부 서버에 교내 메시지나 원격지원 데이터를 복제하지 않는다. 인터넷망에서 교무실을 사용하는 방법은 기존 VPN 정책을 따르며, 이번 점검만으로 호스팅이나 망 구성을 바꾸지 않는다.

현재 코드에 있는 HTTPS, 비밀번호 해시, 반복 로그인 실패 잠금, 세션 버전 검사, 메시지/첨부 대상 검사를 확장한다. 다음 항목은 구현·검증해야 할 기준이며 완료 주장으로 읽지 않는다.

- 기본 거부와 매 요청 권한 검사: 목록·검색·상세·다운로드·실시간 연결·변경/삭제 경로 모두 검사한다.
- 역할 구분: 시스템 관리자, 수업 담당자, 분반 담당 교사, 학사 담당자, 특별실 관리자를 분리하고 클라이언트의 권한 선택을 허용하지 않는다.
- 파일 보호: 크기·형식·저장 경로·권한·만료 검사와 악성 파일 대응을 함께 검토한다. 서버의 첨부 1개월 보관 정책을 적용하되 휴대폰에 저장·공유된 사본까지 원격 삭제할 수 있다고 표시하지 않는다.
- 기기 보호: 교사/가족 앱의 설치 ID·세션·공유 캐시를 분리하고 로그아웃 시 임시 첨부를 정리한다. 현재 공통 공유 캐시의 계정 전환 잔존 문제는 후속 수정 대상이다.
- 감사 기록: 계정 등록·활성화·좌석 변경·권한 변경·공지 게시/회수·예약 변경을 기록하되 비밀번호·고유번호·세션 값은 기록하지 않는다. 조회 권한과 보관 기간도 설정한다.
- 운영 보호: 서버 전용 실행 계정, DB/암호화 키 접근 제한, 암호화 백업과 복구 시험, 의존성 업데이트를 실제 운영 환경에서 확인한다.
- 푸시: 잠금 화면에 민감한 본문이나 이름을 넣지 않고, 알림을 연 시점에 다시 권한을 확인한다.

구현 뒤에는 타 계정/분반의 ID를 넣은 요청, 학생이 교사 API를 호출한 요청, 초기 세션의 파일/허브 접근, 임시 비밀번호 재사용, IP 입력 조작, 계정 중지 후 남은 세션, 보호자 관계 해제, 동시 예약·겹치는 시간 변경·재시도·예약 취소 후 재사용을 검사한다. Windows·Android·iOS 실제 앱에서도 활성화와 권한 회수 동작을 확인한다.

이번 작업은 코드와 운영 문서의 요구사항 대조이며, 새로운 기능 테스트나 실제 서버 침투 시험을 실행한 결과가 아니다. 운영 서버의 방화벽·인증서·기기 정책·백업 상태는 이 점검으로 확인되지 않았다.

참고: 서버의 기본 거부·요청별 검사·자료별 권한 설계는 [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html), 인증과 세션 관리 원칙은 [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)를 참고했다.

## 구현 순서

1. 로그인 입력 방식 확정, 교직원 사전 등록·좌석 연결·초기 활성화·서버 접근 제한.
2. 교사/가족 설치 앱 분리와 기존 기능의 계정 연결 유지.
3. 학사력·학교 일정과 특별실 예약 API 및 네이티브 화면.
4. 분반 관리·수강 명부 가져오기·공지 권한. 실제 명부가 올 때까지 준비 기능과 기존 학급 공지 운영.
5. OS 푸시 연동, 권한 회수·동시 예약·계정 전환·복구 시험.

약관은 학교 검토 초안을 유지하고, 운영 가입은 학교가 약관을 확정한 뒤 활성화한다. 학생 개별 가입 후 학교 승인, 학부모 임시계정에서 자녀의 대소문자 구분 8자리 고유번호를 입력하면 즉시 정회원 전환, 다자녀 연결이라는 최근 합의를 유지한다. 공통 임시 비밀번호를 학생·학부모 가입에 확장하지 않는다.
