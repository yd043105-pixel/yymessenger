# 제출 회수와 메시지 보관

## 파일 제출

이미 받은 제출 요청은 PC의 **할 일·제출 → 파일 제출·수합**에서 열고 파일만 제출할 수 있다. 답장 메시지는 필요 없다. 요청이 없는 임의의 상대에게 제출 파일을 보내는 기능과는 다르다.

진행 중이고 면제되지 않은 요청은 **제출 회수**로 미제출 상태로 되돌릴 수 있다. 회수 후 파일을 새로 선택하여 다시 제출한다. 재제출만 해도 수합 화면과 ZIP에는 최신 제출본이 표시된다. 요청이 종료되면 제출·재제출·회수를 막는다. 기한이 지나도 열린 요청에는 지각 제출이 가능하다.

회수는 본인 계정의 현재 제출 번호를 확인한 뒤 처리한다. 오래된 화면에서 누른 회수로 새 제출을 취소하지 않는다. 이전 제출본도 회수 상태로 표시해서 이전 파일이 다시 제출본으로 등장하지 않는다. 이미 회수된 제출 요청 번호로 재시도하면 새 파일을 선택하도록 안내한다.

서버는 회수 직후 다운로드 권한을 차단하고 파일을 만료 처리한다. 다음 파일 정리 때 실물을 삭제한다. 수합자의 미제출 인원과 자동 알림 대상에 다시 포함된다. 이미 다운로드하거나 저장한 사본·진행 중인 다운로드까지 되돌릴 수는 없다.

## 메시지 회수

PC 메시지함의 보낸 메시지에서 **메시지 회수**를 누른다. 수신자 중 한 명이라도 읽었으면 회수할 수 없다. 제출이나 할 일 확인·등록이 진행된 메시지도 회수하지 않는다. 채팅과 시스템 자동 알림에는 이 기능을 적용하지 않는다.

본문 조회, 제출 요청 상세 조회, 첨부 다운로드는 서버에서 먼저 읽음 처리를 확정한다. 읽음과 회수는 같은 SQLite 쓰기 트랜잭션을 사용하므로 동시에 요청해도 둘 중 하나만 성립한다. 메시지 목록의 제목·미리보기나 알림만 본 것은 읽음으로 처리하지 않으므로 이미 보았던 미리보기까지 지울 수 있다는 뜻은 아니다.

회수 시 본문과 제목을 비우거나 회수 표시로 바꾸고, 메시지 목록·상세·첨부 접근과 자동 추출 제안을 없앤다. 미응답 전송 재시도 때문에 회수한 메시지가 재전송되지 않도록 메시지 번호와 요청 지문은 남긴다. `MessageRecalled` 변경 기록으로 연결된 PC와 재접속한 PC가 회수 사실을 동기화한다. 연결이 끊긴 PC에서 이미 보였던 화면이나 사용자가 만든 별도 사본까지 즉시 제거할 수는 없다.

## 보관과 PC 사본

첨부파일의 운영 보관 한도는 업로드부터 30일이다. 본문에는 현재 30일 자동 삭제가 적용되지 않는다. 별도 보관 정책을 확정하기 전에는 서버 기록을 유지한다. 이는 무기한 보관이 개인정보 정책으로 확정되었다는 의미는 아니다.

교사용 앱 확인, PC가 꺼진 동안 수신, 여러 기기의 읽음·회수를 위해 서버가 원본을 가진다. 설치 폴더에만 본문을 보관하도록 구조를 변경하지 않았다. PC 폴더로 이동 자체가 보안을 보장하거나 서버 부하를 크게 줄이는 것도 아니다.

PC에서 **열어 확인한 메시지**는 `%LOCALAPPDATA%/SchoolMessenger/messages` 아래에 Windows DPAPI 사용자 범위로 암호화한 사본을 저장한다. 서버 주소와 사용자 번호로 폴더를 구분하고, 업데이트 설치 폴더와 분리한다. 회수 변경을 받으면 사본도 삭제한다. 연결 없이 사본을 조회하는 화면이나 모든 과거 메시지를 일괄 다운로드하는 기능은 포함하지 않는다.

DPAPI는 다른 Windows 계정의 단순 파일 열람을 막는 보호다. 로그인한 Windows 계정 자체가 침해된 상황까지 보호하는 방식은 아니다. 서버 DB·과거 백업·별도 다운로드에는 각자의 접근 제한과 보관 정책이 필요하다. 회수가 이미 작성된 서버 백업까지 소급 파기하는 기능은 아니다.

## 확인 범위

검사는 가상 교직원과 가상 파일로 수행한다. 타인의 회수 차단, 읽은 메시지 회수 거부, 읽음·회수 동시 요청, 첨부 차단·정리, 회수 후 재시도 중복 방지, 제출 최신본 회수·재제출, 이전 제출본 재등장 차단과 서버 재시작 상태 유지를 확인한다. PC 검사는 작은 접속 원·마우스 안내와 DPAPI 암호화·복원·회수 후 사본 재저장 방지를 확인한다.

후속 검사 중 테스트가 예약 전송 자료를 직접 수정할 때 `database is locked`가 발생했다. 해당 Node 테스트 연결에는 기본 잠금 대기 시간이 없어서 서버의 백그라운드 쓰기와 충돌할 때 바로 실패했다. 테스트 전용 연결에 5초 대기를 설정했다. 서버 연결은 기존 30초 설정을 유지하며, 이 테스트 오류를 서버 전송 HTTP 500의 원인으로 단정하지 않는다.

이전 작업에서 동시 전송 12회 중 발생했던 단일 HTTP 500은 원인 미확인 상태다. 이번 검사가 통과해도 그 오류의 원인이 규명되거나 해결되었다고 주장하지 않는다.
