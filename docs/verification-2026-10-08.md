브라우저에서 별도로 **9개 항목**을 확인했다: 승인 교사 로그인·받은함, 원문 표시, 할 일 편집·등록, 설문 응답 저장, 채팅 조회, 실제 파일 업로드·즉시 상태 갱신, 첨부 및 일괄 ZIP 다운로드, 요청 교사 현황·면제 변경, 로그아웃 시 개인 데이터 제거. 요청 종료의 브라우저 확인 팝업은 자동화 도구가 응답하지 않아 UI 검사를 완료하지 못했다. 서버의 종료·권한·재제출 차단 검사는 통과했다.

발견하여 수정한 사항:

- 웹 제출 직후 상세는 완료였지만 목록에 미제출이 남았다. 제출·면제·요청 종료 뒤 목록과 상세를 함께 갱신하도록 수정했고, 새 데이터로 미제출→제출 완료가 즉시 바뀌는 것을 확인했다.
- 실제 키보드 검사 창에 포커스를 주는 단일 시도가 간헐적으로 실패했다. 최대 2초 동안 포커스를 확인하며, 안전한 검증 창에 포커스가 없으면 입력을 보내지 않는 조건을 유지했다.
- 릴리즈 빌드의 런타임·단일 파일 설정이 개발용 잠금 파일과 달랐다. 공통 런타임 대상과 단일 파일 설정을 명시하고 잠금 파일을 갱신했다. SQLite 라이브러리를 데이터 파일로 오인한 배포 검사 정규식도 수정했다.

NuGet 취약점 조회에서 두 프로젝트의 직접·간접 패키지에 알려진 취약점이 보고되지 않았다. 공개 소스에 DB·첨부·비밀번호·인증서 개인키를 포함하지 않았고, ZIP의 개인정보 파일 제외와 SHA-256 일치를 확인했다.

CI용 화면 없는 검사에는 50개 서버 검사가 포함된다. 실제 WPF·Windows 키보드 검사를 CI에서 통과했다고 표시하지 않는다. 서로 다른 학교 PC 두 대, 교내 인증서·망·운영 백신·실사용 부하는 현장 시범 운영 대상이다. Android·iPhone 앱과 학생·학부모 외부 공지는 아직 구현 범위에 포함하지 않는다.
