# 학교 엑셀 시간표 운영

버전은 1.0.0. Windows 메신저의 **시간표**에서 등록하고, 교사 PC·Android/iOS 공통 앱 화면·교무실 웹·학생/보호자 웹에서 조회한다. 학생별 수강 목록이 없어도 사용할 수 있다. 이 문서는 시간표 기능의 운영 절차이며, 스토어 출시나 백그라운드 푸시 구축을 완료했다는 의미는 아니다.

## 처음 설정

1. 외부 학교 소식 서버에 학년·학급과 학생·보호자 관계를 등록하고 교내 서버의 `Announcements:Address`, `Announcements:BridgeKey`를 연결한다. 시간표의 학급 식별자는 해당 명부를 사용한다. 명부 연결이 끊겼다면 게시가 제한된다.
2. 관리자 PC에서 **시간표 → 수업 담당자 권한 · 담임 연결**을 연다. 수업 담당자를 지정하고 시간표에 포함될 각 학급의 담임을 활성 교내 계정과 연결한다. 전체 공지 발송 권한과 수업 담당자 권한은 별개다.
3. 실제 담당 교사가 교내 계정을 발급받았는지 확인한다. 같은 이름이 여러 명이면 부서·계정 번호까지 보고 직접 연결한다. 자동 후보가 하나면 화면에서 선택해 주지만, 계정이 없거나 후보가 모호하면 임의로 배정하지 않는다.

## 학기 기초시간표

수업 담당자가 **학기 기초시간표 올리기**에서 학교 양식의 `.xlsx`를 고른다. 학년도와 학기가 표시되고, 학급과 교사를 명부에 연결한다. 적용 시작·종료일을 직접 선택한 뒤 **미리보기**에서 내용을 검토하고 게시를 확인한다. 파일 선택이나 미리보기만으로 학생 화면이 바뀌지는 않는다.

지원 양식은 학급이 행에 있고 요일·교시가 열에 있는 표다. `과목(교사)`를 읽으며 병합된 교시도 처리한다. 한 파일의 여러 시트가 같은 학년도·학기여야 한다. 날짜 범위가 겹치는 별도 기초시간표는 막는다. 기존 기간과 동일한 기간으로 교체하거나 기존 게시본을 취소한 뒤 새 기간을 등록한다.

## 변경이 있는 날

**일자별 시간표 올리기**에서 해당 파일을 올린다. 파일의 `일자` 행/열에 적힌 실제 수업일을 사용하며 인쇄·내보내기 날짜는 사용하지 않는다. 한 파일은 같은 수업일 하나만 지원한다. 미리보기에서 변경된 교시와 이전/현재 교사·과목을 확인한 뒤 게시한다.

- 해당 날짜에 해당 학급이 포함되면 일자별 표의 전체 교시를 적용한다. 빈 칸은 **수업 없음**이며 기초 수업으로 채우지 않는다. 하루 전체가 빈 일자별 파일도 휴업·수업 취소 표로 사용할 수 있다.
- 일자별 표에 없는 학급이나 다른 날짜는 유효한 기초시간표를 따른다. 변경이 없으면 파일을 올릴 필요가 없다.
- **게시 이력 · 취소**에서 현재 게시본을 취소하면 그 날짜/학급은 기초시간표로 돌아간다. 앞서 올렸던 다른 일자별 수정본을 다시 살리지 않는다. 일부 학급이 이미 새 파일로 교체되었다면 오래된 파일 전체 취소를 막으므로 현재 게시본을 확인한다.
- 다른 담당자가 먼저 게시하면 이전 미리보기는 만료된다. 다시 미리보기한다. 업로드 초안은 24시간, 게시 후보는 15분 보관한다.

## 조회와 알림

교사는 **내 수업** 또는 학급을, 학생은 자기 학급을, 보호자는 현재 연결된 자녀의 학급을 선택한다. 날짜와 주 단위 조회를 제공하며 변경 전 수업과 최종 게시 시각을 표시한다. 아직 기초시간표가 없으면 미등록으로 표시한다. 학생별 선택과목이나 교실·분반은 원본 파일에서 추측하지 않는다. 나중에 실제 수강 명부를 연결할 때 그 자료를 기준으로 개인 시간표를 제공한다.

변경된 학급의 학생·보호자·담임과 변경 전/후 수업 교사에게 중복 없이 읽음 상태가 있는 알림을 저장한다. 각 담임·가족의 알림은 해당하는 학급만 가리키며, 알림을 누르면 변경된 학급의 시간표를 연다. PC는 실시간 알림과 30초 재조회로 확인한다. 앱과 웹은 시간표 화면 및 다음 로그인/새로고침에서 확인한다. **앱이 완전히 종료된 상태의 OS 푸시는 아직 제공하지 않는다.** APNs/FCM 자격 증명·기기 등록과 실제 수신 검증을 별도로 완료해야 한다.

외부 서버에는 정규화한 시간표와 필요한 알림만 교내 서버가 밖으로 전달한다. 원본 엑셀과 교직원 업무 메시지는 전달하지 않는다. 전달 실패 시 교내 게시본과 대기열을 유지하고 연결 복구 후 순서대로 재시도한다. 서버가 갱신되는 짧은 시간 동안 앱에는 이전 버전이 보일 수 있으므로 PC의 **앱 전달 대기**와 화면의 버전을 확인한다.

보호자 관계 해제·전학·교사 연결 만료는 서버에서 다시 검사하며 다른 학급 ID를 지정해도 허용되지 않는다. 시간표 원본의 교사 이름은 수신 학급 학생/보호자에게 표시된다. 공지 서버의 명부 권한과 운영 동의를 학교에서 정리한다.

## 파일과 운영 제한

원본 `.xlsx`는 10MB 이하다. 수식은 값으로 저장해서 제출하며 매크로·외부 연결·손상 파일은 거부한다. 운영 환경의 악성코드 검사 설정을 사용하고 임시 원본은 가져오기 성공/실패 후 즉시 삭제한다. 시간표 셀·게시 이력은 DB에 남으며 **학년도 말 자동 삭제는 아직 구현하지 않았다.** DB/백업의 보관 기간은 학교 운영 정책으로 관리해야 한다.

두 서버 모두 이 기능이 포함된 버전으로 갱신한다. 아직 배포 승인을 하지 않았으므로 GitHub Release·스토어 게시는 수행하지 않는다. 운영 인증서·브리지 키·원본 엑셀·학생 수강 명부를 공개 저장소에 넣지 않는다.

## 확인 명령

`dotnet build tests/TimetableChecks -p:RestoreLockedMode=true` 후 `node tests/timetable.mjs`를 실행한다. 재현 테스트는 학교 개인정보 없이 만든 병합 셀 양식과 가상 계정만 사용한다. 실제 파일 확인은 로컬에서 테스트 실행 인자로만 전달할 수 있고 원본이나 교사 이름을 테스트 결과에 저장하지 않는다.
