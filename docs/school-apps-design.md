# 교사 앱·학생/학부모 앱 분리와 학교 소식 연동 설계

작성일: 2026-10-08. 상태: 사용자 검토안. 이 문서는 추가 기능의 설계이며 구현 완료 보고서가 아니다. 버전은 배포 지시 전까지 1.0.0을 유지한다.

## 목적과 사용자 요청

교사용 PC 메신저에서 가정통신문이나 공지와 파일을 올리면, 지정한 학생·학부모와 교사가 각자의 앱에서 알림을 받고 확인한다. 전체 학교뿐 아니라 학년·학급·개별 학생 등 필요한 대상에게만 보낸다. 대상 밖의 계정에는 목록·본문·첨부를 제공하지 않는다. 학생·학부모 앱에는 시간표와 급식도 제공한다.

‘제한해서 보낸다’는 요청은 포함 대상을 지정하고 필요하면 일부를 제외하는 방식으로 해석한다. 예를 들어 ‘2학년 학생과 보호자, 2학년 3반 제외’라면 제외된 학급은 알림과 열람 모두 받을 수 없다. 선택한 학생의 보호자는 학교가 확인한 보호자 관계로만 산정한다.

이전 제안 중 응답·동의서, 학생·학부모 자료 제출, 상담 예약은 이번 설계 범위에 추가하지 않는다. 이미 구현한 교직원 제출 기능을 외부에 그대로 노출하지 않는다.

## 현재 구현과 추가 범위

현재 PC의 `AnnouncementWindow`와 교내 `ExternalAnnouncements` 발송 대기열, 별도 외부 공지 서버가 연결되어 있다. 학생·보호자 역할과 학급/학교 전체 선택, 첨부 전송·열람 검사·읽음 현황·공지 회수가 구현되어 있다. 모바일은 하나의 앱에서 외부 학교 소식과 교내 교무실을 선택한다.

추가할 것은 두 앱의 설치·로그인·화면 분리, 발송 대상의 학년/개별 학생/제외 조건, 교사 수신 대상, 시간표·급식, Android/iOS 원격 푸시 알림이다. 현재 앱을 열어 새로고침하는 기능을 백그라운드 푸시 구현으로 간주하지 않는다.

## 앱 구성 선택

권장안은 기존 MAUI 소스를 공유하면서 교사용·가족용 두 앱으로 빌드하는 방식이다. 각각 별도 앱 식별자, 표시 이름, 아이콘 표시, 로그인 저장소, 푸시 설정을 사용하여 한 기기에 함께 설치할 수 있다. 교사 앱은 교직원 계정만, 가족 앱은 학생·보호자 계정만 허용한다. 가족 앱에는 교직원 서버 주소 선택과 업무 메뉴를 넣지 않는다. 변조된 앱을 고려하여 역할과 자료 접근은 서버에서도 검증한다.

하나의 앱에 역할별 화면만 두는 방식은 변경량이 적지만 사용자가 요청한 별도 설치 앱에 맞지 않는다. 두 개의 독립 코드베이스는 화면·보안 수정과 Android/iOS 검사를 반복해야 하므로 채택하지 않는다.

표시 이름은 ‘여양고 교무실’, ‘여양고 학교 소식’을 제안한다. 학교의 실제 개발자 계정에서 앱 식별자 소유권을 확인하기 전에는 스토어에 등록하지 않는다. 설치 앱 두 개와 기존 PC 프로그램의 표시 버전은 모두 1.0.0이다.

## 발송 화면과 대상 확정

PC에서 제목·본문·파일을 입력한 뒤 수신 역할을 학생, 보호자, 학생과 보호자로 선택한다. 이어 전체 학교, 학년, 학급, 개별 학생 중 하나의 기본 범위를 선택한다. 개별 학생의 보호자에게 보내는 경우 보호자 이름을 직접 검색하여 임의 연결하지 않는다. 기존 담당 학급 범위에서 학생을 선택하고 확인된 보호자를 산정한다.

학급·학생 제외 목록은 기본 범위에서 빼는 조건으로 적용한다. 서로 모순되는 포함/제외 선택은 최종 미리보기에서 명확히 표시하고 제외를 우선한다. 결과가 0명인 발송은 차단한다. 교사의 담당 범위 밖 선택은 화면뿐 아니라 교내 서버와 외부 서버에서도 거부한다. 학교 전체·임의 학년 발송은 별도 전체 발송 권한이 필요하다.

사용자의 추가 요청에 따라 최종 대상 학생이 속한 학급의 담임 교사는 자동으로 함께 받는다. 학생만, 보호자만, 학생과 보호자 중 어느 역할로 발송해도 적용한다. 학급·학생 제외 조건을 먼저 적용하고 남은 대상 학생의 학급에서 담임을 산정하므로, 제외된 학급의 담임에게 자동 전달하지 않는다. 한 학급에서 일부 학생만 제외했다면 남은 대상 학생이 있는 한 그 학급 담임은 받는다. 같은 담임이 여러 수신 근거를 가져도 공지와 기기별 알림은 중복 생성하지 않는다.

관리자가 학급마다 담임 계정을 명시적으로 연결한다. 기존 `TeacherClasses`는 담당 범위이며 교과 교사도 포함할 수 있으므로, 여기에 등록된 모든 교사를 담임으로 간주하지 않는다. 학교가 확인한 활성 교직원 계정만 담임으로 연결하고 교내 교직원 확인도 적용한다. 담임이 미등록·비활성·확인 불가인 학급은 발송 전 미리보기에 오류를 표시하고, 정상 담임 연결을 확인하기 전에는 해당 발송을 확정하지 않는다. 임시 담임·대체 담임은 관리자 연결을 변경하여 처리한다.

작성자는 항상 본인이 보낸 공지와 발송 상태를 확인할 수 있다. 담임 외에 내용을 함께 받을 추가 교사는 별도로 선택한다. 추가 교사 수신자는 학교가 확인한 활성 교직원으로 한정한다. 일반 교사는 해당 공지의 담당 학급에 연결된 교사를 선택할 수 있고, 전체 발송 권한자는 전체 또는 개별 교직원을 선택할 수 있다. 담임·추가 교사에게 공지 본문과 첨부를 제공하지만, 이것만으로 다른 가족의 명단·읽음 상태 조회 권한을 부여하지 않는다.

발송 직전에 역할별 인원수, 포함 학급/학생, 제외 조건, 자동 포함 담임, 추가 교사, 외부로 전달되는 파일을 표시한다. 수신 목록은 게시 시 확정한다. 대기 중 관계·소속·담임 연결·교사 권한이 변경되면 새 사람을 자동 추가하지 않고 재검토 상태로 남긴다. 중복 요청은 동일한 공지로 처리하며 대상이나 내용을 바꾸려면 새 요청으로 보낸다.

예시: ‘1학년 2반 보호자만, 학생 A 제외’는 해당 학급의 A를 제외한 학생들에게 학교가 연결한 보호자와 그 학급 담임에게 자동 제공한다. 학생 계정은 보호자 전용 공지를 받을 수 없다. 보호자가 다른 대상 자녀도 가지고 있으면 그 자녀를 통한 수신은 유지하며 자녀별 수신 근거를 구분한다.

## 서버 경계와 접근 검사

교직원 개인 쪽지·업무 파일·원격지원은 기존 교내 서버에 유지한다. 공개 공지 서비스에는 교사가 명시적으로 게시한 학교 소식과 필요한 대상 정보만 전송한다. 교사용 앱의 외부 학교 소식과 내부 업무 영역은 별도 세션을 유지하며, 학교 밖 내부 업무 접근은 기존 교내망/VPN 정책을 따른다.

기존 학생/보호자 공지 대상과 별개로 교사 수신 기록을 저장한다. 가족 관계를 가짜 학생 기록으로 표현하지 않는다. 목록·검색·공지 상세·읽음 처리·첨부 다운로드·알림 클릭마다 활성 계정과 현재 수신 근거를 확인한다. 대상 밖에는 공지 제목, 파일명, 수신 인원도 공개하지 않는다. ID 또는 다운로드 주소를 다른 계정에 전달해도 접근을 거부한다.

학생 소속 변경, 보호자 관계 해제, 교사 담당 범위 회수, 계정 정지, 공지 회수는 열람·푸시 대상에도 적용한다. 자동 담임 수신 기록에는 학급과 담임 연결 당시의 식별 정보를 보관한다. 담임 변경 시 이전 담임의 자동 수신 근거를 회수하고 새 담임에게 과거 공지를 자동 공개하지 않는다. 작성자나 별도로 확정한 추가 교사 수신 근거가 있으면 그 권한은 독립적으로 검사한다. 이미 회수한 권한을 재연결로 되살리지 않는다. 발송자가 볼 수 있는 읽음 명단은 본인의 현재 담당 범위와 전체 발송 권한으로 제한한다. 알림 수신이나 앱 화면 표시 자체는 읽음으로 처리하지 않으며, 실제 공지 열람 후 서버에 읽음 기록을 남긴다.

첨부의 기존 30일 만료와 크기·유형·백신 검사 규칙을 유지한다. 만료 파일은 알림이나 오래된 링크로도 복원하지 않는다. 외부 운영 데이터와 비밀키는 공개 저장소·앱 패키지·로그에 넣지 않는다.

## 시간표와 급식

급식은 사용자가 선택한 NEIS 공개 데이터 자동 연동을 사용한다. 시간표는 사용자의 최신 요청과 제공 양식에 따라 학교가 업로드한 학기 기초시간표·일자별 시간표를 기준으로 운영한다. 자세한 적용·업로드·조회·알림 규칙은 [시간표 업로드 설계](timetable-import-design.md)를 따른다. 실제 학생·보호자 명부나 개인별 선택과목 정보를 NEIS에 보내지 않는다. 급식 연동에는 학교 식별 코드만 사용하고 API 키는 서버에서 보관한다.

시간표는 오늘과 주간 보기, 날짜 이동, 학년·학급 및 교시별 과목을 제공한다. 학생은 본인 학급을 기본으로, 보호자는 선택한 자녀 학급을 기본으로 보여준다. 교사는 업로드 자료에서 교직원 계정에 연결한 수업으로 개인 시간표를 확인하며 학급 표도 조회한다. 일자별 표가 있는 날짜·학급은 해당 표를 우선하고 없으면 유효한 기초 표를 사용한다. 학생별 선택과목 시간표는 별도의 수강 배정 자료가 있어야 하며 제공된 학급 표만으로 임의 생성하지 않는다.

급식은 날짜별 조식·중식·석식 중 등록된 항목과 메뉴, 제공되는 알레르기 표기, 열량을 표시한다. 식단이나 시간표가 없는 날은 ‘등록된 정보 없음’으로 표시하여 조회 장애와 구분한다.

수업 담당자는 PC에서 시간표 엑셀을 미리보기 후 게시·교체·취소한다. 날짜별 표의 빈 교시는 수업 없음이며 기초 수업으로 되채우지 않는다. 급식 담당자는 자동 연동 식단을 수정할 수 있고 학교 수정본은 자동 갱신으로 덮어쓰지 않는다. 급식 외부 서버는 하루 한 번 한국 시간으로 동기화하고 권한 있는 담당자의 수동 갱신을 허용한다. 시간표·급식 모두 최근 갱신 시각과 자료 출처를 표시한다. 원본 서비스 오류나 외부 전달 대기에서는 마지막 정상 자료를 시각과 함께 표시하고 최신 반영 완료로 오인시키지 않는다.

급식의 학교/교육청 코드와 학교 시간표의 학급·교직원 계정 매핑은 관리자 설정과 확인 화면에서 연결한다. 이름이 비슷한 학급이나 동명이인 교사를 추측해서 연결하지 않는다. 급식 자동 연동의 키·학교 코드가 없으면 설정 필요 상태를 표시한다. 서버는 허용한 NEIS HTTPS 주소만 호출하여 관리자 입력을 통한 임의 URL 요청을 막는다.

## 앱 알림

게시가 외부 서버에서 확정되면 수신 대상의 등록 기기에 알림 작업을 기록한다. Android는 FCM, iOS는 APNs를 사용한다. 비공개 공지를 공개 토픽이나 앱이 자율 가입하는 학급 토픽으로 발송하지 않고, 서버가 권한을 확인한 사용자 기기별로 발송한다.

기기 등록은 로그인 세션과 앱 종류에 연결하며 토큰 갱신·로그아웃·계정 전환·기기 분실·관계 회수에 대응한다. 로그아웃에는 서버 기기 연결 해제와 기기 알림 정리를 포함한다. 푸시 비밀키는 학교가 관리하는 서버에서만 사용한다. 두 앱의 기기 연결과 앱 식별자를 섞지 않는다.

잠금 화면에는 ‘새 학교 소식이 도착했습니다’ 같은 일반 문구만 표시한다. 학생 이름·학급·공지 제목·본문·첨부 링크·세션은 푸시에 넣지 않는다. 알림을 누르면 로그인 상태와 공지 권한을 다시 확인한 뒤 상세를 연다. 이미 회수되었거나 만료된 대상이면 공지 내용을 표시하지 않는다.

알림 작업은 중복 방지와 재시도를 적용하고 전송 직전 현재 수신 권한을 다시 검사한다. 이미 발송한 알림의 원격 삭제를 보장하지 않으며 일반 문구만으로 정보 노출을 줄인다. 알림 차단·네트워크 지연·운영체제 상태 때문에 수신을 보장할 수 없으므로 앱의 미확인 목록과 교사의 읽음 현황을 함께 사용한다. 시간표 변경은 게시·교체·취소로 확정한 변경에 대해 영향받는 학급 가족·담임과 변경 전후 교사에게 알린다. 단순 미리보기·동일 자료 재업로드·급식 자동 수집마다 전체 학교 알림을 보내지 않는다.

## 오류와 실제 배포 조건

교내 PC는 기존 발송 대기열 상태를 보여주고, 게시됨과 푸시 요청됨/실패를 구분한다. 푸시 실패로 이미 게시한 공지를 취소하지 않는다. 같은 공지를 다시 게시하여 중복을 만드는 대신 알림 전송만 재시도한다. 제공사가 요청을 수락한 상태를 모든 기기 수신 완료 또는 읽음 완료라고 표시하지 않는다.

FCM 프로젝트 설정, iOS 앱별 푸시 권한과 APNs 서명 정보, NEIS 연동 키·학교 코드가 없더라도 가상 제공자로 권한과 재시도 로직을 검사할 수 있다. 실제 푸시 수신 시험은 학교 계정 설정과 실제 Android/iPhone이 준비된 뒤 별도로 실시한다. 시뮬레이터 검사나 가짜 전송 수락을 실제 휴대폰 푸시 성공으로 보고하지 않는다. 현재 요청은 출시 지시가 아니므로 스토어 게시·GitHub 릴리즈 생성·버전 인상은 하지 않는다.

## 일반 개발 방식의 작업 순서와 검증

1. 대상 산정 규칙을 교내 발송과 외부 게시에서 공유하고 개별 학생·제외 조건·담임 자동 수신·추가 교사 수신을 확장한다. 학급별 담임 연결을 관리자 설정에 추가하고 기존 DB와 기존 공지의 권한을 유지하는 마이그레이션을 작성한다.
2. PC의 최종 대상 미리보기와 모바일 두 앱의 식별자·로그인 경계를 구현한다. 웹에서도 동일한 대상 선택과 서버 규칙을 적용한다.
3. 시간표 기초/일자별 엑셀 업로드·적용·취소와 급식 공개 자료 연동·직접 수정, 출처·오류 상태와 가족/교사 조회 화면을 구현한다.
4. 기기별 알림 등록·해제, 게시 알림 대기열, FCM/APNs 전송과 앱 알림 클릭을 구현한다. 운영 키가 없으면 설정 대기 상태를 명시한다.
5. 가상 가족과 교사로 PC 파일 게시부터 대상 앱 조회·읽음·회수까지 확인한다. 비대상 상세/첨부 접근, 보호자 다자녀, 제외 우선, 대기 중 명부 변경, 보호자 전용 공지의 담임 자동 수신, 제외 학급 담임 미수신, 담임 미등록 차단, 교과 담당 교사 미자동 수신, 담임 변경 후 접근 회수, 중복 담임 알림 방지, 대상 교사와 발신자 권한, 재시작 후 알림 재시도, 로그아웃 기기 제외를 검사한다.
6. 두 앱의 Android 빌드·동시 설치·역할별 로그인, iOS 두 빌드·시뮬레이터, 실제 기기 푸시 준비 여부를 각각 보고한다. 시간표 휴일·다중 수업·수정 우선·NEIS 장애·한국 날짜 경계와 급식 알레르기 표기를 확인한다.

Superpowers는 사용자가 지정한 brainstorming만 적용한다. 승인 후 구현·검사는 일반 개발 방식으로 진행한다.
