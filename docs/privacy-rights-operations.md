# 개인정보 권리 요청 접수·회신

2026-10-24 · 개발 기능과 학교 운영 절차를 구분

## 사용자

PC 설정 또는 교사용/학생·학부모 앱의 내 정보에서 **개인정보 열람·정정·삭제 요청**을 연다. 열람, 정정, 삭제·탈퇴·동의 철회, 처리정지 중 하나를 골라 제목과 요청 내용을 적는다. 로그인 계정 식별자와 접수번호로 학교가 확인하므로 비밀번호·주민등록번호·신분증 파일을 보내지 않는다. 이 요청만으로 계정이 즉시 삭제되지는 않는다. 같은 화면을 새로고침해 처리 상태와 학교 회신을 확인한다. 로그인할 수 없으면 약관 안내에 표시된 해당 학교의 문의처에 요청한다.

## 학교 관리자

관리자 프로그램의 전체 접수 화면에서 ‘개인정보 권리 요청’ 분류·접수번호·학교 계정 식별자·요청 내용을 확인한다. 업무 서버와 학교 소식 서버의 접수함은 각각 조회한다. 본인/대리인 확인, 관련 정보 파악, 법령상 허용 여부 검토, 실제 계정·자료 처리, 결과 또는 제한 사유 회신을 학교 담당자가 수행한다. 상태만 ‘처리 완료’로 바꾸는 것은 실제 삭제·정정이 아니다. 요청 유형별 법정 처리 기한과 처리 책임자는 학교가 확정하고 관리한다. 학생 교육 기록을 요청만으로 일괄 삭제하거나 학부모 번호 확인을 법정대리인 신원 확인으로 간주하지 않는다.

학교 회신은 신청자에게 표시된다. 비밀값이나 다른 이용자 정보를 쓰지 않는다. 권리 요청은 개발용 설명 승인 체크가 나타나지 않으며, API에서도 개발용 승인과 내보내기를 차단한다. 오류 알림 메일도 생성하지 않는다. 개발자에게 권리 요청의 원문을 전달하지 않는다.

## 보호와 한계

- 기존 인증·CSRF·관리자 권한을 사용한다. 일반 사용자는 본인 접수만 조회한다.
- 요청 원문·회신은 학교 서버의 Data Protection 보호자로 암호화한다. DB 파일 전체 암호화나 운영체제 관리자의 접근 방지를 뜻하지 않는다. 키·OS 계정·백업 장치 보호가 필요하다.
- 같은 접수번호의 중복 요청은 같은 응답을 반환하고 내용 변경은 거부한다. 하루 10건/계정·보관함 10,000건 한도가 있다. 긴급·초과·로그인 불가 요청은 학교 문의처에서 받는다.
- 학생과 마지막 재학 자녀가 졸업한 보호자의 계정에 연결된 접수는 기존 졸업 파기 대상이다. 학교 외부에 내보낸 사본과 별도 법정 보관 자료는 학교가 정한 기준으로 관리한다.
- 알림·기한 자동 관리, 자동 법적 판단, 임의의 모든 데이터 즉시 삭제, 법률 적합 인증을 제공하는 기능이 아니다.

시험: `node tests/feedback.mjs`는 두 서버에서 네 유형·암호화·본인 격리·관리자 회신·CSRF·권한·중복·개발 내보내기 제외·오류 메일 제외·졸업 파기를 가상 데이터로 검증한다.
