# 학생·학부모용 공지 이미지 열람

PC 메신저의 학생·보호자 공지 창과 교사용 앱에서 공지를 작성한다. 가정통신문과 일반 공지 모두 아래 제한을 적용한다. 유형을 생략하는 기존 클라이언트도 같은 제한을 받는다. 공지 유형은 분류 정보이며 첨부 제한의 예외를 만들지 않는다.

- 모든 공지 첨부는 `.jpg`, `.jpeg`, `.png`만 허용한다. 한 장당 **200,000바이트(200KB, 0.2MB)** 이하, 최대 5장이다. 여러 쪽은 읽는 순서대로 올린다.
- 교내 서버와 공지 서버가 업로드와 게시 시 모두 검사한다. 파일 시그니처·이미지 헤더·해상도를 검사하고 운영 환경에서는 기존 악성코드 검사도 통과해야 한다. 각 변 6000픽셀 이하, 총 1600만 화소 이하이다. 모든 손상 파일의 완전한 디코딩을 보장하는 검사는 아니다.
- Android/iOS 공지 상세에서 인증된 연결로 이미지를 가져와 바로 표시한다. 확대해서 읽기와 이미지 새로고침을 제공한다. 이미지 열람은 앱의 파일 저장·공유 경로를 사용하지 않는다.
- `/api/attachments/{id}/view`는 학생·보호자·담임·분반 열람 권한, 회수, 만료 및 저장 파일 검증을 적용한다. JPG/PNG MIME, `Content-Disposition: inline`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`를 사용한다. 공지 첨부의 기존 다운로드 경로는 모두 404이다.
- 이미지 보관 기간은 업로드 시점부터 최대 30일이며, 늦게 전달되어도 원본 기한을 연장하지 않는다. 만료 후 공지 내용은 남고 이미지의 보관 기간 만료를 표시한다.
- 교직원 쪽지·채팅·제출 파일에는 이번 공지 이미지 제한을 적용하지 않는다.

이전 게시물의 본문과 데이터를 자동 삭제하거나 변환하지 않는다. 이전 문서 첨부(PDF·한글 등)나 200KB 초과 이미지는 새 열람 경로에서 표시하지 않으므로 담당자가 제한에 맞는 이미지로 다시 게시해야 한다. 이전 제작본으로 보낸 미게시 첨부도 게시 시 같은 검사를 받는다.

이미지 표시에도 바이트 전송은 필요하다. 다운로드 버튼을 없애도 화면 캡처, 다른 클라이언트의 열람 응답 저장, 이미 표시된 자료의 사본까지 막을 수는 없다. 제한된 자료를 공개 CDN 캐시로 배포하지 않는다.

200KB는 텍스트 중심 JPG 문서의 시작 제한이다. 글자 크기와 압축 품질에 따라 읽기 어려울 수 있으므로 업로드 전에 확대해서 확인한다. 자동 압축·변환은 제공하지 않는다. 화면 낭독기 사용자를 위해 중요한 안내는 공지의 텍스트 본문에도 적는다.

기존 데이터의 `Notices.Kind`는 시작 시 `notice` 기본값으로 추가한다. 일반 공지의 기존 게시 요청 지문과 업무 서버 발송 대기열의 이전 JSON 비교를 유지한다. 버전은 1.0.0이다.

교내 서버·공지 서버·PC 메신저·두 앱을 함께 최신 제작본으로 교체한다. Android 설치파일은 로컬 서명된 Debug 시운행용이며 스토어 배포본이 아니다. iOS는 같은 소스를 공유하지만 별도 Mac 빌드와 실제 기기 검증이 필요하다.

앞선 검증에서 발견한 졸업 정보 파기 수정: 기본 `backups`, `migration-backups`, `recovery-backups`에서는 모든 `.db` 백업을 검사한다. 별도 백업 장치에서는 해당 서버 역할의 파일명만 검사한다.
