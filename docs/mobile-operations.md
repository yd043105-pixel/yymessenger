# 학교 소식 앱·외부 공지 서버 운영

2026-10-08 구현 기준. 학교의 외부 도메인·서버·스토어 계정은 아직 이 작업에 제공되지 않았으므로 실제 인터넷 공개와 스토어 출시는 진행하지 않았다.

## 연결 구조

교직원 서버와 외부 공지 서버를 서로 다른 호스트에 설치한다. SQLite, 첨부 폴더, 로그인 쿠키, 암호화 키를 공유하지 않는다. 인터넷에는 외부 공지 서버의 HTTPS 포트만 열고 교직원 API·원격지원·개인 메시지 서버는 교내망에 유지한다. 교사가 학교 밖에서 업무 메시지를 열려면 학교 승인 VPN이 필요하다.

교직원 서버가 외부 공지 서버에 HTTPS 연결을 시작한다. 승인된 학급·계정 관계와 교사의 활성·전체 발송 권한을 확인하고, 교사가 별도로 작성한 외부 공지와 전용 첨부만 전송한다. 개인 쪽지·채팅·설문·할 일·파일 수합 자료는 복제하지 않는다. 연결 키는 앱에 포함되지 않는다.

발송 때 수신자와 당시 관계·소속의 변경 번호를 확정한다. 대기 중 새 보호자가 연결되어도 이전 공지 대상에 추가되지 않는다. 관계 해제 후 재연결, 학급 변경 후 원복, 계정 중지 후 재활성화가 있었어도 예전 대기 공지는 `재확인 필요`로 멈춘다. 내용을 확인해 새 공지를 작성하거나 기존 대기 공지를 회수한다. 연결 장애는 DB 대기열에 남아 재시도한다. 응답을 받지 못한 경우에도 발송 번호로 기존 게시 여부를 먼저 확인한다.

## Windows 외부 서버

1. 배포 ZIP의 `announcement-server`, `scripts/Start-AnnouncementServer.ps1`을 별도 서버에 설치한다. `server` 폴더는 교직원 서버이며 외부에 공개하지 않는다.
2. 공인 도메인, 신뢰되는 HTTPS 인증서와 자동 갱신, 학교 관리 서버 계정을 준비한다. Windows 로컬 컴퓨터 인증서 저장소에 개인키가 있는 인증서를 설치한다. 현재 실행 스크립트는 직접 HTTPS를 제공하며 프록시의 임의 전달 헤더를 신뢰하지 않는다.
3. 충분히 긴 무작위 연결 키를 생성해 외부 서버의 `Portal__BridgeKey`와 교직원 서버의 `Announcements__BridgeKey`에 같은 값을 설정한다. 환경변수·서버 설정은 제한된 운영 계정만 읽게 하고 GitHub에 올리지 않는다. 키를 URL이나 앱 설정에 넣지 않는다.
4. 교직원 서버 환경변수 `Announcements__Address=https://학교가-소유한-공지-도메인:포트`를 설정하고 재시작한다. 주소는 경로 없는 HTTPS 기본 주소다. HTTP는 Development의 로컬 테스트에만 허용된다.
5. 외부 서버에서 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Start-AnnouncementServer.ps1 -CertificateThumbprint 인증서지문 -PublicHost 실제도메인 -DataDirectory 별도데이터폴더 -Port 443`을 실행한다. 최초 관리자 비밀번호와 연결 키는 화면에 표시하지 않고 입력한다.
6. 외부 관리자 웹 화면에서 학급, 학교가 확인한 교사·학생·보호자 계정을 등록한다. 교사는 Windows `학교 공지` 창에 표시되는 교내 계정 번호로 연결하고 담당 학급을 지정한다. 보호자·학생 관계는 학교가 직접 확인 후 연결한다.
7. 초대 코드는 한 번, 2일 이내 사용한다. 사용자가 역할·자녀·담당 학급을 스스로 지정할 수 없다. 교사 신규 로그인·발송은 최근 2분 이내 교직원 연결 확인이 필요하다. 교내 서버가 장시간 중단되면 교사 외부 접근이 제한되지만 학생·보호자는 이미 게시된 허용 공지를 읽을 수 있다.

등록 이전에 학교가 확정한 계정도 수신 대상이 될 수 있다. 해당 계정으로 초대를 수락하면 학교가 그 사람에게 보낸 기존 공지를 읽을 수 있다. 게시 후 새로 만든 계정이나 새 보호자 관계에 이전 비공개 공지를 자동 부여하지 않는다.

관계 해제·전학·계정 중지는 기존 접근과 해당 로그인 세션을 회수한다. 회수 대기 상태는 즉시 회수 완료가 아니다. 외부 연결 복구와 외부 서버의 승인 응답 후 완료된다. 담당 학급을 잃으면 기존 상세 읽음 명단도 제한된다. 수신자는 다른 가족의 읽음 명단·집계에 접근할 수 없다.

Windows Defender는 운영 첨부 업로드의 필수 조건이다. 검사기 부재·시간 초과·감염은 업로드를 거절한다. 파일당 100MB, 공지 합계 200MB, 최대 10개이며 허용 확장자·서명을 검사한다. 게시된 첨부는 외부 게시 시점부터 30일 후 물리 삭제한다. 미게시 첨부는 24시간 후 삭제하며, 교내 발송 대기용 사본도 최대 30일 후 삭제한다. 만료된 파일을 재시도로 되살리지 않는다. 사용자가 직접 저장·공유한 사본은 원격으로 삭제할 수 없다.

외부 DB와 메타데이터 백업에도 개인정보가 포함된다. 전용 운영 계정·폴더 권한·BitLocker 또는 동등한 디스크 암호화·서버 업데이트가 필요하다. 일일 메타데이터 백업은 14일이며 첨부 내용은 백업하지 않는다. 기기 분실 시 계정을 중지하고 비밀번호를 재설정하는 운영 절차를 마련한다. 서버 코드만으로 실제 운영 환경의 무사고를 보장할 수 없다.

## 앱 설치·출시

`scripts/Build-Mobile.ps1`은 Windows의 한글 프로젝트 경로를 피하도록 소스만 전용 영문 경로에 복사해 Android를 빌드한다. 로컬 `.tools/android`, `.tools/java` 또는 명시한 SDK 경로를 사용한다. APK는 `artifacts/mobile`에 생성된다. Debug APK는 로컬 서명한 시운행용이다. 앱 식별자 `kr.school.yeoyang.messenger`는 임시 값이며 학교의 스토어 소유권 확인 후 확정해야 한다.

앱은 학교 소식과 교직원 교무실의 서버 주소·로그인을 구분한다. 자동 로그인은 비밀번호 대신 플랫폼 보안 저장소의 세션을 사용한다. 로그아웃은 서버 세션을 무효화하고 저장된 로그인을 지운다. 본문을 HTML로 실행하지 않고 별도 오프라인 본문 캐시를 만들지 않는다. Android 앱 화면은 캡처·최근 앱 화면 노출을 제한하고, 백그라운드 진입 때 화면을 가린 뒤 복귀 시 세션을 확인한다. 첨부의 저장·공유는 사용자가 요청할 때만 진행한다.

Release 앱은 HTTPS만 허용한다. Debug 앱만 Android 에뮬레이터 `10.0.2.2`, localhost, 127.0.0.1의 개발 HTTP를 허용한다. 실제 학교 주소에는 신뢰되는 인증서를 사용한다.

Android 실제 출시에는 학교의 Google Play 개발자 계정, 지속 사용할 서명 키와 백업, 버전 코드 관리, Release AAB와 실제 휴대폰 검증이 필요하다. iPhone 소스는 같은 MAUI 화면을 사용하지만 **Mac·Xcode·Apple 개발자 계정에서 빌드·서명·기기 검증해야 한다. Windows에서 iOS 배포 파일을 검증했다고 간주하지 않는다.** 설치·서명 계정은 이 작업에 제공되지 않았다.

앱은 현재 사용자가 열거나 새로고침할 때 소식을 조회한다. FCM/APNs 백그라운드 푸시는 아직 구현하지 않았다. 푸시 자격 증명, 동의·철회, 잠금 화면에 본문을 표시하지 않는 설정, 실제 기기 검증을 다음 출시 준비에 포함한다. GitHub 릴리즈는 PC·서버 배포 경로이며 Play/App Store 업데이트를 대신하지 않는다.

## 구현 후 반영한 개선과 다음 작업

실제 운영에서 필요한 부분을 검토해 연결 장애 대기열·재확인 상태·멱등 발송, 관계 재연결에 따른 과거 대기 공지 차단, 담당 학급 변경 후 읽음 명단 제한, 수신자 집계 비공개, 미확인·자녀 필터, 로그아웃·백그라운드 화면 정리, 웹의 키보드 조작 가능한 확인 창을 반영했다. 대용량 파일 전송과 교직원 권한 확인을 별도 실행해 파일 업로드가 로그인 확인을 지연시키지 않게 했다. 명부 조회도 사용자별 반복 쿼리 대신 네 번의 일괄 조회로 줄였다. 두 서버를 같은 DB 폴더에 잘못 설치하면 시작을 거절한다.

다음 작업은 실제 도메인과 인증서·서버 계정 준비, 소수 학급 시범 운영, 실제 Android/iPhone의 첨부·접근성·절전 상태 검증, 초대 전달 및 분실 계정 복구 절차, FCM/APNs 푸시, 스토어 개인정보 안내·보관 정책 확정, 서명·심사·공개 순서다. 데이터베이스 복구와 연결 키 교체 훈련도 시범 운영 전에 수행한다. 자동 업데이트 프로그램은 아직 없으며 PC는 GitHub 릴리즈 ZIP을 수동 교체한다.

[Microsoft MAUI 설치 안내](https://learn.microsoft.com/en-us/dotnet/maui/get-started/installation?view=net-maui-10.0&tabs=visual-studio-code), [보안 저장소](https://learn.microsoft.com/en-us/dotnet/maui/platform-integration/storage/secure-storage?view=net-maui-10.0), [Android 배포](https://learn.microsoft.com/en-us/dotnet/maui/android/deployment/), [한글 경로의 APT2265 오류](https://learn.microsoft.com/en-us/dotnet/android/messages/apt2265)를 기준으로 도구·배포 조건을 확인했다.

학교 Wi-Fi에서 많은 교사가 동시에 로그인할 때 같은 IP에 묶여 차단되는 것을 줄이도록 교직원 로그인 제한 기본값을 분당 120회로 조정했다. 계정별 5회 실패·15분 잠금은 유지한다. School__LoginLimitPerMinute로 분당 20~300회 범위에서 조정할 수 있다.

휴대폰 자동 로그인을 선택하면 다음 앱 실행 시 보안 저장소의 세션으로 접속한다. 첨부 공유용 임시 사본은 Android의 공유 대상이 파일을 읽을 수 있도록 즉시 지우지 않고 앱 캐시에 최대 24시간 유지한다. 앱을 다시 실행할 때 오래된 공유 사본을 정리한다. 본문 목록을 오프라인 저장하는 기능은 없다.

공지 제목·내용·학급을 빠뜨리면 발송 전에 수정할 수 있게 했다. 첨부 선택 창에서 돌아올 때는 세션을 다시 검증하면서 작성 중인 공지를 유지한다. 파일 업로드와 발송을 동시에 실행하지 않으며, 로그인 확인·조회가 끝나기 전에는 목록 버튼을 비활성화한다.

## 시운행 결과

2026-10-08 가상 교직원·학생·보호자 계정으로 Windows 독립 실행 배포본 54개, 외부 공지 서버 16개, 발신 연결·장애 복구 7개, 데이터 경로 혼용 거절 2개, Android 에뮬레이터 실제 실행 12개를 통과했다. 합계 91개다. Android에는 설치·자동 로그인·로그아웃·교직원 메시지, 교사 입력 수정·실제 파일 선택·첨부 업로드·공지 작성·읽음 현황·회수 검사를 포함한다. 외부 관리자 웹과 교직원 웹의 제출 요청 종료 취소·확정도 시운행했다.

실제 Windows 키보드 입력 검사는 앞에 열린 Windows 파일 선택 창이 검사 창의 포커스를 막아 별도 보류했다. 해당 입력을 다른 창에 보내지 않았으며, 직접 연결의 화면·입력 패킷·권한 회수 검사와 WPF 화면 검사는 통과했다. 실제 두 교직원 PC 사이의 학교 망 검사, Android 실기기·iPhone, 실제 외부 도메인 접속과 스토어 심사는 별도 운영 준비다.

현재 재현 명령은 `scripts/Build.ps1 -HeadlessTests -Version 1.0.0`, `node tests/smoke.mjs --ui --package`, `scripts/Build-Mobile.ps1`, `node tests/portal-preview.mjs` 후 전용 에뮬레이터에서 `node tests/mobile-ui.mjs`다. 이전 시험판 버전의 검사 기록은 당시 결과를 보존한다. 실제 입력을 제외하려면 명시적으로 `--skip-native-input`을 사용한다. 결과 JSON은 로컬 `artifacts`에 기록하며 운영 데이터·초대 코드·연결 키·서명 개인키와 함께 Git에 올리지 않는다.
