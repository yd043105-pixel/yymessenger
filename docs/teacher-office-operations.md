# 교직원 계정·학사일정·특별실·분반 운영

2026-10-13 구현 기준. 버전은 1.0.0이며 배포·스토어 등록을 수행했다는 의미는 아니다. PC는 WPF, Android/iOS는 MAUI 설치 앱이다. 서버의 HTTP API를 사용하더라도 사용자 화면을 브라우저 웹앱으로 제공하는 구성이 아니다.

## 계획 검토 후 반영한 변경

- 교사 로그인 이름과 좌석 IP를 분리했다. 이름은 한글을 지원하고, 동명이인은 `김교사.수학`, `김교사.영어`처럼 로그인 이름을 구분한다. IP는 자리 관리 정보이며 계정 인증에 사용하지 않는다. 자리를 바꾸어도 교사 ID와 메시지·시간표는 유지된다.
- 공통 임시 비밀번호 외에 개인별 20자리 활성화 번호를 발급한다. 처음 사용하는 교사에게 두 값을 안내하되 활성화 번호는 개별 전달한다. 공통 비밀번호만으로 다른 교사의 계정을 활성화할 수 없도록 했다.
- 초기 로그인은 15분 동안의 비영구 세션이다. 약관·활성화·로그아웃 이외의 업무 API와 메시지/원격지원 연결을 차단한다. 개인 비밀번호 설정 후 기존 세션을 무효화하고 다시 로그인하게 한다.
- 학사일정과 특별실 예약은 교직원 전용으로 먼저 구현했다. 가족용 서버에 자동 복제하지 않는다. 가족에게 공유할 학교 일정은 기존 공지 기능으로 별도 발송한다. 일정의 외부 달력 게시 기능은 후속 범위다.
- 특별실 운영 담당자는 이번 버전에서 학교 전체 특별실을 관리한다. 일반 교사는 자기 예약만 변경·취소한다. 특별실별 개별 관리자 배정과 운영 시간표는 후속 범위다.
- 분반 공지는 실제 등록한 수강생을 기준으로 한다. 학생 목록이 없는 분반은 준비 상태로 저장할 수 있지만 발송할 수 없다. 명부에서 제외된 학생을 재등록해도 과거 비공개 공지 접근이 자동으로 살아나지 않는다.

## 교사 PC

교직원 서버에 관리자 계정으로 로그인하고 **설정 → 교직원 · 서버 관리**를 연다. 기존 브라우저 관리 화면 대신 네이티브 관리 창이 열린다.

1. **교직원 계정 · 운영 권한**에서 로그인 이름, 이름, 부서, 좌석 IPv4와 공통 임시 비밀번호(12~128자)를 입력하여 등록한다. 이미 연결된 로그인 이름/IP는 중복 등록되지 않는다. 활성화 번호는 등록 응답에서만 표시되므로 본인에게 전달한다. 유효 기간은 7일이다. 비밀번호와 활성화 번호는 로그에 기록하지 않는다.
2. 교사는 첫 로그인에서 번호, 새 개인 비밀번호, 비밀번호 확인, 학교 약관을 확인한다. 새 비밀번호는 임시 비밀번호와 달라야 한다. 운영 약관이 학교 승인 전이면 활성화가 차단된다. 개발용 가상 환경에만 초안을 허용한다.
3. 초기 설정 후 다시 로그인하면 자동 로그인 설정을 사용할 수 있다. PC 자동 실행은 기존 Windows 로그인 시 실행 설정을 유지한다. 초기 세션은 자동 로그인으로 저장하지 않는다.
4. **계정 상태 · 좌석 · 초기화**에서 이름/부서/사용 상태/관리자/전체 공지 권한을 관리한다. 좌석 변경은 업무 기록을 이동시키지 않는다. 사용 중지와 계정 변경은 기존 세션을 회수한다. 초기화는 새 임시 비밀번호와 새 번호를 발급하고 모든 기기의 세션을 회수한다. 관리자 계정은 일반 교사 초기화 대상에 포함하지 않는다.
5. 업무 화면의 **일정·예약**에서 학사력·행사·일정과 특별실 예약을 조회한다. 관리자 화면에서 학사일정 담당·특별실 운영 담당 권한을 부여한다. 역할별 권한은 서버가 매 요청에서 확인한다.

기존 일반 교직원 계정은 자동 초기화하거나 새 ID로 교체하지 않는다. 이번 사전 등록 화면은 신규 계정용이다. 기존 계정을 사전 등록 방식으로 대량 전환하는 도구는 아직 제공하지 않는다.

## 학사력·학교 일정

교사는 월별 일정을 조회한다. 학사일정 담당자 또는 시스템 관리자가 제목, 설명, 시작/종료를 등록·변경·취소한다. 입력과 표시의 학교 시간은 한국 시간이다. API는 오프셋이 포함된 시각만 허용한다. 종일 일정은 한국 시간 자정부터 마지막 날의 다음 날 자정까지 지정한다.

수정 버전이 달라지면 덮어쓰지 않고 재조회하도록 안내한다. 삭제 대신 취소 상태를 보관하고 처리자와 시각을 감사 기록에 남긴다. 파일 첨부·개인별 일정·외부 공개 달력·반복 일정은 이번 일정 기능에 포함하지 않는다.

## 특별실 예약

특별실 운영 담당자 또는 관리자가 특별실 이름과 위치를 등록한다. PC에서는 신규 예약 허용/중지를 변경할 수 있다. 기존 예약은 특별실을 중지하더라도 유지되며 담당자가 별도로 취소할 수 있다.

교사는 날짜와 시작/종료 시각, 특별실, 예약 제목을 입력한다. 예약은 미래 시각이며 한 건의 기간은 최대 7일이다. 교시 번호와 종 시각의 자동 변환은 제공하지 않으므로 학교 수업 시각에 맞춰 입력한다. 같은 특별실의 시간이 일부라도 겹치면 거절한다. 앞 예약 종료와 다음 예약 시작이 같으면 허용한다.

쓰기 잠금을 확보한 SQLite 트랜잭션 안에서 중복 검사와 저장을 처리하므로 동시 요청도 한 건만 성공한다. 변경 시에도 같은 규칙을 적용한다. 요청 번호로 동일 전송 재시도의 중복 생성을 막고 수정 버전으로 다른 사용자의 변경 덮어쓰기를 막는다. 자기 예약 또는 운영 담당 권한으로 취소하며, 취소 이후에는 해당 시간에 새 예약이 가능하다.

## 분반 공지와 명부

PC 관리에서 **분반 · 수강 명부 관리**를 연다. 외부 학교 소식 서버와 교사 계정의 연결이 먼저 필요하다. 학년도·학기, 분반 이름, 담당 교사, 승인된 학생을 선택해 저장한다. PC에 표시한 학생 ID 목록을 한 줄씩 또는 `studentId` 한 열 CSV로 준비하여 수강 명부를 가져올 수 있다. 이름만으로 수강 학생을 추측하지 않으며, 중복/미등록 ID는 거절한다. 학교가 나중에 제공할 원본 엑셀의 학생 식별 정보가 확정되면 가져오기 변환을 연결한다.

PC **학교 공지**와 교사용 앱의 공지 작성에서 담당 분반을 선택한다. 분반과 학급/전체 발송은 함께 선택하지 않는다. 학생·보호자 중 누구에게 보낼지 지정하고 대상 학생의 담임도 함께 수신한다. 분반에 여러 학급 학생이 있으면 해당하는 담임을 산정한다. 담임 연결은 기존 시간표의 학급·담임 연결을 사용한다.

목록·상세·첨부 모두 수신 권한을 검사한다. 명부에서 빠진 학생과 그 학생을 통해 수신한 보호자/담임의 접근은 회수된다. 담당 교사는 현재 담당 분반의 학생에게 해당하는 읽음 현황을 조회한다. 학생/보호자에게 다른 수신자의 이름·읽음 통계를 제공하지 않는다. 이미 휴대폰에 저장·공유한 사본까지 회수할 수는 없다.

## 학생·학부모 관리

PC 관리의 **학생·학부모 가입 · 학교 명부 관리**에서 외부 학교 소식 서버의 별도 관리자 계정으로 로그인한다. 이 창은 네이티브 화면이며 해당 계정의 비밀번호를 저장하지 않는다. 교내 관리자 로그인만으로 외부 서버 관리자 권한을 자동 부여하지 않는다.

학급/명부 계정 등록, 학생 신청 정보 확인 후 학교 승인, 계정 중지, 교사-교내 계정 연결, 초대 코드, 학생 고유번호 확인/재발급, 보호자 관계 해제를 처리할 수 있다. 가족 앱에서 가입하는 학생·학부모 절차는 기존 합의를 유지한다. 학교 승인 전 학생은 로그인할 수 없고, 학부모 임시회원은 자기 설정에서 자녀 번호를 입력해야 정회원이 된다. 다자녀를 연결할 수 있다.

## 교사용·가족용 설치 앱

공통 소스로 두 설치 앱을 빌드한다. 교사 앱은 `kr.school.yeoyang.teacher`, 가족 앱은 `kr.school.yeoyang.family`다. 별도 설치·프로세스·보안 저장소를 사용한다. 교사 앱은 교무실 서버와 교직원 계정을, 가족 앱은 학교 소식 서버와 학생/학부모 계정을 사용한다. 앱 화면의 제한과 별도로 서버의 계정/자료 권한 검사를 유지한다.

Android 예:

```powershell
./scripts/Build-Mobile.ps1 -SchoolApp Teacher
./scripts/Build-Mobile.ps1 -SchoolApp Family
```

공통 개발 검증 앱은 `-SchoolApp Combined`로 명시한다. 기본 Release 빌드는 가족 앱이며 실제 두 앱의 배포용 빌드에서는 종류를 명시한다. 버전은 모두 1.0.0, 내부 앱 버전은 2다. 학교 외부에서 교무실 메시지를 확인하려면 기존 학교 VPN이 필요하다. 가족 공지는 외부 학교 소식 서버를 사용한다.

iOS는 macOS/Xcode에서 `YY_SCHOOL_APP=Teacher` 또는 `Family`를 지정하여 `bash scripts/Build-iOS.sh simulator`/`archive`를 실행한다. 실제 기기/스토어용은 각 앱 ID에 맞는 Apple 서명 프로필이 필요하다. Windows에서 iOS 기기 빌드·서명·설치가 완료되었다고 간주하지 않는다.

공유 첨부 캐시는 접속 공간·서버·계정별로 나누고 로그아웃, 계정 전환, 인증 회수 때 정리한다. 시작 시 하루 지난 임시 공유 파일도 정리한다. OS 공유 대상이 만든 사본은 관리 범위 밖이다.

## 보안·검증과 남은 운영 작업

교직원 계정·활성화·좌석·권한·일정·예약 변경은 감사 기록으로 조회한다. 최초 승인 약관과 재활성화 확인을 별도로 보존한다. 운영 서버의 방화벽·TLS 인증서·망/VPN·DB와 암호화 키 접근 권한·백업 복구는 학교 환경에서 별도로 확인해야 한다.

`tests/office.mjs`는 기존 smoke 검사에 포함되어 초기 세션의 접근 차단, 약관/번호/비밀번호 검증, 잠금, 세션 회수, 권한 변경, 시간대·수정 충돌, 부분 시간 겹침·동시 예약, 좌석 변경과 재초기화를 검사한다. `tests/sections.mjs`는 공지 검사에 포함되어 담당 분반, 수강 명부, 담임 수신, 제외자 차단, 수강 철회/재등록, 읽음 명부 보호를 검사한다. 데이터는 가상 계정과 명부만 사용한다.

앱이 완전히 종료된 상태의 OS 푸시는 아직 구현되지 않았다. FCM/APNs 서버 설정, 각 앱의 기기 토큰 등록·회수, 네이티브 수신 처리와 실제 기기 검사가 필요하다. 현재 일정·공지 변경은 앱 화면을 열어 조회/새로고침할 때 반영된다. 급식 NEIS 연동, 기존 계정 대량 전환, 실제 수강 엑셀 자동 매칭, 운영 서버 보안 검증도 후속 작업이다. 이번 변경을 학교 운영 승인이나 스토어 배포 완료로 표시하지 않는다.
