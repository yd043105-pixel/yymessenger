# 서버·단말 실행 및 배포 절차

버전 1.0.0 유지. 이번 작업은 개발 반영이며 실제 공개 배포·릴리즈·스토어 제출·운영 서버 교체를 수행하지 않는다.

## 서버 컴퓨터

교내 SchoolMessenger.Server와 학교 소식 AnnouncementServer는 별도 서비스 계정·데이터/첨부·백업·키 경로를 사용한다. 공개 서버는 승인된 외부 접속 환경에서 HTTPS로 제공한다. 실제 분리 방법은 앞서 승인한 두 서버 구성을 따른다. SQLite 데이터는 서버의 로컬 디스크를 쓴다. 서버는 로그인·메시지 DB·첨부 정리·전달 큐를 상시 실행한다.

School:AdminPassword / Portal:AdminPassword, DataDirectory, 각 BackupDirectory, 인증서·AllowedHosts·학교 AllowedNetworks·연결 주소/키를 운영 비밀 저장 방식으로 지정한다. 비밀 설정을 GitHub나 설치 패키지에 포함하지 않는다. 기존 Start-Server.ps1 / Start-AnnouncementServer.ps1의 운영 설정을 점검한다.

연결 업그레이드 때 두 서비스를 잠시 정지하고 먼저 현재 DB·키·설정을 백업한다. **두 서버 코드가 같은 서명 프로토콜이어야 한다.** 업무 서버의 Announcements:BridgeKey, BridgeKeyId(primary 기본), BridgeServiceId(office 기본)와 공개 서버의 Portal:BridgeKey 또는 BridgeKeys:<ID>, BridgeServiceId를 맞춘다. 키 교체 시 새 ID를 공개 서버에 추가 → 업무 서버에 새 키/ID 적용 → 전달 확인 → 옛 키 제거 순서다. 키는 최소 32자이고 충분한 임의성을 가져야 한다.

서비스 시작 시 이관 전 DB 스냅샷·중복 폴더 잠금·새 스키마가 적용된다. 관리자 상태, 백업 성공, 합성 테스트 계정의 발송/공지/시간표/로그아웃을 확인한다. 약관 미확정 상태에서는 운영 신규 가입·최초 활성화를 열지 않는다. 보호자 연결 기본은 학교 확인 대기다.

정지 상태 복원 예시(운영 데이터에 이번 작업 중 실행하지 않음):

```powershell
# 서비스가 정지되어 있고 파일 경로/서버 종류를 확인한 뒤 로컬 관리자가 실행
$env:School__DataDirectory = 'D:\SchoolData\office'
& 'C:\SchoolMessenger\server\SchoolMessenger.Server.exe' --backend-restore 'E:\ApprovedBackup\school-YYYYMMDD.db'
# 공개 서버는 Portal__DataDirectory와 SchoolMessenger.AnnouncementServer.exe를 사용
```

복원 도구는 API를 열지 않고 종료한다. 실행 성공 후 학교 명부·권한·관계 변경을 대조하고 서버를 시작한다. 이전 명부의 승인이 그대로 올바르다고 단정하지 않는다.

## 사용자 컴퓨터

PC 메신저 설치 파일로 설치한 WPF 프로그램을 실행한다. 교내 서버 HTTPS 주소를 설정하고 본인 계정으로 활성화/로그인한다. 자동 실행·자동 로그인은 기존 설정을 따른다. 학생·보호자 가입/연결 심사는 PC 학교 소식 관리에서 별도 공개 서버 관리자 계정으로 처리한다. 두 서버 관리자 비밀번호를 공유하지 않는다. sid가 없던 이전 로그인은 서버 교체 후 다시 로그인한다.

## 교사용 학교 앱

교사용 Android/iOS 앱을 설치한다. 교내 업무 기능에는 교내망 또는 학교 승인 VPN이 필요하다. 외부 학교 공지는 공개 서버 주소·학교 승인 교직원 계정으로 연결한다. 자기 시간표·메신저·담당 공지·업무 일정/예약의 기존 권한을 따른다. 학교 밖에서 업무 API를 임의로 공개하지 않는다.

## 학생·학부모용 학교 앱

별도 학교 앱을 설치하고 승인된 학교 공개 서버로 로그인한다. 학생은 학교 명부·승인 절차, 학부모는 임시 계정 → 자녀 번호 신청 → 학교 확인을 따른다. 개발 환경의 즉시 연결과 운영 절차는 구분한다. 여러 자녀는 각각 연결한다. 현재 앱 열기/새로고침 조회는 가능하며 절전/종료 상태의 백그라운드 푸시는 미구현이다.

## 출시 전 정지 조건

학교 약관/개인정보·보호자 확인·보관/폐기 정책, 실제 HTTPS/ACL/VPN/AV, 별도 디스크 복구, 푸시·실기기, 스토어 서명·심사, 관리자 화면 의존성 대조가 완료될 때까지 제한된 개발/합성 검증 단계로 본다. 확인하지 못한 항목 때문에 DB·호스팅을 자동 교체하지 않는다.

복원 시 BackendRecoveryState의 검토 대기를 설정한다. 일반 계정의 업무/학교 소식 이용과 서버 간 전달은 503으로 대기한다. 관리자는 기존 권한 범위에서 명부·관계·권한을 확인할 수 있으며 PC 운영 관리/학교 소식 관리에서 “복원 검토 완료 · 일반 이용 재개”로 명시적으로 확인한다. 교내 확인은 최고관리자만 할 수 있다. 복원된 학생 번호와 미심사 신청도 폐기해 재발급/재신청한다. 이 확인은 학교의 실제 기록 대조를 대신하지 않는다.
