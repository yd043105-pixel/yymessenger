# 보안 결과와 잔여 위험

이번 점검은 저장소 코드 및 로컬 합성 사례에 대한 개발 점검이다. 지시서 전체가 완료되었다거나 운영 보안이 철저히 보장되었다고 주장하지 않는다.

| 발견 위험 | 등급 | 반영 | 잔여 조건 |
| --- | --- | --- | --- |
| 고정 연결 키만으로 요청 재전송 | High | 본문 서명·서비스/키 ID·시간·영속 난수 중복 차단 | 실제 키 저장·교체·시계 확인 |
| 메시지 저장 후 휘발성 알림 | High | 동일 트랜잭션 영속 큐·재시도·안정된 커서 | 앱 전면 커서 전환·푸시 없음 |
| 로그인 기기별 폐기 불가 | High | 해시 기반 기기 세션·폐기·실시간 검증 | 모든 네이티브 기기 관리 화면은 미완료 |
| 백업이 권한·쿠키를 되살림 | High | 정지 복원·세션/초대/증명 폐기·검증 | 백업 이후 탈퇴/관계 변경을 운영 명부와 대조해야 함 |
| 번호만으로 보호자 본인확인 | High | 운영 기본 신청/학교 확인, 즉시 전환은 별도 승인 설정 | 실제 신원 확인 절차·담당자·학운위 검토 |
| 발송 시점부터 첨부 보관 계산 | Medium | 새 파일 업로드 완료부터 계산, 재사용 시 연장 금지 | 기존 파일 검사·단말 사본·백업 폐기 |
| 새 파일 무결성 기록 없음 | High | SHA256·상태·다운로드/수합/연결 검사 | 구파일 검사 기록 없음·AV 실환경 |
| 중복 프로세스·미검증 백업 | Medium | 데이터 폴더 잠금·이관 전 백업·무결성 검증 | 별도 디스크·운영 계정 ACL |
| 학교 전체 IP가 요청 한도 공유 | Medium | 인증 이후 계정별 제한, 로그인 IP 제한 유지 | 실제 최대 동시 규모·DoS 시험 |
| 관리자 상호 승격·최고계정 수정 | High | 교내 최고관리자 ID 구분과 승격/관리자 변경 제한 | 모든 관리자 기능 등급 세분화는 남음 |
| 감사 내용 위변조·유출 | Medium | 최소 정보 구조화 기록·앱 DB 수정/삭제 금지 | OS 관리자·외부 보관·보관정책·감사 실패 경보 |

확인하지 못한 항목: 실제 HTTPS/VPN/방화벽, 서버 OS 업데이트·ACL·BitLocker, AV 실검사, 개인 단말 캐시, 푸시 자격증명/실기기, NEIS API 실운영 값, 전체 정전·용량 부족·별도 디스크 복구, 개인정보 법률 검토. 미확인을 이유로 호스팅·DB·앱 구조를 바꾸지 않았다.

실제 서버가 보고한 SQLite 3.53.3은 공식 WAL-reset 수정 기준 이후다. 다른 실행 환경은 다시 확인해야 한다. [SQLite의 WAL 설명·수정 버전](https://www.sqlite.org/wal.html).

신규 진행 과제: 전체 작업 지속 상태, 안전한 기존 파일 이관, 감사 외부 보관·실패 경보, 모든 관리자 화면 의존성 대조, 사용자별 내 기기 관리 화면, FCM/APNs 최소 payload·토큰 폐기·실기기 시험, 정책에 따른 계정/명부/백업 삭제·익명화, 학생 개인 수강 데이터, 공개 범위별 학사력, 크기/예약 정책 설정. 외부 AI에 메시지/학생 데이터를 보내는 추출 기능은 추가하지 않았다.

복원 시 BackendRecoveryState의 검토 대기를 설정한다. 일반 계정의 업무/학교 소식 이용과 서버 간 전달은 503으로 대기한다. 관리자는 기존 권한 범위에서 명부·관계·권한을 확인할 수 있으며 PC 운영 관리/학교 소식 관리에서 “복원 검토 완료 · 일반 이용 재개”로 명시적으로 확인한다. 교내 확인은 최고관리자만 할 수 있다. 복원된 학생 번호와 미심사 신청도 폐기해 재발급/재신청한다. 이 확인은 학교의 실제 기록 대조를 대신하지 않는다.
