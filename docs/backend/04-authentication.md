# 인증·세션·보호자 확인

교사는 학교가 등록한 안정된 내부 ID를 사용한다. 좌석 이동·IP 변경이 ID를 바꾸지 않는다. 공통 임시 비밀번호로 업무를 계속하는 대신 개별 활성화 증명과 개인 비밀번호 설정을 거친다. 학교 약관이 미확정이면 운영 신규 가입·최초 활성화를 열지 않는 기존 정책을 유지한다.

PBKDF2-HMAC-SHA512 최소 220000 반복과 기존 재해시를 유지한다. 계정 실패·15분 잠금은 DB에 남는다. 로그인 IP 제한, 로그인 후 사용자별 사용 제한을 적용한다. 같은 학교 NAT IP의 정상 이용자가 서로의 일반 사용 한도를 소진하지 않도록 인증 후 사용 제한을 판정한다.

쿠키는 HttpOnly·SameSite Strict이며 외부 접속은 HTTPS를 요구한다. 로그인마다 256비트 임의 세션 토큰을 만들고 DB에는 SHA256 해시만 저장한다. 쿠키의 sid·계정 버전·활성·만료를 매 요청 확인한다. 기본 8시간, 기억하기는 30일, 최초 활성화 로그인은 15분이며 기억하기를 허용하지 않는다. 기존 PC/앱 OS 보안 저장 방식과 쿠키 전달 계약은 유지한다.

API의 POST·PUT·PATCH·DELETE는 세션에서 받은 `X-CSRF-TOKEN` 헤더를 필수로 검증한다. 누락·중복·빈 헤더는 본문을 읽기 전에 거부하며, 토큰을 찾기 위한 폼 파싱 fallback은 사용하지 않는다. 파일 작업 한도는 실제 매핑된 엔드포인트에만 적용하고 공개 공지 업로드는 교사 권한을 앞단에서 검사한다.

`GET /api/sessions`와 `DELETE /api/sessions/{id}`는 자신의 기기 로그인만 조회·폐기한다. 타 사용자 세션 ID로 해제할 수 없다. 기존 로그아웃·암호/권한 변경은 계정 전체 세션 버전을 폐기한다. 구버전 sid 없는 로그인은 이번 서버 교체 후 재로그인이 필요하다. 교내 메시지·원격 연결은 세션 상태를 검사하고 폐기 시 종료된다.

학생 번호는 기존 암호학적 난수로 대문자·소문자·숫자 포함 8자리이며 이전 번호 해시도 보존해 재사용을 방지한다. 이를 보호자의 본인확인 증명으로 단정하지 않는다.

| 환경·설정 | 자녀 연결 |
| --- | --- |
| Development | 기존 번호 일치 시 즉시 연결 유지 |
| Production 기본 / Portal:GuardianBindingMode=SchoolReview | 유효 번호로 신청 → 열람 권한 없음 → 학교 확인 후 승인 |
| Production CodeOnly | Portal:GuardianCodeOnlyApproved=true까지 있어야 즉시 연결 |

승인 요청은 7일 이내·현재 유효 번호·활성 학생/보호자를 다시 검사한다. 번호 재발급 뒤 이전 신청을 승인할 수 없다. 승인 담당자·시각을 기록한다. PC 학교 소식 관리에서 심사하며 학교가 실제 보호자 확인 방법을 확정해야 한다. 승인 플래그는 법률 검토를 대신하지 않는다. 자녀가 여럿이면 각각 신청·연결한다.

[ASP.NET Core 쿠키 검증](https://learn.microsoft.com/en-us/aspnet/core/security/authentication/cookie?view=aspnetcore-10.0).

쿠키 Secure는 실제 HTTPS 요청에서 설정된다. 합성 검사의 loopback HTTP 예외는 기존 동작을 유지한다. 실제 외부 요청은 HTTPS를 요구하며, TLS를 종료하는 프록시를 사용한다면 실제 전달 헤더·호스트·쿠키 정책을 별도 확인해야 한다. 확인 없이 프록시를 신뢰하도록 구성하지 않았다.

교내·학교 소식 로그인 IP 한도는 기본 분당 120회이며 School/Portal:LoginLimitPerMinute로 20~300회 범위에서 조정한다. 학교 Wi-Fi 및 이동통신 공통 IP의 정상 동시 로그인을 고려하되 계정별 DB 잠금을 유지한다. 세션 목록은 현재 계정 버전에 유효한 로그인만 표시한다.
