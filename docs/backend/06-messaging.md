# 메시지·연결·알림

쪽지·수신자·채팅 연결·할 일·제출 요청·MessageEvents를 동일 SQLite 트랜잭션에 저장한다. 요청 키는 DB 고유 제약과 내용 Fingerprint로 중복 요청을 식별한다. 트랜잭션 안에서도 현재 발신자 활성·세션 버전을 확인한다. HTTP 성공은 DB 저장 성공이며 수신자 읽음을 뜻하지 않는다.

MessageDelivery는 영속 이벤트를 순번대로 읽어 SignalR 힌트를 전송한다. 실패 시 DB의 Attempts/NextAttempt를 갱신하고 최대 5분까지 지연한다. 중단·재시작 후 미처리 이벤트를 재시도한다. 전송 뒤 상태 기록 전에 종료되면 힌트가 중복될 수 있다. DeliveredAt은 기기로부터의 확인 응답이나 읽음이 아니다. 연결하지 않은 사용자도 DB에서 쪽지를 조회한다.

읽음 저장과 발신자 ReadChanged 이벤트도 같은 트랜잭션이며 수신자별 이벤트 키로 중복되지 않는다. `GET /api/messages/changes?after=<순번>`은 본인 이벤트 최대 200개와 cursor/hasMore를 반환한다. 정수 순번은 동일 시각·삭제·VACUUM에도 기존 timestamp/offset 방식보다 안정적으로 이어받는다. 이 API는 이번에 추가한 서버 계약이며 모든 PC/앱의 기존 조회를 새 커서로 전면 전환한 것은 아니다.

기존 ExternalOutbox 및 TimetableBatches.Delivered는 중복 신설하지 않고 유지한다. 공지 연결은 lost-ack 상황에서도 ClientId로 재조회한다. 서명은 `YY-BRIDGE-1 + 메서드 + 경로/질의 + UTC초 + 256비트난수 + 서비스ID + 키ID + 본문SHA256`의 HMAC-SHA256이다. 고정 Bearer 요청은 거부한다. 기본 서비스 office, 기본 키 ID primary. Portal:BridgeKeys:<ID>로 교체 기간의 키를 선택한다. 요청은 기본 ±120초(10~300초 범위)와 DB 난수 고유 제약을 검사한다.

서명용 본문은 제한된 임시 파일로 처리해 대형 첨부를 메모리에 여러 개 복제하지 않는다. 제한 110MiB, 실제 파일 제한 100MiB와 HTTP 제한을 함께 적용한다. 리다이렉트를 따라 키를 다른 서버에 보내지 않는다. TLS·현재 교사 증명·대상 검사를 서명으로 대체하지 않는다.

공개 앱 백그라운드 FCM/APNs 전송은 미구현이다. 원격지원은 기존 사용자 동의·수락한 연결 ID·핀·제어 권한·짧은 유효시간을 유지한다. 서버로 화면/입력을 중계하지 않는다.

키별 유효 기간은 Portal:BridgeKeyValidity:<ID>:NotBefore / NotAfter의 UTC Unix 초로 설정할 수 있다. 지정한 기간 밖의 키는 서명이 맞아도 거절한다. 기존 연결 호환을 위해 미지정 키는 무기한이며 운영 정책에서 기간·교체 책임자를 정해야 한다. 이름 있는 키만으로 시작할 수 있어 옛 primary 키를 제거할 수 있다. 전체 서비스 간 추적 ID 전파는 아직 미완료이며 현재 감사 추적 ID는 서버 요청별이다.

새 이벤트 커서는 이관 전 쪽지의 전체 목록을 생성하지 않는다. 클라이언트가 새 커서 방식을 채택할 때는 기존 보관함으로 최초 전체 조회를 하고 이후 이벤트로 변경을 이어받아야 한다.

자동 미제출 알림 쪽지도 동일 트랜잭션에 MessageEvents를 함께 저장한다. 기존 날짜별 알림 중복 제약은 유지한다. 제출 상태 변경의 별도 SubmissionChanged 힌트는 기존 조회 방식이며 모든 업무 이벤트가 이번 큐에 통합된 것은 아니다.

본인을 수신자로 넣지 않은 발신자에게도 SentMessage 변경 기록을 남겨 다른 기기에서 보낸 쪽지를 새 커서로 확인할 수 있다. 기존 클라이언트의 NewMessage 수신 동작은 유지한다.
