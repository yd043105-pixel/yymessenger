# 첨부 파일

기본 파일 100MiB, 메시지·제출 합계 200MiB, 미전송 총량 500MiB, 쪽지 첨부 10개를 유지한다. UUID 물리 이름·안전한 표시 이름·확장자/내용 서명·남은 디스크 검사·업로드 동시 제한을 유지한다. 크기·개수의 모든 사용자 설정화는 미완료다.

새 업무/공개 공지 업로드는 FileVerification에 uploading → scanning → ready 또는 rejected 상태를 기록한다. 검사·메타데이터·ready의 성공 기록 이후에만 파일을 사용한다. 업무/공개 파일 SHA256을 저장하고 다운로드와 수합 ZIP에서 확인한다. 외부 공지의 교내 임시 파일도 ready+해시를 저장하고 외부 업로드 전에 확인한다. 외부 임시 파일의 중간 uploading/scanning 상태는 아직 전면 추적하지 않는다.

Production에서는 검사기가 없거나 실패하면 업로드를 허용하지 않는다. Development의 AV 생략을 운영 검사 통과라고 표시하지 않는다. 기존 파일의 검사 기록을 이번에 만들어내지 않았다. 기존 메타데이터·권한·만료 정책을 유지하므로 운영 전 기존 파일 전수 검사와 안전한 해시 이관이 필요하다.

새 업무·공개·외부 공지 파일의 만료는 **업로드 완료 시점의 UTC + 30일**이다. 발송/제출/복제 확인 시 기존 만료를 늘리지 않고 더 이른 만료를 선택한다. 기존 만료는 연장하지 않는다. 기존 미전송 고아 24시간 정리 규칙도 유지한다. 개발 테스트만 짧은 보관 시간을 사용한다.

매 다운로드에서 로그인·현재 열람 권한·회수·삭제·만료·파일 존재를 판정한다. 검사 기록이 있는 새 파일은 ready+SHA256도 검사한다. 저장 기간 종료는 접근 차단 뒤 물리 정리가 수행되며 일부 삭제 실패는 다른 파일 정리를 계속하고 작업 실패를 기록해 재시도한다.

복원 후 없는 파일은 삭제 상태로 표시하고 만료 파일 접근은 차단한다. 만료 원본 파일의 물리 삭제는 서버 시작 정리가 처리한다. DB 백업에는 원본 첨부가 없다. 복원·별도 백업으로 파일을 붙여 넣는 경우도 만료를 연장할 수 없다. 단말이 이미 저장·공유한 사본을 서버 회수로 삭제할 수 있다는 보장은 하지 않는다.

교내 외부 공지 첨부의 원본 만료 시각을 서명된 연결의 expiresAt 질의값으로 전달한다. 공개 서버는 자체 최대 보관 기한과 이 원본 기한 중 더 이른 시각을 저장한다. 재시도·지연 복사·중복 업로드도 기존 기한을 늘릴 수 없다.
