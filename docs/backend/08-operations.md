# 운영·작업 상태

학교 서비스 계정, 분리된 데이터/첨부/키/백업 디렉터리, HTTPS, 교내 접근 네트워크, 올바른 도메인을 먼저 준비한다. 현장 설정을 자동 변경하지 않는다.

BackendJobs에 cleanup/backup 시작·성공/실패·시도 횟수·오류 종류를 저장한다. 성공 백업 시각은 재시작 후에도 유지된다. 검증한 임시 DB를 완료 파일로 교체하므로 실패한 백업을 정상 파일로 먼저 공개하지 않는다. `/api/admin/backend-status`는 관리자에게 작업 상태와 실제 SQLite 버전을 반환한다. `/health`는 최소 서비스 생존 상태이며 관리자 상세·키·DB 경로를 공개하지 않는다.

기존 교내 파일 정리는 시작 즉시 및 운영 시간당 수행한다. 공개 서버는 기존 60초 주기를 유지한다. 일부 물리 삭제 실패는 만료 메타데이터를 보존하고 다음 실행 때 재시도한다. 새 메시지 전송 큐는 0.5초 간격, 원격 계정 상태 확인은 기존 1초 간격이다. 실제 정지된 단말 P2P 종료 수신 시간은 네트워크 상황에 좌우된다.

모든 기존 NEIS·공지·시간표·리마인더 작업이 단일 BackendJobs/실패 큐로 통합된 것은 아니다. 기존 공지 큐·시간표 전달 플래그·날짜별 제출 알림 중복 제약을 유지하며 남은 작업 상태/모니터링 통합은 잔여 목록에 남긴다.

구조화된 요청 기록은 서비스·라우트 템플릿·추적 ID·상태 코드·시간만 사용한다. 변경 작업 감사에는 최소 내부 ID만 추가한다. 요청 본문·질의값·파일명·학생 번호·암호·쿠키·연결 키·원격 화면을 새 로그에 기록하지 않는다. 감사 저장 실패는 Critical 기록으로 드러내며 이를 완전한 감사 보장으로 표현하지 않는다. 외부 감사 보관 및 용량 감시가 필요하다.
