# 교직원 웹 화면과 메시지 기반 할 일

작성일: 2026-10-08. 사용자의 설계 승인 후 일반 개발 방식으로 구현한 교직원 기능의 범위를 기록한다. 기존 교내망 전용 운영과 작은 Windows 메신저를 유지한다. Superpowers는 brainstorming만 사용했다. 추가 모바일 앱·학생·학부모 외부 공지는 `docs/mobile-announcements-design.md`의 별도 검토안이다.

## 목적과 범위

교직원이 학교 안에서 브라우저로 자기 메시지와 업무를 확인하고, 받은 메시지에 들어 있는 요청을 할 일로 관리한다. Windows 앱과 웹이 같은 로그인 계정, 권한, SQLite 데이터, 첨부파일 만료 규칙을 사용한다. 새 외부 서버와 별도 계정을 만들지 않는다.

웹 주소는 기존 학교 HTTPS 서버의 `/office/`이다. 기존 관리자 화면 주소는 유지한다. 웹에서는 받은함·보낸함, 메시지 본문·첨부파일·읽음, 참여한 채팅 기록, 대상 설문과 자기 응답, 작성한 설문의 결과, 개인 할 일을 제공한다. 메시지 발송·채팅 발송·설문 작성·원격 지원은 현재 Windows 앱에서 사용한다. 웹의 첫 범위는 조회와 할 일 관리이다.

교내망 외부 접속은 열지 않는다. 개인 계정으로 로그인하며 관리자는 관리자라는 이유만으로 타인의 대화나 할 일을 조회할 수 없다. 실제 학교의 고정 주소, 신뢰할 수 있는 HTTPS 인증서와 교직원망 설정을 사용한다.

## 화면과 동기화

웹 화면은 승인된 남색·파란색 디자인을 이어간다. 받은함·보낸함·채팅·설문·할 일 메뉴, 목록과 상세 영역을 제공하고 작은 화면에서는 세로로 배치한다. 화면을 열거나 새로고침할 때 같은 서버 API에서 읽고, 켜 둔 화면은 주기적으로 변경 사항을 조회한다.

Windows 앱에는 ‘할 일’ 메뉴와 별도 창을 추가한다. 웹과 앱에서 추천 항목을 확인·수정하고, 진행·완료 상태를 바꾼다. 같은 할 일을 두 화면에서 동시에 수정하면 변경 번호를 확인하여 덮어쓰기 대신 새 내용을 불러오도록 안내한다. 로그아웃은 해당 계정의 다른 웹·앱 로그인도 만료시킨다.

## 할 일 추출

추천안은 **학교 서버 안에서 후보를 만들고, 교사가 확인·수정한 뒤 등록**하는 방식이다. 자동 등록 여부는 사용자 답변과 설계 승인 때 확정한다.

첫 버전은 명시적인 요청 문장과 날짜 표현을 읽는 규칙 방식이다. 제출·작성·회신·준비·신청·참석 요청과 기한을 찾아 제목, 원문 근거, 기한 후보, 발신자와 원본 메시지를 연결한다. 메시지 본문을 외부 AI 서비스로 보내지 않으며 학교 서버에 별도 AI 모델을 설치하지 않는다. 규칙으로 판단하기 어려운 문장에는 잘못된 기한을 만들어 넣지 않는다. 폭넓은 자연어 해석이 필요한 경우 학교 서버 사양과 메시지 처리 정책을 확인하여 다른 방식을 별도로 검토한다.

예: ‘10월 12일까지 생활기록부 점검표를 제출해 주세요.’를 받으면 ‘생활기록부 점검표 제출’, 기한 ‘2026-10-12’, 해당 원문을 함께 추천한다. 교사는 확인 후 저장하거나 기한·제목을 고치고, 필요 없는 항목은 제외한다.

‘내일’은 메시지를 보낸 한국 날짜를 기준으로 해석한다. 날짜만 있는 표현에는 메시지를 보낸 연도를 적용하고, 불명확하거나 여러 기한이 섞이면 기한을 미지정으로 표시하여 확인을 받는다. 이미 끝난 일이나 명시적인 취소 문장은 추천에서 제외한다. 규칙에 맞지 않는 요청이 누락될 수 있으므로 원문 확인과 직접 추가도 제공한다.

개인 쪽지와 참여한 채팅에서 **본인이 받은 내용**을 대상으로 한다. 새 메시지부터 자동 추출하며 기존 기록 전체를 한꺼번에 할 일로 만들지 않는다. 발신자가 보낸 일이라는 이유로 수신자의 개인 할 일 상태를 조회할 수 없게 한다. 메시지당 후보 개수와 본문 길이를 제한하고, 같은 수신자·원본·근거의 중복 후보를 만들지 않는다.

## 데이터와 처리

기존 메시지 저장과 권한 검사 흐름을 확장한다. 후보 생성이 메시지 전송을 지연시키거나 실패하게 하지 않도록 추출을 먼저 제한된 길이·개수로 수행하고, 저장된 메시지와 연결한다. 후보가 없는 메시지도 기존처럼 전송된다. 전송 요청 번호에 따른 기존 중복 방지와 같은 원본에 대한 후보 중복 방지를 함께 적용한다.

할 일 테이블은 소유자, 원본 메시지, 원문 근거, 제목, 한국 날짜로 된 선택 기한, 상태, 생성·수정 시각과 변경 번호를 저장한다. 상태는 추천·진행·완료·제외이다. 원본과 소유자 권한을 서버에서 다시 검사하고, 다른 사람의 항목 번호를 알아도 조회·수정할 수 없게 한다. 원본 메시지 삭제 정책을 추후 추가할 때 연결된 후보와 할 일도 같은 정책에 따라 처리한다.

본문과 할 일은 현재 서버 DB에 저장한다. 서버 운영자가 파일에 직접 접근하는 경우까지 막는 종단 간 암호화 시스템은 아니다. 서버·백업의 접근 권한과 디스크 암호화를 학교 운영 정책으로 적용해야 한다. 외부 서비스에 본문을 전송하는 기능은 이 설계에 없다.

## 안전한 웹 처리

기존 승인 계정, HTTPS, 세션 만료·회수, 교직원망 제한, CSRF를 재사용한다. 웹 세션과 본문을 브라우저 localStorage에 저장하지 않는다. 원문·이름·파일명은 HTML로 해석하지 않고 텍스트로 표시한다. API 응답은 캐시하지 않으며 로그아웃·로그인 만료 때 표시 중인 개인 데이터를 지운다. 서버가 매 요청마다 소유자와 원본 권한을 확인한다.

## 제출 요청과 파일 수합

사용자 요청은 파일 제출을 요구한 교사가 파일을 일괄로 받고, 수신자 중 미제출자를 확인하며, 마감 이틀 전부터 하루 한 번 자동으로 제출을 안내하는 것이다. 일반 문장의 할 일 후보 추출과 별도로, 발신자가 명시적으로 설정하는 제출 요청을 제공한다. 자유롭게 보낸 쪽지의 의미를 추측하여 제출 의무나 반복 알림을 생성하지 않는다.

첫 범위는 개인 쪽지 작성 화면의 ‘파일 제출 요청’ 선택이다. 여러 교사 또는 부서를 수신자로 선택하고 제목·안내·마감 날짜를 정하여 발송한다. 발송 시 실제 수신자 목록을 확정하여 이후 부서 변경이나 교직원 추가로 제출 대상이 바뀌지 않는다. 발신자를 자동으로 제출 대상에 넣지 않는다. 채팅 안에서 별도 제출 요청을 생성하는 기능은 첫 범위에 포함하지 않는다.

수신자는 Windows 앱과 웹의 메시지 상세 화면, ‘제출할 항목’에서 파일을 올린다. 개인 할 일 후보의 ‘등록’을 누르지 않아도 제출 요청은 표시된다. 할 일에는 해당 요청을 연결하고, 실제 파일 제출 상태가 제출 여부의 기준이 된다. 개인 할 일을 완료했다고 파일 제출 완료로 처리하지 않는다.

발신자의 ‘내가 요청한 제출’ 화면은 대상 인원, 제출·미제출·지각 제출 수, 교사별 제출 시각과 최신 제출 파일을 표시한다. ‘파일 일괄 다운로드’는 교사별 폴더로 구분한 ZIP이며 최신 제출본만 포함한다. 이름이 같아도 파일이나 폴더를 덮어쓰지 않도록 식별자를 함께 사용한다. 파일명이 ZIP 경로를 탈출할 수 없게 처리하며 만료·삭제된 파일은 제외하고 화면과 ZIP의 안내 파일에 표시한다. ZIP은 다운로드 응답에서 생성하여 서버에 별도 복사본을 계속 보관하지 않는다. 동시에 처리할 수 있는 일괄 다운로드 수도 제한한다.

마감은 한국 날짜 기준 해당일 23:59:59이다. 기본값으로 마감 전 파일 수정·재제출을 허용하고, 마감 후 제출은 거부하지 않고 ‘지각 제출’로 표시한다. 발신자가 요청을 종료하면 새 제출과 재제출, 알림을 중단한다. 알림 기간, 지각 제출 정책은 설계 검토 중 변경할 수 있다.

### 자동 알림

추천 기본값은 **마감 이틀 전부터 한국 시각 매일 오전 9시에 미제출자에게 한 번**이다. 예를 들어 10월 12일 마감이면 10월 10일 오전 9시부터 시작한다. 제출하거나 발신자가 요청을 종료하면 중단하며, 마감 후에도 미제출 상태라면 하루 한 번 계속 안내한다. 이미 제출한 사람은 재제출할 필요가 있다는 이유로 미제출 알림을 받지 않는다. 발신자가 개별적으로 대상자의 제출 의무를 면제하면 그 사람의 알림도 중단하고 현황에 ‘면제’를 표시한다.

학교 서버가 자동 알림을 DB에 저장하고 기존 실시간 알림 경로로 전달한다. 쪽지 화면에는 ‘시스템 자동 알림’, 원본 제출 요청의 발신자·제목·기한·바로가기를 표시한다. 외부 SMS·메일은 사용하지 않는다. 로그아웃한 교사도 다음 로그인 때 저장된 알림을 조회한다. 시스템 알림에서 다시 할 일 후보나 제출 요청을 만들지 않는다.

요청·대상 교사·한국 날짜 조합을 DB에서 유일하게 하여 서버 재시작·중복 실행 때 하루 두 번 생성되지 않게 한다. 알림 저장과 중복 방지 기록은 같은 트랜잭션으로 처리한다. 서버가 오전 9시에 꺼져 있었다면 같은 날 재시작 후 당일 알림만 생성하며 지난날 알림을 몰아서 보내지 않는다. 비활성 계정에는 새 알림을 생성하지 않는다. 전송 직전에 제출·면제·종료 상태를 다시 검사하고 제출 확정 및 종료와 알림 생성의 순서를 DB 트랜잭션으로 보호한다. 정상 운영에서는 1분 간격으로 당일 미처리 알림을 확인하므로 정확히 9시 정각 전달을 보장하지는 않는다.

### 제출 파일과 권한

기존 첨부 업로드의 크기·유형·백신 검사와 임시 저장 처리 코드를 재사용한다. 제출 확정 시 로그인 교사가 해당 요청의 대상자인지, 요청이 종료되지 않았는지, 파일이 자기 미사용 업로드인지 재검사한다. 제출 기록과 파일 연결, 만료 시각은 한 트랜잭션으로 확정하고 재시도 시 중복 제출을 만들지 않는다. 한 제출본은 최대 10개 파일, 파일당 100MB, 합계 200MB로 기존 쪽지 제한과 맞춘다. 제출한 파일은 일반 쪽지 첨부처럼 모든 수신자가 볼 수 있게 연결하지 않는다.

다운로드 권한은 제출자 본인과 요청 발신자만 갖는다. 발신자만 전체 현황과 일괄 다운로드를 볼 수 있고, 다른 수신자와 관련 없는 관리자에게는 공개하지 않는다. 사용자가 파일 번호를 알아도 서버의 요청별 권한 검사를 통과해야 한다. 요청을 만들거나 마감 변경·종료·면제·제출·재제출할 때 기존 CSRF·Origin 검사와 승인 계정 조건을 적용한다. 종료 후 업로드를 확정하려는 경쟁 요청도 거부한다.

제출 파일도 **제출 확정 시각부터 30일 후 만료**한다. 재제출로 기존 파일의 보관 기한을 늘리지 않으며 이전 제출본도 원래 기한에 삭제한다. 제출·지각 여부와 제출 시각 기록은 파일이 만료되어도 유지하고 ‘파일 만료’를 별도로 표시한다. 만료됐다고 다시 미제출 알림을 보내지 않는다. 기간이 긴 요청에서는 일찍 제출한 파일이 마감 전에 만료될 수 있으므로 발신자에게 만료일을 보여주고 필요한 파일을 내려받도록 안내한다. 발신자 PC에 내려받은 파일은 서버의 30일 삭제 정책으로 회수할 수 없다.

요청·대상자/면제·제출본/파일·일별 알림 기록을 기존 SQLite에 추가한다. 파일 정리는 쪽지 및 제출에 확정된 파일을 미사용 업로드로 오인하지 않도록 조건을 확장한다. 별도 외부 저장소나 작업 큐는 도입하지 않는다. 제출 파일 백업은 현재 첨부파일 백업 제외 정책과 같다.

## 확인 기준

- 같은 계정에서 웹·Windows 앱의 메시지와 할 일 변경이 일치한다.
- 관련 없는 교직원과 관리자는 타인의 대화·할 일에 접근하지 못한다.
- 로그인 만료와 로그아웃 후 웹 API·실시간 연결과 개인 데이터 표시가 종료된다.
- 악성 HTML처럼 생긴 본문·파일명이 실행되지 않고 그대로 표시된다.
