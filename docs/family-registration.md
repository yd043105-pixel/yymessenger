# 학생·학부모 가입과 자녀 고유번호

2026-10-09 구현 기준. 프로그램 버전은 배포 전 1.0.0을 유지한다.

## 가입 절차

학생과 학부모는 웹 또는 Android/iOS 앱의 `학생·학부모 회원가입`에서 각자 이름, 아이디, 비밀번호를 입력한다. 아이디는 영문·숫자·점·밑줄·하이픈 3~32자, 비밀번호는 12~128자다. 학부모는 임시회원으로 즉시 가입하고 로그인할 수 있다. 임시회원은 자신의 설정과 자녀 연결만 이용하며 공지, 첨부파일, 시간표에 접근할 수 없다.

학생은 학교가 미리 등록한 학급과 출석 번호를 입력한다. 관리자가 웹 `계정·가입 승인`에서 학교 학생 명부와 이름·학급·번호를 대조하고 `학교 확인 후 학생 가입 승인`을 선택해 저장하면 로그인할 수 있다. 입력한 학생 이름이나 학급만으로 자동 승인하지 않는다. 학생 일괄 가입과 수강 목록은 이 가입 흐름의 필수 조건이 아니다.

승인된 학생은 `설정 · 내 고유번호`에서 8자리 번호를 확인한다. 학부모는 **학부모 자신의 임시계정**으로 로그인한 뒤 `설정 · 자녀 연결`에서 해당 번호를 입력한다. 번호가 일치하면 별도 관리자 승인 없이 관계를 연결하고 정회원으로 즉시 전환한다. 자녀가 여러 명이면 같은 설정에서 각각의 고유번호를 추가한다. 한 학생을 여러 보호자 계정에 연결할 수 있고 동일 번호를 다시 입력해도 중복 관계를 만들지 않는다.

## 고유번호와 접근 관리

번호는 영문 대문자·소문자와 숫자를 모두 포함하는 무작위 8자리이며 대소문자를 구분한다. 서버의 암호학적 난수 생성기를 사용하고, 데이터베이스 고유 제약으로 다른 학생과의 중복을 막는다. 재발급한 이전 번호의 해시도 보관하여 과거에 발급한 번호를 재사용하지 않는다. 번호 원문은 Data Protection으로 암호화해 저장하고 비교용 해시를 별도로 보관한다. 로그인한 학생 본인과 학교 관리자만 번호를 조회할 수 있으며 공지 명부나 공개 API에 번호를 포함하지 않는다.

고유번호는 보호자 열람 권한을 부여하는 비밀값이다. 번호를 아는 사람은 학부모 계정으로 해당 학생을 연결할 수 있다. 별도의 보호자 신원 심사는 자동 전환 과정에 포함되지 않으므로 가족에게만 전달하고 단체 채팅방이나 공개 자료에 적지 않는다. 학생 비밀번호를 보호자에게 전달할 필요는 없다. 번호가 노출되면 관리자가 학생 행의 `고유번호 재발급`을 사용한다. 이전 번호는 즉시 무효화되지만 이미 연결한 보호자의 관계는 유지된다. 의심되는 보호자 계정이 있으면 관계 해제도 함께 진행한다.

관리자가 보호자 관계를 해제하면 해당 보호자 세션과 기존 공지 접근을 회수하고 학생 고유번호를 바꾼다. 이전 번호로 즉시 다시 연결할 수 없으며 다른 보호자의 기존 관계는 유지한다. 학생 계정을 중지하면 번호도 무효화하며 다시 활성화할 때 새 번호를 발급한다. 현재 연결된 활성 학생이 한 명도 없으면 학부모는 임시회원으로 표시되고 콘텐츠 접근이 차단된다. 재학 상태 변경은 학교가 계정·학급 관리에서 반영해야 한다.

번호를 5번 잘못 입력하면 해당 학부모 계정의 입력을 15분간 잠근다. 이 잠금은 서버 재시작 후에도 유지된다. IP별로는 15분에 최대 100회 입력을 허용하며 모든 변경 요청에 로그인과 CSRF 검증을 적용한다. 이 제한은 잘못된 입력뿐 아니라 여러 계정을 통한 반복 시도도 줄인다.

학생 소속 학급과 현재 자녀 관계에 따라 열람 범위를 제한한다. 새로운 자녀를 연결했다고 과거 비공개 공지의 수신 대상에 자동 추가하지 않는다. 연결한 이후 새로 발송된 공지는 현재 관계에 따라 수신하며, 시간표는 현재 연결된 자녀 학급을 조회한다.

## 기존 계정과 운영

기존 학교 초대 가입은 교직원과 학교가 미리 만든 계정의 활성화에 계속 사용할 수 있다. 기존 학생·보호자 관계도 유지한다. 교직원과 관리자 권한은 공개 회원가입에서 선택할 수 없다. DB뿐 아니라 암호화 키도 전용 운영 계정으로 보호하고 함께 복구할 수 있게 관리해야 한다. 운영 개인정보나 고유번호를 GitHub 및 테스트 자료에 올리지 않는다.

서버/API 검증은 `node tests/enrollment.mjs`, 웹 UI 검증은 Playwright가 설치된 환경에서 `node tests/enrollment.mjs --web`으로 실행한다. 가상의 계정과 학급만 사용한다. iOS 시뮬레이터 검사에는 개별 가입, 임시회원 화면, 번호 입력에 따른 즉시 전환, 다자녀 추가, 학생의 본인 번호 표시가 포함된다. 실제 기기와 스토어 출시는 별도 검증이 필요하다.
