# 관리자 시스템과 저부하 운용

서버 자동검색·이름 아이디·초기 비밀번호 변경·자동 구동 설정은 [연결과 자동 구동 안내](server-connection-and-autostart.md)를 따른다.

버전 1.0.0. 별도 클라우드나 별도 서버 관리 앱을 만들지 않는다. 기존 교내 업무 서버와 학교 소식 서버를 유지하며 PC 메신저의 관리자 계정으로 로그인하면 관리자 시스템이 자동으로 열린다. 자동 로그인에도 적용하고 같은 창의 중복 실행을 막는다. 로그아웃 시 창과 갱신 타이머를 종료한다. 일반 교직원은 화면과 관리 API에 접근할 수 없다. 앱의 관리자 계정은 Windows 관리자 권한과 구분한다.

학교 사진은 i5-10500, RAM 8GB, Windows 11 x64, RAM 약 75% 사용 및 여유 약 1.9GB를 보여 준다. 순간 측정이므로 평균·피크·동시 사용자를 증명하지 않는다. 작업 관리자에는 DDR4와 2667 MT/s, 슬롯 1/2가 표시되고 Intel의 i5-10500 사양도 DDR4-2666이다. 사용자가 말한 DDR3 추가 모듈과 서로 달라 실제 모듈 라벨과 메인보드 지원 규격을 확인해야 한다. DDR3를 DDR4 슬롯에 사용하지 않는다. 호환되는 8GB를 추가해 16GB가 되면 여유가 커지지만, 두 Windows VM의 안전한 운용을 보증하는 수치는 아니다.

- [Intel i5-10500 메모리 사양](https://www.intel.com/content/www/us/en/products/sku/199277/intel-core-i510500-processor-12m-cache-up-to-4-50-ghz/specifications.html)
- [메모리 세대 호환성](https://www.crucial.com/articles/about-memory/difference-among-ddr2-ddr3-ddr4-and-ddr5-memory)
- [Hyper-V 요구사항](https://learn.microsoft.com/virtualization/hyper-v-on-windows/reference/hyper-v-requirements)

## 관리자 화면

교내 관리자 로그인 → 서버 운영 창 → 교직원 계정·승인·권한 또는 학생·학부모 관리로 이동한다. 학교 소식 서버는 기존 별도 관리자 인증을 유지하며, 그 서버에 관리자 로그인을 하면 해당 서버의 상태 창도 열린다. 새 홈페이지나 사용자용 웹 화면은 추가하지 않는다. 서버가 먼저 실행되어 있어야 메신저 로그인과 관리 화면에 접속할 수 있으며, 관리자 로그아웃은 서버를 종료하지 않는다.

상태는 로그인한 API 서버에서 측정한다. PC 전체 CPU·RAM, 서버 프로세스 RAM, OS·CPU 모델·IPv4, 활성 네트워크 인터페이스의 송수신량, 데이터 저장 위치와 첨부 사용량·디스크 여유를 보여 준다. 첫 CPU·트래픽 값은 이전 샘플이 없어 '수집 중'으로 표시한다. 측정은 10초간 캐시하고 활성 관리자 창만 10초마다 조회한다. 디스크 파일 목록 전체를 매번 스캔하지 않고 DB의 첨부 크기 합계를 사용한다.

네트워크 수치는 쿨메신저·Windows 등 같은 PC의 다른 프로그램도 포함하며 가상 인터페이스가 있으면 중복 집계될 수 있다. VM 안에서 실행하면 VM의 자원과 네트워크를 보여 주므로 물리 호스트 전체 사용량과 구분한다. 쿨메신저 파일·데이터 폴더와 우리 프로그램 폴더를 공유하지 않는다. 저장 위치 변경, 인증서, 서버 바인딩, 백업 장치와 터널은 기존 운영 도구에서 점검해 설정하며 관리 화면이 임의로 바꾸지 않는다.

## 저부하 설정

운영 환경의 첫 실행은 저부하 모드이고 기존 시운행의 Development 기본값은 일반 모드이다. 관리 화면에서 선택한 모드는 서버 데이터 폴더의 `server-resource-policy.json`에 원자적으로 저장되어 재시작 후 유지된다. 서버 계정과 서버 간 연결은 기존 구조를 그대로 사용한다.

| 항목 | 저부하 | 일반 |
|---|---:|---:|
| 서버별 동시 업로드 | 1 | 4 |
| 서버별 동시 다운로드 | 2 | 8 |
| 동시 ZIP 생성 | 1 | 2 |
| 교내 파일 다운로드, 연결당 | 1MiB/초 | 별도 속도 제한 없음 |
| 학교 소식 이미지 열람, 연결당 | 256KiB/초 | 별도 속도 제한 없음 |

ZIP은 다운로드 슬롯도 사용한다. 최대치에 이르면 새 요청에 429와 재시도 안내를 반환하고 취소·실패·완료 후 슬롯을 반환한다. 파일을 통째로 RAM에 올리지 않고 작은 청크로 전송한다. 학교 소식 서버의 이미지 본문 송신은 동시 두 연결 기준 약 4.2Mbps, 교내 서버는 약 16.8Mbps가 시작 제한이다. 이는 해당 파일 본문에만 적용하며 전체 PC 트래픽·프로토콜 오버헤드·쿨메신저·업로드·클라우드 통신까지 제한하는 값이 아니다. 속도 제한은 순간 부하를 분산하며 전체 전송 바이트를 줄이지 않는다. 앱의 공지 이미지에는 지수 간격과 무작위 지연을 포함한 최대 5회 자동 재시도를 제공한다. 실패하면 새로고침으로 다시 요청할 수 있다.

저부하 상태에서 CPU 샘플 평균 85% 이상, PC 여유 RAM 512MiB 미만 또는 해당 서버의 RAM 768MiB 초과이면 새 파일 작업을 503으로 잠시 거부한다. 이미 진행 중인 전송을 죽이거나 메시지·계정·설문 같은 일반 기능을 강제로 중단하지 않는다. 이는 부하 완화 장치이며 PC 전체 CPU나 RAM 사용률의 절대 상한이 아니다. 백신, 기존 쿨메신저 및 다른 프로그램은 이 설정의 제어 대상이 아니다.

두 서버의 메모리 회수는 workstation GC를 사용한다. 운영 예시의 `resourceProfile: low-memory`로 시작하면 해당 서버 프로세스에만 `DOTNET_GCHeapHardLimit=20000000`을 지정한다. 환경 변수 값은 16진수이며 관리 힙과 GC 부기 공간을 512MiB로 제한한다. 네이티브 메모리·SQLite·스레드·백신까지 합친 프로세스 전체 RAM 상한은 아니다. 환경 변수는 운영 명령 종료 후 원래 값으로 복구하며 Windows 전역 설정을 바꾸지 않는다. UI 모드 변경은 동시 작업·속도·부하 거부 정책부터 적용되고 시작 시 GC 설정은 다시 실행해야 바뀐다. [Microsoft GC 설정](https://learn.microsoft.com/en-us/dotnet/core/runtime-config/garbage-collector), [동시 요청 제한](https://learn.microsoft.com/en-us/aspnet/core/performance/rate-limit?view=aspnetcore-10.0)

공지 업로드 요청 본문은 서명·파일 검사 전에 240,000바이트로 제한하여 oversized·chunked 요청을 조기에 거부한다. 파일 한 장의 업로드 형식에 필요한 여유를 포함한 값이며 파일 자체 제한과 구분한다. 공지 이미지는 기존 확정대로 JPG·PNG 한 장당 200,000바이트, 공지당 최대 5장, 30일 보관이다. 교직원 파일의 용량 정책과 메시지 회수·백업·졸업 파기를 바꾸지 않는다. 메시지나 화면을 중계하는 새로운 서버·스토리지·캐시를 추가하지 않는다.

## 학교 서버에 적용할 순서

1. `Inspect-ServerComputer.ps1`로 Windows 에디션·RAM 규격·모듈·슬롯·가상화 지원을 확인한다. 실제 모듈과 메인보드 지원을 대조한 뒤 메모리를 증설한다.
2. 기존 [학교 서버 설치 안내](server-setup-school-tunnel.md)의 망 격리·백업 장치·UPS·인증서·운영 계정·메일 준비를 완료한다. 8GB 사진이나 16GB 증설 계획을 망 격리 확인으로 대신하지 않는다.
3. 최신 교내·공지 서버 패키지와 PC 설치파일·두 앱을 교체한다. 운영 설정에 `resourceProfile: low-memory`를 사용한다. 비밀 값은 기존 DPAPI 등록 도구에서 직접 입력한다.
4. 서버를 기존 운영 도구로 먼저 실행하고 PC 메신저에 관리자 계정으로 로그인한다. 저장 위치·CPU·RAM·트래픽과 자동으로 열린 관리 화면을 확인한다.
5. 실제 인원으로 로그인·공지 열람·파일 제출·ZIP 작업을 차례로 시험하며 기존 쿨메신저와 동시에 사용했을 때의 평균·피크를 기록한다. 증설 후에도 저부하 모드에서 시작하고 충분한 여유와 부하 검증이 있을 때 일반 모드를 선택한다.

사진의 28일 보관 설정은 기존 쿨메신저의 설정이다. 우리 프로그램의 확정된 30일 보관을 변경하지 않는다. Windows 에디션·추가 메모리·학교 망과 외부 접속·백업 장치·UPS·운영 SMTP·실제 학교 부하는 미검증 상태이며, 준비 확인 항목을 임의로 true로 바꾸지 않는다. 학교의 호스팅 구조나 방화벽을 자동 변경하지 않는다.
