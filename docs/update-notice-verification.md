# 업데이트 안내 검증 기록

2026년 10월 8일, 가상 계정과 별도 시험 데이터로 검사했습니다. PC·모바일은 설치 파일의 내장 변경 내용을, 두 웹 서비스는 각 서버 배포 파일의 변경 내용을 표시합니다. 현재 안내 버전은 `0.1.0-beta.2`, 배포 순서는 `2`입니다.

## 실행 결과

| 검사 | 명령 | 통과 |
|---|---|---:|
| Windows 독립 실행 배포본과 WPF | `node tests/smoke.mjs --ui --skip-native-input --package` | 56 |
| 외부 공지·웹 배포 파일 | `node tests/announcements.mjs` | 17 |
| 학교 발신 연결·장애 복구 | `node tests/announcement-bridge.mjs` | 7 |
| 두 서버 데이터 폴더 분리 | `node tests/data-boundaries.mjs` | 2 |
| Android 에뮬레이터의 실제 앱 | `node tests/mobile-ui.mjs` | 13 |
| 업데이트 표시 조건·문자열 처리 | `node tests/update-notice.mjs` | 8 |
| 원격 검사 도구의 빠른 거절 응답 | `node tests/remote-channel.mjs` | 1 |

총 104개를 통과했습니다. 별도로 실제 브라우저에서 학교 소식 로그인 팝업, 나중에 선택 후 새로고침과 재로그인, 확인 후 재접속, 수동 다시 보기, 교직원 웹 로그인·확인 후 재접속, 관리자 웹 다시 보기의 6개 흐름을 확인했습니다.

WPF는 실제 안내 창의 확인·닫기 버튼을 실행해 미확인 버전 표시, 닫기 후 재안내, 확인 기록 저장, 동일 버전 재표시 방지, 수동 다시 보기, 이전·이후 버전 기록의 처리 조건을 확인했습니다. Android는 로그인 후 안내, 확인 후 프로세스 재실행에서 안내 생략, 수동 다시 보기를 확인했고 기존 메시지·공지·파일 선택·회수 시운행도 통과했습니다.

두 서버의 업데이트 JSON·JavaScript·CSS가 개발 실행과 Windows 배포본에서 제공되는지 검사했습니다. 버전과 내장 안내 내용이 일치하고 배포 ZIP·Android APK의 SHA-256 기록이 생성되는 것을 확인했습니다. 변경 내용은 HTML로 실행하지 않으며 계정·메시지·첨부 정보를 수집하지 않습니다. 저장소 차단과 안내 파일 연결 실패가 로그인·업무를 중단하지 않는지도 검사했습니다.

검사 중 개발 서버의 공통 안내 파일 경로를 수정했습니다. 시험 서버는 실행 파일을 별도 시험 폴더에 복사해서 빌드 파일과 충돌하지 않도록 했습니다. 원격 검사 도구는 거절 응답이 발신 요청 완료보다 먼저 도착해도 오류를 정상 검증하도록 보완했습니다.

실제 Windows 키보드 주입 1개는 `--skip-native-input`으로 제외했습니다. 사용자 Windows 창에 입력하지 않았으며 원격 연결·입력 패킷·권한 회수 검사는 수행했습니다. iOS 빌드·실기기, 실제 학교 외부 서버·도메인, 스토어 공개, 자동 설치 업데이트는 이 검증에 포함하지 않습니다. 운영·릴리즈 작성 방법은 [releases.md](releases.md)를 참고하세요.
