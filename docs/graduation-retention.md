# 재학 기간 보유·졸업 자동 탈퇴 및 파기

2026-10-13 · 프로그램 1.0.0 · 약관 문서 2026-10-13-draft.3. 학교가 정한 학생 보유기간과 교무실 문의처를 반영한다. 실제 학교 계정에 졸업 예약을 등록하거나 운영 DB를 삭제한 작업은 아니다.

## 학교가 정한 기준

- 학생 개인정보는 재학 기간 동안 보유하며 졸업 처리 시 자동 탈퇴·파기한다.
- 학부모는 다른 재학 자녀가 있으면 계정과 그 자녀 연결을 유지한다. 마지막 자녀 졸업 시 함께 탈퇴·파기한다.
- 운영 학교는 여양고등학교, 문의 창구는 **여양고등학교 교무실 061-689-5870**이다. 별도 담당 부서를 만들어 기재하지 않는다.

학교 홈페이지의 2년 재동의·6개월 미동의 계정 삭제를 학생 보유기간으로 적용하지 않는다. 교직원의 재직·퇴직, 전학, 직접 탈퇴 및 자녀를 연결하지 않은 임시계정의 보유 정책은 이 졸업 기준에서 자동으로 추정하지 않는다. 남은 정책·처리 근거·시행일 등을 학교가 확정해야 하므로 기본 운영 가입 승인 false를 유지한다.

## 등록과 자동 실행

1. PC의 학생·학부모 학교 소식 관리 창에서 별도 학교 소식 관리자 계정으로 로그인한다.
2. **졸업 자동 탈퇴·파기 예약**을 연다.
3. 학교가 확인한 졸업 대상 학생을 선택하고 한국 시간으로 `yyyy-MM-dd HH:mm` 형식의 처리 시각을 입력한다. 중지된 학생 계정도 명부 확인 후 선택할 수 있다. 프로그램이 3학년이라는 이유만으로 졸업일을 추측하지 않는다.
4. `졸업 자동 탈퇴 및 파기`를 입력하고 대상 수·시각을 확인하여 저장한다. 교직원·학부모·없는 계정을 학생 대상에 섞으면 전체 저장을 거부한다. 관리자 권한과 CSRF 확인이 필요하다.
5. 처리 시각 전에는 예약을 취소하거나 수정할 수 있다. 시각이 지난 예약과 완료된 파기는 취소할 수 없다.

예약 시각부터 학생 및 마지막 자녀가 졸업하는 학부모의 신규 로그인·기존 세션을 거부한다. 정상 가동 시 자동 정리 작업은 운영 환경에서 60초 주기로 실행하며, 요청 처리 시에도 지난 졸업 예약을 확인한다. 서버가 꺼져 있었다면 시작 시 지난 예약을 처리한다. 계정 비활성화만으로 작업을 끝내지 않는다.

교내 서버와 학교 소식 서버는 이 변경을 함께 적용해야 한다. 서로 연결되어야 교내 사본 파기 확인을 마칠 수 있다. 기능은 두 서버의 기존 서명된 연결을 사용하며 새 공개 관리 사이트나 호스팅을 만들지 않았다.

## 파기 대상과 실패 처리

학생·마지막 자녀가 졸업하는 학부모의 계정 이름/아이디/비밀번호 해시, 소속 및 관계, 초대, 고유번호와 학생 연결, 연결 신청, 동의 확인 이력, 세션, 분반 소속·공지를 받은 대상·읽음, 해당 계정의 시간표 알림 등 구조화 정보를 제거한다. 감사 기록의 계정 식별 연결도 제거한다. 공통 약관 전문 및 다른 구성원의 정보를 삭제하지 않는다.

이전 고유번호를 다른 학생에게 재발급하지 않도록 소유자·학생과 연결되지 않는 재사용 방지 해시를 별도 보관한다. 예전 번호의 보호된 원문·학생 연결은 제거한다. 파기와 서버 간 확인을 마칠 때까지 재시도에 필요한 최소 계정 식별자를 내부 작업 목록에 남기며, 교내 서버가 확인하면 그 목록에서도 제거한다. 완료하지 못한 상태를 전체 파기 완료로 표시하지 않는다.

두 서버 데이터 폴더 안의 `backups`, `migration-backups`, `recovery-backups`에 있는 관리 DB 스냅샷도 정리한다. 다른 구성원을 포함한 백업을 통째로 삭제하지 않고 해당 대상의 정보만 제거하여 검증 후 원자적으로 교체한다. 기존 백업 날짜를 유지하여 14일 정리 기준을 연장하지 않는다. DB secure_delete, WAL 정리 및 VACUUM을 사용한다. 외부로 연결된 백업 경로는 자동으로 따라가 수정하지 않으며 확인 대기로 남긴다.

교내 서버에 저장된 학교 소식 수신자·수신 확인 이름의 사본과 관리 DB 백업도 서명된 파기 요청을 받아 정리한다. 과거 확인 사본에 자녀 ID가 없어 여러 자녀를 구별할 수 없다면 해당 수신자의 모호한 확인 사본을 제거한다. 다른 자녀의 실제 공지·읽음은 학교 소식 서버에서 유지하며 최신 형식으로 다시 받을 수 있다. 이미 줄어든 대상이 들어 있는 미발송 작업은 취소 상태로 두어 새 수신자로 확대해 발송하지 않는다. 작업이 끝난 뒤에만 학교 소식 서버에 완료를 확인한다. 백업 오류, DB 잠금 또는 교내 연결 장애가 있으면 영속 작업으로 재시도한다. 관리 화면의 **백업·교내 서버 파기 확인 대기** 숫자가 0이 되는지 확인한다.

## 별도로 확인할 범위

- 교직원이 자유롭게 작성한 메시지·공지·첨부에 학생 이름 등이 들어 있다면 학생 계정과의 구조화 연결만으로 전부 찾아낼 수 없다. 학교가 교육 기록의 별도 보존 근거·기간을 분류하고 불필요한 개인정보를 파기해야 한다. 이번 기능을 모든 자유 입력 자료의 자동 탐지·삭제로 해석하지 않는다.
- 학교가 반출한 백업, 휴대폰·PC에 내려받은 파일, 관리자 수동 사본은 서비스의 관리 폴더 밖이므로 별도 확인이 필요하다. 그런 사본을 복원하기 전에는 졸업·탈퇴 명부와 대조하고 기존 복원 검토 절차를 거친다. 이번 기능이 외부의 오래된 미정리 백업까지 자동 발견·정리하지는 않는다.
- SSD의 삭제 흔적, OS 임시파일·외부 로그, 실제 디스크 암호화와 물리 매체 폐기는 실운영 검증 범위다. 앱의 DB 파기만으로 모든 매체의 포렌식 복구 불가능성을 인증하지 않는다.
- 실제 학교의 졸업 대상·시각은 아직 입력되지 않았다. 실제 명부·최종 약관 승인·실기기 관리 화면과 운영 환경은 학교 확인 후 적용한다.

보유 목적 종료 시 파기 및 법령상 별도 보존의 구분은 [개인정보 보호법 제21조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334901)를 검토했다. 법적 적합성이나 학교 승인 절차를 대신하지 않는다.

## 실행 검증

- AnnouncementServer·Server·Desktop 빌드: 경고 0, 오류 0.
- 졸업 시험 10개: 권한·확인 문구·대상 혼합 롤백·미래 시각·예약 취소, 서버 정지 중 지난 시각의 재시작 처리, 학생/마지막 자녀 학부모 파기, 재학 형제 및 다른 계정 유지, 관계/분반/고유번호/동의/세션 제거, 감사 보호 유지, 두 서버의 세 관리 백업 폴더와 교내 수신 확인 사본 정리, 백업 날짜 유지, 중지 학생 처리, 실패 시 확인 보류·복구 후 재시도.
- 기존 검증: 가입 동의 21개, 학교 소식 21개, 서버 연결 8개, 백엔드 보안 23개, 교내 기능 57개 통과.
- 최초 새 시험에서는 가상 DB의 컬럼명을 잘못 사용했고, 재시작 시험을 추가한 다음에는 이미 종료한 시험 프로세스를 다시 기다리는 정리 오류가 있었다. 시험 코드를 수정한 최종 실행은 종료 코드 0이며 위 10개가 모두 통과했다. 실패를 무시하거나 실제 프로그램 판정을 완화하지 않았다.
- Android/iOS의 약관은 서버 전문을 사용하는 기존 화면이므로 이번에는 모바일 소스를 변경하지 않았다. 새 전문의 실제 단말 표시·PC 예약 화면의 직접 클릭 시운행은 별도 미확인이다.

시험에는 임의 가상 계정만 사용했다. 결과는 `artifacts/graduation-checks.json`이며 재시운행은 `node tests/graduation.mjs`로 한다. 빌드 검증에도 같은 시험을 추가했다. 원문 검토안은 [이용약관](policies/서비스%20이용약관%20검토안.txt), [개인정보 수집·이용](policies/개인정보%20수집%20및%20이용%20동의%20검토안.txt)에 있다.
