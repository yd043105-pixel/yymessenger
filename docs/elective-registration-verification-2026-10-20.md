# 선택과목 신청 검증 기록

2026-10-20 · 1.0.0 · 가상 계정과 가상 명부 사용

## 적용 내용

Windows PC의 수강신청 설정과 학생 앱의 신청·변경·취소를 연결했다. 정원과 선착순 제한은 없다. 담당자는 신청·미신청 현황을 확인하고 유효한 신청자를 과목별 새 분반으로 확정할 수 있다. 학부모 대리 신청과 일반 교사의 전체 명단 조회는 서버에서 차단한다. 사용 순서는 [운영 안내](elective-registration.md)를 따른다.

## 확인 결과

- `tests/electives.mjs --ui`: 실제 배포 폴더의 두 서버 EXE와 Windows 클라이언트로 17개 검사 통과. 권한·기간·선택 규칙, 같은 과목의 복수 학생 접수, 중복 요청·동시 변경, 취소·재신청, 재시작 후 유지, 명단 조회·권한 회수, 마감·분반 확정, 대상 학급 이동, 학생 졸업 시 운영 DB와 관리 백업 파기, 네이티브 화면 입력·저장·현황 조회를 포함한다.
- 기존 기능 회귀 검사: 약관 21, 졸업 10, 공지·분반 25, 백엔드 강화 23, 시간표 21개 통과. 합계 100개이며 실제 기기 시험 수와 구별한다.
- 두 서버와 Windows 클라이언트 빌드: 경고·오류 0개.
- Android 교사용·학생/학부모용 두 앱: 경고·오류 없이 빌드. APK 서명과 앱 식별자·표시 이름·버전 1.0.0을 확인했다. 실제 휴대폰에서 신청 화면을 조작한 결과는 아니다.
- Windows 설치·업그레이드·제거 검사 7개 통과. 운영용 설치 파일의 해시와 별도 시험용 설치 ID를 사용해 실행 파일·사용자 파일 보존·자동 실행 항목 처리·다운그레이드 차단을 확인했다.

로그와 가상 화면 캡처는 프로젝트의 `artifacts/electives-2026-10-20`에 보관한다. `packaged-electives.log`, `regression-*.log`, `android-*.log`, `apk-*-signature.log`를 참조한다. 이전 실패 로그와 진단 자료도 남긴다.

## 함께 수정한 백업 오류

긴 Windows 경로에서 백업 이름에 임시 GUID를 두 번 덧붙이면 경로가 269자에 도달해 SQLite Error 14가 발생했다. 계정의 운영 DB 삭제 뒤에도 관리 백업 파기가 완료되지 않는 것으로 실제 재현했다. 임시 파일을 같은 디렉터리에 짧은 고유 이름으로 만들어 원자적 교체를 유지하면서 경로 길이를 줄였다. 같은 가상 백업에서 파기 성공을 확인하고 졸업·복원 검사와 배포 EXE의 수강신청 검사를 다시 통과했다. 시험도 계정 삭제뿐 아니라 영속 파기 작업의 백업 완료 상태까지 기다려 확인한다.

## 미확인·남은 범위

iOS 공통 소스는 반영했으나 이번 소스의 Mac 빌드·서명 IPA·실제 iPhone 시험은 하지 않았다. 개인 시간표 자동 연결은 과목/분반과 수업 시간대 매핑이 더 필요하다. 교사용 앱의 수강신청 관리 화면과 학부모의 자녀 결과 화면은 포함하지 않는다. 학교 서버 설치, Cloudflare 연결, 정식 스토어 배포·릴리즈 공개는 실행하지 않았다. 약관은 학교 검토용 초안이며 운영 승인 값은 꺼져 있다.
