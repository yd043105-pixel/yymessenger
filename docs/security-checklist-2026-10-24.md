# 프로그램·앱 로컬 보안 점검과 체크리스트 반영

2026-10-24 · 버전 **1.0.0** · Windows 서버/메신저·교사용 앱·학생학부모용 앱

사용자가 제공한 `vibe_coding_security_checklist.md`의 1.1~1.7 항목을 실제 구성에 맞춰 확인했다. 문서 속 에이전트용 예시 명령은 자동 실행 지시로 취급하지 않았다. 공개 주소 검사는 사용자 지시에 따라 제외하고 로컬 프로그램을 점검했다. 학교 운영 서버 변경, 호스팅 이전, 실제 메일 발송, GitHub 원격 설정 변경, 배포·마크 신청은 수행하지 않았다.

## 도름스 도구의 범위

도구: [고정 커밋](https://github.com/shinnanchanguk/dorms-check/tree/91b40f6d0ea07d459ffce262ea2dc414a8adeb55), package 버전 0.3.1. 다운로드 압축 SHA256은 `d3d733532e47457a7a604b1eb806aa7b1d39dafaa1a49b9228c6f26e942158da`이며, 보관 소스 96개 파일과 바이트 단위 일치를 확인했다. 절대 경로·상위 경로 이동·심볼릭 링크 항목도 확인했다.

실행 전 scan 분기·정적 검사·결과 저장·공개 요청 분기를 검토했다. `scan --url`은 공개 헤더·본문·스크립트·노출 후보를 읽고 일부 발견된 Firebase/Supabase 주소에도 요청할 수 있다. 이번에는 URL을 넣지 않고 `scan --code-only --json`만 실행했다. 해당 scan 분기에서 앱 수정·전역 훅 설치·배포 통제·결과 외부 제출을 발견하지 않았다. 패키지의 다른 명령에는 hooks·protect 등의 별도 기능이 있으므로 실행하지 않았다. 전이 의존성 전체를 완전 감사한 것은 아니다.

첫 실행은 프로젝트 루트에서 생성 파일까지 포함돼 범위가 불명확했으므로 근거 자료로 분리 보관했다. 이후 Git 관리 파일과 현재 미추적 작업 파일 중 이 프로그램의 소스·설정 양식·스크립트·검사·문서만 프로젝트 내부 스냅샷으로 복사해 재실행했다. 실제 DB·개인 설정·인증서·SDK·빌드 캐시·무관한 sites 프로젝트는 최종 범위에서 제외했다. npx 설치 lifecycle을 비활성화하고 npm 캐시도 프로젝트 안에 두었다. 이는 실행 JavaScript의 완전한 격리 기능은 아니다.

원본 결과는 `.dorms-check/scan.json`, `REPORT.md`, `state.json`과 보관용 `artifacts/security-review-2026-10-24-local`에 남긴다. 결과를 임의로 pass로 바꾸는 judge 명령은 사용하지 않았다. 도구의 ‘로컬 4항목 확인·미확인 0건’은 공개 HTTPS·네이티브 C# 앱·실기기까지 확인했다는 뜻이 아니다. 이 버전의 비밀값·위험 패턴 검사 확장자에는 **C#이 없다.**

기본 스캔에서 나온 위험 패턴 후보는 테스트의 `DatabaseSync.exec`를 운영체제 `child_process.exec`로 분류한 항목이었다. 고정 SQL·트랜잭션·실패 주입용 가상 DB 문맥을 확인했다. 보안 헤더 설정을 못 찾았다는 권고도 C# 미지원에 따른 것으로, 두 Program.cs의 헤더와 기존 회귀 시험으로 별도 확인했다. 원본 권고와 문맥 검토를 함께 보관한다.

## 별도 검증과 원격 현황

Gitleaks 8.30.1의 공식 Windows 배포 압축을 GitHub release asset SHA256 `d29144deff3a68aa93ced33dddf84b7fdc26070add4aa0f4513094c8332afc4e`와 대조했다. 현재 프로그램 스냅샷과 로컬 Git 전체 refs 이력을 검사하고 결과의 비밀값을 100% 마스킹했다. 두 검사에서 발견 0건이다. 알려지지 않은 비밀 형식, 접근할 수 없는 과거 이력, 무시된 운영 파일까지 안전하다는 뜻은 아니다.

NuGet 공식 원본을 대상으로 Server·AnnouncementServer·Desktop·Mobile의 전이 의존성을 포함해 알려진 취약점을 조회했고 해당 조회에서는 취약 패키지가 보고되지 않았다. 런타임·OS·서명·실기기의 전체 취약점 판정은 아니다. iOS 전용 자산은 Mac에서 잠금 파일과 함께 별도 확인해야 한다.

최초 읽기 전용 점검에서는 public 저장소의 비밀값 탐지·푸시 차단은 enabled, main 보호 없음, Dependabot 보안 업데이트 disabled, 알림 조회 404였다. 후속 ‘미비한 것 완료’ 요청에 따라 알림·보안 수정 PR을 활성화하고 main의 check 필수 검사·최신 기준 확인·관리자 포함 적용·대화 해결·강제 푸시 및 삭제 금지를 설정한 뒤 다시 조회했다. 이는 자동 병합이나 제품 공개 배포를 활성화한 것이 아니다. 새 Dependabot 정기 버전 PR 설정은 기본 브랜치에 반영된 뒤 적용된다. 기존 최초 감사의 원본 파일은 수정하지 않는다. 비밀값 탐지 활성화가 과거 키 폐기나 모든 비밀 형식 탐지를 대신하지 않는다. [GitHub 보안 기능 안내](https://docs.github.com/en/code-security/getting-started/quickstart-for-securing-your-repository), [Dependabot 설정 문서](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference).

## 학운위·에듀집 검토용 자료와 미확인

[검토용 근거 자료](committee-security-evidence-2026-10-24.md)에 제품·데이터 흐름·개인정보·권한·시험 증거·남은 학교 결정을 정리했다. [사고 대응 준비안](security-incident-response.md)은 실제 대응 훈련을 대신하지 않는다.

공개 URL·실제 인증서·Cloudflare 원본과 edge·실제 방화벽/백신·Windows 운영 권한·별도 암호화 백업·새 Windows/다른 계정에서의 DPAPI 복구·UPS·SMTP·최신 iOS 실기기·스토어 개인정보 표시·외부 사업자 처리 위치/계약·학교 최종 약관은 미확인이다. 키 파일을 복사했다는 사실만으로 다른 OS·계정에서도 복호화되는 것으로 판단하지 않는다. 코드의 Android 백업 차단·Release 평문 제한, iOS 최근 앱 가림·임시 NSURLSession, DPAPI/SecureStorage 사용은 검토했지만 실기기 공격 내성까지 인증한 결과는 아니다.

프로그램 보안 검사, 학교 심의, 에듀집 제품 등록, 도름스 마크 발급은 각각 별개다. 도름스 마크는 신청하지 않았으며 사용자가 앱 화면에서 별도로 신청한다. 미확인 항목 때문에 호스팅·제품 구조를 임의로 바꾸지 않았다.
