# 보안 사고 대응 준비안

2026-10-24 · 실제 사고 발생·조치 기록이 아닌 학교 검토용 절차 초안

문의: **여양고등학교 교무실(061-689-5870)**. 기술 조치 권한자·개인정보 책임자·부재 시 대체 담당자와 연락망은 학교가 확정한다.

## 발견과 초기 판단

1. 발생 시각, 앱 종류·버전, 영향받은 기능, 최소 재현 절차와 서버 추적번호를 비공개로 접수한다. 실제 비밀번호·쿠키·자녀 고유번호·개인키나 전체 학생 자료를 신고 본문에 복사하지 않는다.
2. 일반 오류, 권한 오용, 계정 탈취, 비밀키 노출, 데이터 유출·변조, 장비 장애를 구분한다. 가상 계정 재현 결과와 실제 피해 확인을 분리해 기록한다.
3. 서버·앱 버전과 관련 로그를 접근 제한된 장소에 보존한다. 합성 검사와 실제 사용자 증거를 구분하고 수집 범위를 최소화한다. 신고 내용은 공개 이슈나 외부 AI로 자동 전송하지 않는다.

## 위험 확산 억제

1. 해당 계정의 사용 중지·세션 회수·비밀번호 초기화가 필요한지 확인한다. 정상 사용자의 접근을 무조건 전체 차단하지 않는다.
2. 관리자 비밀번호·서버 연결 키·SMTP 인증 정보·Tunnel 자격 증명이 노출됐다면 해당 종류의 폐기·교체를 담당자가 수행한다. 소스에서 문자열만 지우는 것으로 완료하지 않는다. 서버 연결 키는 두 역할의 호환·교체 순서를 확인한다.
3. 외부 앱 접근 차단이 필요하면 학교 소식 서버의 해당 기능이나 터널 경로를 담당자가 제한한다. 교내 업무 서버를 인터넷에 공개하거나 학교 방화벽·백신을 해제해서 장애를 해결하지 않는다.
4. 서버 프로그램 교체 전에 정상 백업과 시작·감시 작업의 상태를 확인한다. 관련 없는 보안 프로그램이나 다른 경로의 서버를 강제 종료하지 않는다.

## 조사·수정·복원

1. 영향받은 사용자·자료·기간, 접근 경로, 권한 판정·키·서버 설정의 문제를 확인한다. 확인되지 않은 부분을 유출 없음으로 기록하지 않는다.
2. 수정 근거·변경 내용과 시험 계획을 기록하고, 가상 데이터로 같은 문제가 차단되는지 검증한다.
3. 백업이 필요하면 별도 시험 환경에서 먼저 복원한다. 복원 후 오래된 세션·보호자 연결·권한·졸업 파기 대상이 다시 유효해지지 않는지 확인한다. 운영 복원은 기존 복원 검토 절차를 따른다.
4. 정상 작동·권한 제한·오류 메일·백업·접속 기록을 확인한 후 제한을 해제한다. 프로그램 버전 교체만으로 데이터와 키까지 원상 복구됐다고 판단하지 않는다.

## 통지와 종료

학교 담당자는 실제 영향과 현행 신고·통지 요건, 관할 기관의 대응 절차를 확인한다. 정해지지 않은 법적 기한·기관 승인·배상 범위를 프로그램이 대신 확정하지 않는다. 필요한 사용자 안내에는 확인된 범위·취한 조치·사용자가 할 일을 적고 비밀값이나 다른 사람의 정보를 넣지 않는다.

종료 기록에는 원인, 영향, 실제 수정 버전, 재검증 결과, 키·권한 교체 여부와 남은 조치를 남긴다. 증거·오류 신고·감사 기록의 접근 권한과 보유 기간도 학교 정책에 맞춰 정한다. 자동 릴리즈·자동 설치·외부 마크 신청은 이 문서로 활성화되지 않는다.
