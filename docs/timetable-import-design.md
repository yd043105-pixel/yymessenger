# 기초시간표·일자별 시간표 업로드 설계

작성일: 2026-10-08. 상태: 검토안. 사용자가 제공한 두 엑셀 파일을 읽어 확인한 설계이며, 제품 기능의 구현 완료 기록이 아니다. 앱 분리·공지 범위·알림은 `school-apps-design.md`의 설계를 따른다. 사용자의 최신 요청에 따라 시간표는 학교 업로드 자료를 기준으로 운영하고, 급식은 NEIS 자동 연동을 유지한다.

## 목표와 적용 규칙

수업 업무 담당자가 학기 초에 기초시간표를 등록한다. 일자별 시간표를 등록한 날짜와 학급에서는 일자별 표를 우선한다. 일자별 표를 올리지 않은 날짜 또는 그 표에 없는 학급은 해당 날짜에 유효한 기초시간표의 요일별 수업을 사용한다. 날짜는 한국 시간 기준으로 처리한다.

일자별 표는 ‘변경한 교시만 적은 목록’이 아니라 파일에 포함된 학급의 해당 날짜 전체 시간표로 해석한다. 포함된 학급의 빈 교시는 수업 없음이며, 그 자리에 기초시간표 수업을 채워 넣지 않는다. 따라서 7교시 취소처럼 수업을 없앤 변경도 표현할 수 있다. 다른 날짜나 다른 학년의 시간표는 이 등록으로 변경하지 않는다.

기초시간표에는 학년도·학기·적용 시작일·종료일을 등록한다. 표 상단의 작성일을 적용 시작일로 추측하지 않는다. 같은 학기의 기초시간표가 바뀌면 새 적용 기간과 버전으로 등록하며 지난 날짜의 기준을 덮어쓰지 않는다. 같은 학급에 겹치는 적용 기간은 오류로 처리하고 담당자가 기간을 조정한 뒤 게시한다.

일자별 표를 교체하면 그 날짜·포함 학급만 새 버전으로 게시한다. 취소하면 기초시간표로 복귀하고 영향받는 사용자에게 복귀 알림을 보낸다. 적용 가능한 기초시간표가 없으면 임의 수업을 생성하지 않고 ‘기초시간표 미등록’ 상태를 표시한다. 휴업일은 수업 없음으로 게시할 수 있으며 기초 표의 요일 수업이 자동 노출되지 않도록 한다.

## 제공 양식에서 확인한 사실

두 원본 파일은 수정하지 않았다. 외부 서버나 공개 저장소에도 원본을 업로드하지 않았다.

| 양식 | 실제 구조 | 처리 방법 |
| --- | --- | --- |
| 기초시간표 예시.xlsx | `sheet1`, 월~일 요일 머리글 5행, 교시 6행, 1학년 1~6반 7~12행, 수업은 `과목(교사)` | 학급·요일·교시·과목·교사로 정규화 |
| 2026. 10. 8. 목요일 시간표 - 1학년.xlsx | `sheet1`, 학급 머리글 7행, 일자 B8, 교시 C8:C19, 학급별 수업 영역 | 날짜·학급·교시 전체 표로 정규화 |

기초 예시는 수업이 있는 칸이 192개이고, 일자별 예시는 1학년 6개 학급에 36개 수업이 있다. 제공된 두 자료를 2026-10-08 목요일 기준으로 비교하면 1학년 2반 2교시와 4반 4·5교시 총 3개 수업 칸이 다르다. 교사가 바뀐 칸도 변경으로 산정한다.

일자별 파일의 Q2는 `2026.10.07.`로 작성일이고, B8은 `2026.10.08. (목요일)`로 실제 수업일이다. 파일명이나 작성일 대신 표 안의 수업일을 우선하여 읽고, 미리보기에서 담당자가 확인한다. 년·월·일과 요일이 모순되거나 선택한 학년도·학기와 맞지 않으면 게시하지 않는다.

병합된 셀을 처리해야 한다. 기초 표의 목요일 5교시 머리글은 AR6:AS6에 병합되어 있고, 일자별 표의 학급 머리글과 수업도 폭이 서로 다른 병합 셀을 사용한다. 고정 간격으로 열을 나누지 않고 요일·교시·학급 머리글과 병합 영역의 시작 셀을 기준으로 읽는다. 병합 폭 때문에 같은 수업을 두 번 등록하지 않는다.

원본에는 학생별 수강 배정이나 선택과목 분반 명부가 없다. 이 양식으로 교사 개인 시간표는 해당 교사에게 배정된 수업을 모아 생성할 수 있고, 학생·보호자는 학생 소속 학급의 시간표를 확인한다. 선택과목이 학생마다 다른 학년의 정확한 학생 개인 시간표는 별도의 학생별 수강 배정 자료가 있어야 한다. 학급 표를 선택과목까지 반영된 개인 표라고 표시하거나 누락한 수강 배정을 추측하지 않는다.

## 수업 담당자의 PC 작업

관리자가 승인한 교직원에게 별도의 ‘시간표 관리’ 권한을 부여한다. 이 권한은 학교 전체 공지 발송 권한과 분리하며 일반 교사·학생·보호자는 업로드할 수 없다. 관리자는 담당자를 지정하고 권한을 회수할 수 있다.

PC 메신저에 ‘시간표’ 화면을 추가한다. 조회 화면은 모든 활성 교직원에게 제공하며 관리 권한이 있는 사용자에게만 ‘기초시간표 등록’, ‘일자별 시간표 등록’, ‘등록 이력·취소’ 작업을 표시한다.

업로드는 다음 순서로 진행한다.

1. 종류를 선택하고 기존 `.xlsx` 파일을 고른다. 기초 등록은 학년도·학기·적용 기간도 입력한다.
2. 서버가 파일을 읽어 학급·교사 연결과 날짜·교시를 검사한다. 과목명에 괄호가 있어도 마지막 교사 표시를 구분하고 원문도 보존한다.
3. 학급은 관리자 명부의 안정적인 학급 ID로, 교사는 교직원 계정 ID로 연결한다. 최초에는 일치 후보를 보여주고 담당자가 확인한다. 동명이인·미등록 교사·학급명이 모호한 경우 게시를 막고 명시적으로 연결하도록 한다. 이름만으로 다른 사람의 계정에 연결하지 않는다.
4. 미리보기에서 수업일, 적용 학급, 변경 전후의 과목·교사, 수업 추가·취소, 영향받는 교사·학생·보호자 수를 확인한다. 빈 교시는 ‘수업 없음’으로 표시한다.
5. ‘게시’로 확정한다. 단순 파일 선택이나 미리보기는 기존 시간표를 바꾸지 않는다. 게시 순간 권한·학급·교사 연결을 다시 검사하고 같은 요청의 재시도는 중복 게시하지 않는다.
6. 게시 결과와 앱 전달 상태를 확인한다. 일자별 표 교체·취소도 미리보기와 확인 후 실행하며 변경 이력을 남긴다.

자료를 읽을 수 없거나 날짜·학급·교시가 중복되면 셀 위치와 오류를 표시한다. 하나의 업로드가 검사를 통과하지 못하면 일부 학급만 조용히 바꾸지 않고 기존 게시본 전체를 유지한다.

## 표시 화면과 접근 범위

교사의 PC 메신저와 교사 앱은 ‘내 수업’과 ‘학급 시간표’를 제공한다. ‘내 수업’은 로그인한 교직원 계정으로 연결된 모든 해당 날짜 수업을 모아 보여주며 학급·교시·과목, 변경 여부를 표시한다. 같은 시간에 여러 학급을 함께 담당하는 수업은 모두 표시하고 임의로 한 수업을 제거하지 않는다. 새로 생긴 겹침은 업로드 미리보기에 경고하여 담당자가 확인할 수 있게 한다.

학생 앱은 본인 학급, 보호자 앱은 학교가 연결한 자녀 학급을 기본으로 표시한다. 여러 자녀는 전환할 수 있다. 교사는 교직원 업무 범위의 학급 표를 조회할 수 있으나 학생·보호자는 다른 학생 ID나 학급 ID를 입력하여 관계없는 시간표를 조회할 수 없다. 조회와 알림 클릭 때 현재 소속·보호자 관계·계정 상태를 검사한다.

일간·주간 보기를 제공하고 일자별 표가 적용된 칸에는 ‘변경’ 표시와 변경 전후 수업을 보여준다. 당일 일자별 표가 있어도 기초 표와 실제 내용이 같은 칸은 변경으로 표시하지 않는다. 화면에 자료 출처, 기준일·학기, 최근 게시 시각을 표시한다. 날짜별 조회 결과는 공통 규칙으로 생성하므로 PC·교사 앱·가족 앱의 내용이 일치한다.

## 전달·알림·기록

교내 서버가 업로드·검사·게시 이력을 관리한다. 게시 확정 후 정규화한 시간표와 승인된 계정 연결 정보만 기존의 외부 전송 대기열 방식으로 전달한다. 내부 SQLite·원본 엑셀·교직원 전체 명부를 외부 서비스와 공유하지 않는다. 외부 공지용 데이터와 내부 개인 쪽지를 섞지 않는다.

시간표 전달은 공지 게시와 구분한 버전 번호·수신 확인을 사용한다. 외부 서버는 하나의 버전을 원자적으로 적용한다. 네트워크 장애 때 PC에는 전달 대기를 표시하고 재시도하며, 앱의 마지막 게시 자료와 갱신 시각을 표시한다. 전달이 완료되지 않았는데 앱에서도 변경 완료라고 보고하지 않는다.

일자별 게시·교체·취소 후 실제 변경된 학급의 학생·확인된 보호자·담임과 변경 전후 수업에 해당하는 교사에게 알림을 요청한다. 수업을 잃은 교사도 변경을 알아야 하므로 새 담당 교사에게만 보내지 않는다. 여러 학급에 관련된 계정에는 같은 게시 건의 알림을 중복 생성하지 않는다. 기초 표의 최초 게시와 새 적용 기간 게시도 해당 범위에 알린다. 비교 결과가 동일한 재업로드는 변경 알림을 만들지 않는다.

푸시에는 학생 이름·수업 내용 대신 ‘학교 시간표가 변경되었습니다’와 일반 식별 정보만 넣는다. 알림을 누르면 해당 날짜를 열고 현재 권한을 확인한다. FCM/APNs 설정과 실기기 수신 검증은 별도 배포 조건이며 준비되지 않은 상태를 실제 푸시 성공으로 표시하지 않는다.

누가 언제 어떤 파일의 어느 범위를 게시·교체·취소했는지 관리 이력을 기록한다. 원본 업로드 파일은 기존 30일 임시 파일 정책을 적용한다. 정규화한 기초·일자별 시간표는 해당 학년도 종료 후 90일까지 운영 조회와 오류 복구에 사용하고, 이후 서버·백업의 삭제 작업 대상에 포함하는 정책을 제안한다. 원본 파일의 만료 때문에 운영 중인 학기 시간표가 사라지지 않게 한다. 이 보관 정책은 실제 학교 운영 기준 확인 후 확정한다.

## 파일 처리 보안

제품 파서는 서버의 .NET ZIP/XML 기능으로 확인한 `.xlsx` 양식을 읽는다. Excel 프로그램 실행·매크로 실행·수식 실행·외부 연결 갱신은 하지 않는다. 제공된 두 자료에는 수식이 없으므로 처음에는 시간표 데이터의 수식 셀을 지원하지 않고 셀 위치와 함께 명확히 거부한다. `.xls`, 매크로 파일, 암호화 문서, 손상된 ZIP, 예상 양식이 아닌 파일은 거부한다.

압축 파일과 해제되는 XML에 크기·항목·셀 수 제한을 적용하고 XML 외부 엔터티·외부 문서 참조를 금지한다. 기존 업로드 인증·요청 검증·파일 검사·저장소 권한 규칙을 재사용한다. 실제 제공 파일이나 추출한 교직원 이름을 공개 저장소의 테스트 자료로 넣지 않는다. 회귀 검사는 같은 구조의 가상 학급·가상 교사 자료를 사용한다.

## 일반 개발 방식의 작업 순서와 검증

1. 두 엑셀 양식의 제한된 ZIP/XML 파서와 기초/일자별 정규화 계약을 구현한다. 병합 영역, 목요일 교시의 열 간격, 수업일/작성일 분리, 공백/수업 없음, 원본의 여러 학년 시트를 검사한다.
2. 시간표 관리 권한과 학급/교사 연결, 적용 기간·게시 버전·이력 저장을 추가한다. 기존 계정에는 새 관리 권한을 자동 부여하지 않는다.
3. PC 업로드 미리보기·게시·교체·취소와 날짜별 조회를 구현한다. 기초 표 유지, 일부 학급만 덮어쓰기, 빈 교시로 수업 취소, 다른 날짜/학년 유지, 기간 경계, 권한 회수와 동명이인 차단을 검사한다.
4. 별도 외부 서버의 시간표 전달·권한 있는 조회와 교사/학생/보호자 앱 화면을 연결한다. 전달 중단·서버 재시작·버전 중복·오래된 버전 거부·다른 자녀 접근 차단을 검사한다.
5. 기존 앱 분리·기기별 푸시 설계와 연결하고 변경 전후 교사·대상 가족·담임의 알림 산정을 검사한다. 실제 제공 예시를 로컬에서만 대조하여 192개 기초 수업, 36개 당일 수업, 3개 변경을 확인한다.
6. PC 실제 화면, 두 앱의 Android 동시 설치·조회, iOS 빌드/시뮬레이터를 확인한다. 실제 휴대폰 푸시는 설정된 학교 계정과 실제 기기로 별도 검증한다. 완료 결과에는 구현된 범위와 미검증 조건을 구분한다.

모든 표시 버전은 1.0.0을 유지한다. 이번 요청만으로 실제 학교 명부 전송·외부 서버 공개·스토어 제출·릴리즈 배포를 실행하지 않는다. Superpowers는 brainstorming만 사용하고 나머지는 일반 개발 방식으로 진행한다.
