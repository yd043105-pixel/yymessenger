# 관리자 시스템·저부하 운용 검증 — 2026-10-14

버전 1.0.0. 학교 실제 서버·계정·자료·SMTP·터널·방화벽은 사용하거나 변경하지 않았다. 아래 검사는 가상 데이터와 로컬 개발 서버로 수행했다.

| 검사 | 통과 |
|---|---:|
| 자원·권한·속도·업로드 본문 제한 | 11 |
| Windows 관리자 화면 | 6 |
| 운영·백업·환경 변수 복원 | 26 |
| 기존 메신저 기능 | 69 |
| 공지 권한·200KB·5장 제한 | 25 |
| 서버 간 연결 | 11 |
| 백엔드 동시 처리·복원 | 23 |

기능·운영·관리 화면 171개가 통과했다. 별도로 새 Release 서버 묶음의 교내·공지 역할 업데이트, 데이터·설정 보존과 재시작 로그인 2개도 통과했다.

Windows 관리자 화면 검사는 실제 WPF 창과 버튼 이벤트를 사용했다. 관리자 최초 로그인과 암호화 자동 로그인에 자동으로 창이 열리고, 중복 실행을 막으며 설정을 저장하는 것을 확인했다. 로그아웃 시 창이 닫히고 일반 교직원에게 창을 열지 않으며 API가 403을 반환했다. 검사용 화면은 artifacts/administrator-ui/admin-system-preview.png이며 실제 학교 서버의 사용량으로 해석하지 않는다.

자원 검사는 양쪽 서버의 권한·CSRF·프로필 검증·설정 지속·로그아웃 토큰 폐기·측정 캐시를 포함한다. 교내 파일 두 건의 동시 다운로드에서 원본 바이트를 유지하고 속도를 제한하며 세 번째 요청을 거부했다. 완료·취소 후 슬롯을 반환했다. 업로드 한 건이 진행 중일 때 다음 업로드를 거부하며 취소 후 다시 받았다. 공지 업로드는 Content-Length가 있는 본문과 chunked 본문 모두 240KB를 초과하면 413으로 차단됐다. 초기 측정 시각이 요청마다 조금 달라지던 문제는 실제 샘플 시각을 저장하도록 수정했다.

두 서버/PC Debug·Release와 별도 Android 두 앱 빌드는 경고·오류 없이 완료했고 Windows 설치파일·서버 묶음·APK 해시를 갱신했다. 이번 변경의 Android 네이티브 화면 재조작, Mac/iOS 빌드와 실제 스마트폰 검증은 수행하지 않았다. 이전 Android 시운행 결과와 구분한다. 새 설치 마법사 UI 조작을 다시 했다고 주장하지 않는다.

RAM 슬롯·규격 확인 도구는 개발용 PC에서 실제 읽기 전용으로 실행해 정상 JSON을 확인했다. 개발용 PC의 Windows 에디션·16GB·모듈 규격을 사진의 8GB 학교 서버 정보와 혼동하지 않는다. 실제 서버의 추가 모듈·메인보드 호환성, 학교 동시 사용자의 CPU/RAM/회선 피크, UPS·별도 백업 장치·망 격리·SMTP 수신은 현장 확인이 남는다. CPU/RAM의 절대 사용률 상한을 보장하지 않으며 공지 속도 제한은 전체 PC 회선 제한이 아니다.
