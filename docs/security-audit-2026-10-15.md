# 백엔드 추가 보안 점검

2026-10-15 · 배포 전 1.0.0. 기준 소스 `f2dee5399ace568fd1e954d55e642a90fe00a364`와 이번 변경. 작업 원본은 `C:\Users\user\Documents\ChatGPT\여양고 온라인 교무실`로 복귀했다. 이전 C:의 부분 변경은 Git stash와 D:의 별도 패치에 보존한 뒤 최신 원격 커밋으로 fast-forward했다. 시험 데이터·패키지 캐시 일부는 여유 있는 D:를 사용하며 실제 학교 개인정보는 사용하지 않았다.

## 확인된 위험과 수정

| 항목 | 근거와 재현 | 반영 |
| --- | --- | --- |
| 비밀번호 변경과 관리자 재설정의 경쟁 상태 — 높음 | `/api/password`가 이전 비밀번호를 검증한 뒤 계정 ID만으로 UPDATE했다. 가상 DB의 쓰기 잠금으로 요청을 대기시키고 관리자 재설정과 같은 비밀번호·세션 버전 갱신을 먼저 커밋했다. 수정 전 오래된 요청이 HTTP 200으로 성공해 새 설정을 덮어썼다. 유효한 기존 세션과 이전 비밀번호가 필요한 제한된 시점의 취약점이며 무인증 계정 변경은 아니다. | 활성 상태·요청 세션 버전·검증한 비밀번호 해시가 모두 동일할 때만 UPDATE한다. 변경된 계정은 409로 거부한다. 재설정 해시 보존·옛 세션 거부·새 비밀번호 로그인 회귀 시험을 추가했다. |
| 비밀번호/최초 활성화의 CPU 작업 반복 — 보강 | 비밀번호 변경은 일반 계정 한도 600회/분만 적용했고, 최초 활성화는 잘못된/잠긴 코드에도 PBKDF2 검증과 새 해시를 먼저 계산했다. 8GB 서버에서 불필요한 CPU 작업을 유발할 수 있었다. 실제 운영 서버 고부하나 장애를 재현한 결과는 아니다. | 비밀번호 변경·활성화에 계정별 15분당 10회 별도 한도를 적용한다. 활성화 번호·만료·잠금 상태를 먼저 검사하고 유효한 요청만 비밀번호 해시를 계산한다. 관리자 초기화로 이 시도 한도를 우회하지 못하는지도 시험한다. 기존 영속 5회 실패 잠금은 유지한다. |

비밀번호 변경 완료 시 세션 버전을 올리고 재로그인하도록 한다. 새 계정별 한도는 프로세스 메모리에 있으므로 재시작 시 초기화되며, DB에 기록하는 로그인/활성화 실패 잠금과는 별개다. 운영상 초기 설정을 반복하다 한도에 도달하면 15분 대기한다. 시험의 두 번째 활성화 시나리오는 별도 프로세스에서 실행해 해당 한도와 기존 동의 이력 보존을 각각 확인한다.

호스팅·DB 종류·제품 구분을 바꾸거나 운영 계정을 삭제하지 않았다. 관리자 MFA·백그라운드 푸시·계정 탈퇴 기능을 구현된 것으로 표시하지 않는다.

## 함께 검토한 범위

- 두 서버의 쿠키 인증·CSRF·Origin 검사·기기 세션 폐기, 교직원 최초 활성화, 최고관리자 보호와 권한별 API 접근.
- 교직원/담당 학급/학생/보호자의 공지·첨부·상담 권한, 관계 해제·전학·탈퇴 후 접근 회수, 중복·경쟁 예약 처리.
- 서버 간 HMAC 본문·경로·시각·난수 서명, 영속 재전송 차단, 연결 키 교체와 연결 실패 처리.
- 파일 크기·확장자·시그니처·이미지 해상도 제한, 운영 AV 검사 실패 거부, SHA256 무결성, 30일 만료·회수·수합 파일 권한.
- 메시지 재시도·읽음·회수 경쟁, 제출 철회·재제출, 시간표 ZIP/셀 제한, 졸업 자동 파기·백업 정리, 복원 후 일반 이용 차단과 관리자 검토.
- 로컬 저부하 모드·API 권한·헤더, 두 서버 데이터 폴더 충돌 방지, 운영 사전 점검과 장애 알림 준비.

코드를 읽고 기존·추가 회귀 시험으로 확인한 범위다. 모든 코드의 전수 정적 분석이나 침투시험, 무결점·운영 보안 인증을 뜻하지 않는다.

## 의존성과 실행 환경

C:의 로컬 SDK를 10.0.402, Windows 서버·클라이언트 실행 런타임을 10.0.13으로 맞췄다. 앞서 D: 배포본에 반영한 SignalR 상태 재연결 DoS 패치도 C: 소스와 빌드에 유지한다. 해당 취약점은 [GHSA-334f-vvp4-7g6p](https://github.com/advisories/GHSA-334f-vvp4-7g6p)의 10.0.13 수정 기준을 따른다. PC 전체의 시스템 .NET·Windows가 갱신됐다는 뜻은 아니다.

두 서버·Windows 클라이언트·Android 대상의 NuGet 직접/전이 패키지를 `--vulnerable --include-transitive --format json`으로 조회했다. 해당 조회에서 등록된 취약 패키지는 보고되지 않았다. 원본은 `artifacts/security-final-dependencies-*.json`에 보관한다. 미등록 취약점이나 모든 네이티브 OS·SDK의 안전성 판정은 아니다.

새 SDK가 요구하는 공통 ILLink 작업 패키지를 10.0.13으로 갱신했다. Android는 NuGet 복원으로 새 패키지와 해시를 확인했으며, iOS 잠금 파일에도 동일 패키지의 검증된 항목을 반영했다. iOS 자체 복원·빌드는 Mac CI/실기기 결과를 별도로 확인해야 한다. Android MAUI 워크로드의 필요한 Mono/AOT 도구도 새 로컬 SDK에 맞췄다.

## 검증 자료

`scripts/Build.ps1 -HeadlessTests`는 두 서버·Windows 프로그램을 빌드한 뒤 상담·부하 제한·운영 설정·변경 안내·원격 통신·메시지/보안/제출/예약·학교 공지·가입/동의·졸업·서버 연결·백엔드/복원·데이터 격리·시간표 시험을 순서대로 수행한다. 실제 결과는 `artifacts/security-final-full-build.log`와 각 `artifacts/*-results.json`에서 확인한다. 실행하지 않은 실제 OS 키보드 제어·운영망·실기기 시험을 이 명령의 통과 항목에 포함하지 않는다.

추가 경쟁 상태·계정별 제한 시험은 `tests/password-security.mjs`이며 `tests/security.mjs`를 통해 메시지 회귀 시험에 포함된다. 기존 할 일 페이지 시험의 직접 DB 준비는 짧은 쓰기 트랜잭션과 대기 제한을 사용해 백그라운드 정리 작업과의 불필요한 시험 충돌을 줄였다. 제품 DB 잠금을 없애거나 검사를 건너뛴 수정은 아니다.

기존 GitHub Verify 실행 `38575920703`의 실패도 확인했다. Android/iOS는 SDK 갱신 뒤 ILLink 10.0.12 잠금 불일치였고, Windows는 상담 시험이 개발 PC 전용 `.tools/dotnet/dotnet.exe`를 고정 참조한 문제였다. 패키지 잠금과 상담·자원 시험의 SDK 선택을 보완해 CI가 설치한 SDK도 사용하도록 했다. 실패한 이전 실행을 통과한 것으로 표시하지 않는다.

## 권고

1. 앱 관리자 계정에 다중 인증을 보강하고 최고권한 계정 사용·분실·권한 회수·감사 기록 보관을 학교가 확정한다. Cloudflare 계정의 2단계 인증과 앱 관리자 인증은 별개다.
2. 약관·개인정보 정책 승인, 실제 보호자 확인, 사용자 요청에 의한 앱 내 탈퇴·개인정보 파기 절차를 확정·구현한다. 졸업 자동 파기 기능만으로 스토어의 사용자 요청 삭제 요구를 충족했다고 판정하지 않는다.
3. FCM/APNs를 구현하고 알림 본문 최소화·토큰 교체/회수·로그아웃·실기기 수신을 검증한다. 현재는 열기·새로고침으로 조회한다.
4. 학교 운영망 격리, 유효한 TLS, 별도 암호화 백업 복원·UPS·메일 실제 전달·외부 장애 감시를 확인한다. 서버의 순간 CPU/RAM 전체 사용률을 절대 상한으로 보장하지 않는다.
5. 학교가 배포를 지시하면 Windows 배포 서명, Android Release AAB/학교 서명 키, iOS 서명 IPA/TestFlight와 각 스토어 개인정보·계정 삭제 신고를 준비한다. 상세 순서는 [플랫폼 운영 안내](platform-deployment-guide.md)를 따른다.

## 확인하지 못한 내용

- 공개 HTTPS 주소가 없어 외부 응답·실제 Cloudflare/TLS/프록시 헤더·운영 방화벽·침투 검사는 하지 못했다. 임의 주소나 “내 앱 주소”로 점검하지 않았다.
- 고정 버전 도름스 도구는 [기존 소스 확인·로컬 검사 기록](security-audit-2026-10-13.md)이 있다. 그 도구는 C# 백엔드 전반을 검사하지 않으므로 기존 결과를 최신 C# 수정의 보안 인증으로 재사용하지 않는다. 도름스 마크는 신청하지 않았다.
- 학교의 실제 OS/Defender·계정 ACL·BitLocker·네트워크/VM 격리·키 보관·학교 명부·정전·디스크 가득 참·SMTP 실제 발송·별도 디스크 복원·운영 동시 사용자 부하는 미확인이다.
- 최신 소스의 실제 iPhone/iPad 설치·서명 IPA, Android 운영 휴대폰·Google Play, Windows 학교 PC 설치와 코드 서명은 별도 시험이 필요하다. 과거 Mac 시뮬레이터 기록을 최신 실기기 검사로 표시하지 않는다.

미확인을 이유로 앱 구조나 호스팅을 변경하지 않았다. GitHub 릴리즈·태그·스토어 공개·학교 실서버 설정은 하지 않았다. 버전은 1.0.0을 유지한다.
