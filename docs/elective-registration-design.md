# 선택과목 신청 — 구현 구조

2026-10-23 · 프로그램 버전 1.0.0 · 정원 제한 없음 · 1·2학년 대상

사용 순서는 [선택과목 신청 운영 안내](elective-registration.md)를 따른다. 이전의 정원 초과 처리 검토는 사용자의 ‘정원 없음’ 결정으로 종료했다.

## 저장과 권한

학교 소식 서버가 회차·학생별 신청·선택 과목·재시도 영수증을 SQLite에 저장한다. 교내 업무 서버는 로그인한 관리자 또는 지정된 담당자만 설정·전체 명단 조회·확정 업무를 할 수 있도록 검사하고 서명된 서버 간 연결로 요청을 보낸다. 교내 업무 서버를 외부에 공개할 필요는 없다.

학생은 기존 학생·학부모용 네이티브 앱에서 본인 계정으로 신청한다. 서버는 재학 상태·현재 학급에 등록된 학년(1·2학년)·회차 공개 상태·기간·묶음별 선택 개수를 확인한다. 다른 학생 명단과 미공개 초안은 제공하지 않는다. 학부모 대리 신청과 교사용 앱의 관리 화면은 이번 범위에 포함하지 않는다.

## 일관성

과목별 정원과 선착순 처리는 없다. 같은 과목에 여러 학생이 신청해도 모두 접수한다. 묶음별 필수 선택 개수는 별도로 검사한다.

신청 대상은 현재 재학 학년 기준 1학년·2학년으로 지정하며 3학년과 학급별 대상 설정은 제공하지 않는다. 회차의 `grades`와 학생의 현재 `Classes.Grade`를 서버에서 비교한다. 같은 학년 내 반 이동·신규 반은 자동 반영한다. 과거 `classIds` 저장 회차는 서버 시작 시 해당 학급의 학년 전체로 한 번 전환하고 기존 신청은 유지한다. 신청 현황의 학급 필터는 대상 설정과 별개다.

회차는 초안 → 공개 → 마감 → 분반 확정 순서다. 공개 후 과목·대상·규칙 편집이나 마감 회차 재개는 제공하지 않는다. 학생 신청·변경·취소는 서버 시각 기준 시작 이상, 종료 미만에 허용한다. 담당자는 일찍 마감할 수 있다.

요청 번호와 내용 지문으로 중복 재시도를 구별하고 신청 버전으로 동시 수정을 검출한다. 취소 후에도 버전을 유지해 오래된 변경 요청으로 신청이 되살아나지 않게 한다. 신청·마감·확정은 쓰기 트랜잭션으로 순서를 보장한다.

확정 시 현재 재학 중이며 대상 학년에 속한 신청자만 과목별 새 분반에 반영한다. 미신청자는 임의 배정하지 않는다. 대상 외 학년 이동 등으로 제외된 신청 수는 별도로 표시한다. 기존 분반을 덮어쓰지 않으며 확정 분반은 기존 공지 권한 검증을 사용한다.

## 개인정보와 시간표

학생 졸업 파기에 신청·선택·학생 재시도 영수증과 관리되는 백업을 포함했다. CSV는 담당자만 내보낼 수 있고 셀 수식 실행을 막도록 이스케이프한다. 내보낸 사본은 학교가 별도로 보관·파기해야 한다. 약관·개인정보 검토안에 처리 항목과 목적을 추가했으며 학교 확정 전 운영 가입 차단을 유지한다.

개인 시간표 자동 연결에는 과목/분반과 수업 시간대의 매핑이 더 필요하다. 이번 기능이 기존 학급 시간표를 변경하거나 개인 시간표를 자동 완성하지는 않는다.

## 검증

`tests/electives.mjs`는 실제 두 서버를 실행해 권한·기간·선택 규칙·정원 없는 접수·동시 수정·취소와 재신청·서버 재시작·마감과 분반 확정·졸업 시 운영 DB와 관리 백업 파기를 검사한다. `--ui`는 Windows 네이티브 입력 화면 저장·조회도 검사한다. Android 두 앱 빌드를 별도로 검증하며 iOS 빌드·기기 시험은 Mac에서 진행해야 한다.
