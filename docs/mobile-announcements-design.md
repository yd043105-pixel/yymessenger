# 모바일 앱과 학생·학부모 공지 — 승인한 설계

작성일: 2026-10-08. 사용자 승인 후 별도 외부 공지 서버·교내 발송 대기열·모바일 앱 소스를 구현했다. 실제 외부 서버 공개와 스토어 출시는 아직 진행하지 않았다. 현재 구현·배포 조건은 [운영 안내](mobile-operations.md)를 참고한다. 사용자는 앱에서 메시지를 확인하고 교사가 학생·학부모에게 가정통신문·공지를 보내는 기능, 학교 밖에서도 공지를 확인하는 기능을 요청했다. 추가 설명인 ‘핸드폰 어플로 출시’에 따라 스토어 배포용 모바일 앱을 목표로 수정했다.

## 추천 구성

기존 교직원 서버는 교내망에 유지하고, 학생·학부모 공지용 서비스를 별도 프로세스·저장소·호스트로 운영한다. 내부 서버의 SQLite·첨부 폴더를 외부 서비스에 공유하지 않는다. 인터넷에서 교직원 메시지·파일 제출·관리자·원격지원 API에 접근할 수 없게 한다. 학교 밖에서 교직원 개인 쪽지를 보려면 학교가 승인한 VPN 등 별도 접속 정책이 필요하며 학생·학부모 공지 서버로 개인 쪽지를 복제하지 않는다.

모바일은 **.NET MAUI로 Android·iPhone용 앱**을 개발하는 구성을 추천한다. 기존 서버와 같은 C#을 사용하고 API 계약·유효성 검사 규칙을 재사용하되, Windows WPF 화면을 그대로 실행하지 않고 휴대폰용 화면을 따로 만든다. 승인된 남색·파란색 디자인을 이어가며 로그인, 받은 소식, 공지 상세·첨부·읽음, 자녀 선택, 교사용 공지 작성·현황을 제공한다. 모바일 앱에 원격 화면 제어 기능은 넣지 않는다.

MAUI는 현재 프로젝트의 C# 환경을 이어갈 수 있다. Flutter나 React Native도 Android·iPhone 앱을 만들 수 있지만 별도 언어·도구 환경과 화면 코드를 추가해야 한다. 이 프로젝트는 기존 서버 API를 사용하는 MAUI 앱을 선택하는 편이 운영과 코드 재사용에 적합하다는 판단이다. 이는 프로젝트 상황에 따른 선택이며 모바일 구현·기기 검증 없이 성능이나 완성도를 보장하는 의미는 아니다.

Android는 테스트용 APK와 스토어 제출용 AAB, iPhone은 서명된 iOS 배포 패키지를 구분한다. [Microsoft Android 배포 안내](https://learn.microsoft.com/en-us/dotnet/maui/android/deployment/)와 [iOS 배포 안내](https://learn.microsoft.com/en-us/dotnet/maui/ios/deployment/?view=net-maui-10.0)를 기준으로 준비한다. 스토어 등록·서명·심사에는 학교가 관리할 개발자 계정, 앱 식별자와 배포 설정이 필요하다. [MAUI 지원 플랫폼 안내](https://learn.microsoft.com/en-us/dotnet/maui/supported-platforms?view=net-maui-10.0)에 따라 iOS 개발에는 연결 가능한 Mac이 필요하며 Windows PC만으로 iPhone 출시 패키지 검증을 완료했다고 표시하지 않는다.

설계 당시에는 모바일 도구가 없었으며, 승인 후 일반 개발 방식으로 MAUI Android 워크로드·Android SDK·Java와 에뮬레이터를 준비해 APK를 빌드하고 시운행했다. iOS 소스도 작성했으나 Mac·Xcode·서명 환경과 실제 기기 검증이 필요하다. 실제 스토어 게시까지 완료한 상태는 아니다.

교사 앱의 개인 메시지·채팅·설문·할 일·파일 제출은 기존 교내 서버 API와 본인의 계정을 사용한다. 학교 밖에서 이 영역을 사용하려면 학교가 승인한 VPN 등 교직원 접속 경로가 필요하다. 외부 공지용 계정과 세션은 교내 계정·세션과 별도로 관리하고 학교가 확인한 교직원 연결만 허용한다. 내부 계정의 비밀번호나 비밀번호 해시를 외부 서버로 복사하지 않는다. 학생·학부모 앱에는 교직원 영역을 표시하지 않으며 화면 숨김과 별개로 API에서도 접근을 거부한다.

## 대상별 화면과 계정

- 교사: 학교가 허용한 담당 학년·학급 또는 전체 학교 대상으로 공지·가정통신문 작성, 첨부, 발송 현황과 읽음 확인.
- 학생: 자신의 학급·학년·전체 학교 공지와 가정통신문 조회, 첨부 다운로드·읽음 처리.
- 학부모: 학교가 확인하여 연결한 자녀의 공지 조회. 여러 자녀는 자녀별로 구분한다.
- 관리자: 교사 담당 범위·학생 소속·학부모 연결 관리와 계정 회수. 연결 권한으로 교직원 개인 쪽지를 조회할 수 없다.

학생·학부모가 학번이나 이름만 입력하여 임의의 자녀·학급에 연결할 수 없게 한다. 학교가 관리하는 명부와 1회용·기한 제한 초대, 학교 확인 절차를 사용한다. 초대번호는 해시로 저장하고 재사용·무차별 대입을 제한한다. 가입 화면에서 교사·관리자 역할을 선택하여 획득할 수 없게 한다. 학교가 확인한 보호자 관계만 연결하며 관계 해제·전학·졸업·계정 정지 시 기존 세션과 접근 권한도 회수한다.

학급 단위 조회뿐 아니라 각 공지·파일·읽음 요청에서 실제 대상자 권한을 다시 확인한다. 다른 자녀의 번호나 공지·첨부 번호를 알아도 조회하지 못하도록 검사한다. 다른 학부모의 자녀 목록·읽음 상태·연락처는 공개하지 않는다.

## 발송과 내부·외부 동기화

교사는 내부 메신저에서 ‘학생·학부모 공지’를 별도 메뉴로 선택한다. 개인 쪽지·교직원 대화를 외부로 발송하는 메뉴와 혼동하지 않도록 대상과 ‘외부 공지’ 표시를 확인하고 발송한다. 수신 대상은 학생·학부모·양쪽, 학년·학급·전체 학교이며 학교 전체 발송에는 별도 권한을 적용한다. 공지 발송 시 대상 목록을 확정하여 이후 새로 가입한 계정에 이전 비공개 공지가 자동 공개되지 않게 한다.

내부 서버가 외부 공지 서비스로 HTTPS 연결을 시작하여 승인된 공지·대상과 해당 첨부만 전송한다. 외부 서버가 내부 파일이나 메시지를 임의로 조회하는 API는 만들지 않는다. 별도 서비스 인증과 최소 권한, 중복 방지 번호·전송 상태를 사용한다. 실패하면 발송 대기로 남기고 같은 번호로 재시도한다. 학교 서버가 잠시 꺼져도 이미 외부에 전달한 공지는 외부 서비스에서 조회한다.

공지 철회·계정/대상 회수는 일회성 발송과 달리 지연이 개인정보 접근에 영향을 준다. 외부 서비스에서 계정을 즉시 정지할 수 있는 운영 경로를 별도로 제공한다. 내부 명부 동기화가 중단되면 새 발송과 신규 관계 연결을 중지하고 마지막 동기화 상태를 관리자에게 표시한다. 읽음 상태는 권한 있는 교사에게만 전달하며 다른 교직원의 개인 메시지 수신·읽음과 섞지 않는다.

## 파일·세션·알림

외부 전송 전 기존 업로드 크기·유형·백신 검사를 적용한다. 외부 서버도 최대 크기·유형·권한을 독립적으로 검증한다. 첨부파일은 외부 게시 확정부터 30일간 보관하며 외부 복사본·캐시·백업에도 같은 만료일을 적용한다. 삭제 이후의 백업 복구에서 만료된 파일이 다시 다운로드되지 않게 검사한다. 본문 보관·졸업 후 계정 보관 정책은 학교 운영 결정이 필요한 배포 조건이다.

개인별 본문과 첨부를 기본으로 오프라인 저장하지 않는다. 휴대폰에 저장한 인증 정보는 플랫폼의 보안 저장소를 사용하며 비밀번호는 저장하지 않는다. 교직원 및 외부 공지 서버의 인증 정보를 섞어 보내지 않는다. 로그아웃·권한 회수 후 화면과 저장 인증 정보를 지우고 오프라인일 때 예전 개인정보를 표시하지 않는다. 운영 HTTPS, 정상 인증서 검증, 보안 쿠키와 서버 요청 검증, 로그인/초대 시도 제한과 공지별 권한 검사를 적용한다. 다운로드하여 사용자가 직접 저장한 파일은 서버에서 회수할 수 없다고 안내한다.

앱 안에는 읽지 않은 공지를 표시한다. 출시용 백그라운드 푸시는 Android·iOS의 서비스 인증과 실제 기기 검증을 준비하여 적용할 별도 배포 항목이다. 외부 전송되는 알림에는 학생 이름·본문·첨부·학급 등 민감한 내용을 넣지 않고 ‘새 학교 공지’ 수준으로 제한한다. 기기의 푸시 수신 정보는 로그인 계정에 연결하고 로그아웃·계정 정지·관계 회수 시 대상에서 제외한다. 알림을 누른 뒤에도 서버에서 해당 공지 권한을 확인한다. 실제 알림은 잠금 화면·기기·앱 종료 상태에서도 확인해야 한다. SMS·외부 이메일 발송은 포함하지 않는다.

## 구현 전 확인과 배포 조건

사용자의 추가 설명에 따라 스토어용 앱을 목표로 확정했다. 기기 범위는 별도 답변 전까지 안드로이드·아이폰 모두를 가정한다. 현재 검토할 내용은 MAUI 앱과 별도 외부 공지 서버 구성, 교직원 개인 메시지의 교내망/VPN 유지이다. 실제 학생·보호자 명부는 테스트에 넣지 않고 가상 가족·학급으로 계정 연결, 다른 가족 접근 차단, 교사 대상 범위, 철회·재시도·만료·재시작을 검사한다. Android 실기기·에뮬레이터, iPhone 실기기·시뮬레이터, 서버 재시작·네트워크 단절·세션 회수와 배포 서명을 별도로 확인한다.

외부 공지 서비스는 실제 배포 전 학교가 관리할 도메인·신뢰할 수 있는 인증서·외부 서버 또는 격리 호스트·방화벽·백업/디스크 암호화·최소 접근 권한을 준비해야 한다. 이 문서만으로 기존 서버의 인터넷 접속을 열거나 실제 명부를 전송하지 않는다. 승인 후 일반 개발 방식으로 가상 데이터의 로컬 공지 서비스, 내부 발송 연결과 모바일 앱을 완성하여 검토하고, 실제 외부 배포와 스토어 제출은 구체적인 설정·서명 환경을 확인한 뒤 진행한다.
