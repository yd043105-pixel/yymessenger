# 여양메신저 관리자 프로그램

2026-10-28 · 출시 전 1.0.0

서버 가동뿐 아니라 구성원·권한·학교 설정을 처리하는 Windows 관리자 프로그램이다. 교사용 메신저를 따로 열지 않고 왼쪽 관리 메뉴의 내용을 같은 창 본문에 표시한다. 서버 시작·중지는 관리자 프로그램이 제공하는 기능 중 하나다.

## 관리 메뉴

| 메뉴 | 처리하는 일 | 인증 대상 |
| --- | --- | --- |
| 교내 업무 서버 / 학교 소식 서버 | 최초 시험 설정·시작·정상 중지·자동 시작·실행 기록 | 서버 PC의 Windows 운영 사용자, 로컬 프로세스 제어 |
| 운영 현황 | 실제 CPU·RAM·저장 공간·전송 제한·자동검색 설정 | 선택한 서버 관리자 |
| 교직원·권한 | 검색·이름·부서·직책·좌석·계정 상태·초기화·사전 등록·가입 승인·업무 담당 권한 | 업무 서버 관리자 |
| 학급·분반 | 분반·교사·학생 수강 명부 연결 | 업무 서버 관리자, 기존 학교 소식 연결 |
| 특별실 / 학사일정 | 특별실 목록·위치·예약 허용과 학교 일정 | 업무 서버 관리자 |
| 학생·학부모 | 학급·학교 명부·승인·보호자 관계·고유번호·졸업 파기 예약 | 학교 소식 서버 관리자 |
| 약관·개인정보 | 학교별 검토 초안 작성, 자동 운영 승인 없음 | 선택한 서버 관리자 |
| 오류·의견 | 접수·처리 상태·학교 회신·개발용 자료 관리 | 선택한 서버 관리자 |
| 운영 변경 기록 | 기존 감사 기록 조회 | 업무 서버 관리자 |

회원·학교 관리에 처음 들어가면 본문에서 해당 서버의 관리자 로그인을 요구한다. 업무 서버 로그인으로 학교 소식 서버에 접근 권한을 주지 않는다. 비밀번호·인증 쿠키는 메모리에서만 사용하며 자동 로그인 파일을 만들지 않는다. **이 서버 로그아웃**은 해당 역할을, 창 X는 모든 관리 계정을 로그아웃하며 가동 중인 로컬 서버는 알림 영역에 유지한다. 서버에서 권한이 회수되면 관리 화면을 닫고 다시 인증을 요구한다. 모든 변경의 최종 권한 검사는 기존 서버 API가 수행한다.

## 참고와 디자인 결과

- [NAVER WORKS 관리 콘솔](https://naver.worksmobile.com/whats-new/notice/works-admin-console/overview/)의 관리 영역 구분과 [Mattermost 상태 대시보드](https://docs.mattermost.com/administration-guide/manage/site-health-dashboard)의 상태 우선 정보 구조를 참고했다. 화면·아이콘·상표는 복제하지 않았다.
- [Stitch 기존 프로젝트](https://stitch.withgoogle.com/projects/16363322754853011110)에서 새 서버 관리자 화면을 생성한 뒤, 불필요한 외곽 메뉴와 가상 CPU·사용자·인증서 상태를 제거하도록 수정했다. 결과 제목은 `여양메신저 로컬 서버 관리자 (960x760 네이티브 윈도우)`다. 브라우저로 작업했고 개별 화면 ID는 확인되지 않아 임의로 기록하지 않았다.
- [Figma 정제 화면](https://www.figma.com/design/x3w6KOP0uIi5VnkEDbXx0l?node-id=37-26)은 기존 색상 변수·텍스트 스타일·버튼 인스턴스를 사용한 편집 가능한 레이어다. 비밀번호와 운영 설정이 조건부로 표시되도록 실제 동작에 맞췄다.
- 최종 통합 관리자도 Stitch에서 `여양메신저 관리자 (1060x780)`로 생성한 뒤 [Figma 통합 관리자](https://www.figma.com/design/x3w6KOP0uIi5VnkEDbXx0l?node-id=40-33)에서 정제했다. 앞의 개별 화면은 이전 디자인 참고본이다. Stitch의 임의 버전·SMS·가상 상태·새 임시 비밀번호 정책은 구현하지 않았다.
- 로그인 후 운영 화면도 Stitch에서 별도 생성하고 [Figma 운영 화면](https://www.figma.com/design/x3w6KOP0uIi5VnkEDbXx0l?node-id=38-30)에서 정제했다. **운영 현황 / 계정·학교 / 시작·연결** 탭으로 나눴고, 실제 서버의 CPU·RAM·저장 공간·전송 제한만 표시한다. Stitch가 제안한 가상의 백업 경로·응답 지연·로그아웃 버튼은 추가하지 않았다. 원래 연결된 관리자 계정의 접근 제어를 유지한다.
- `artifacts/server-manager/stitch-admin-workspace.png`, `figma-server-manager.png`, `server-manager-stopped.png`, `server-manager-running.png`, `server-manager-compact.png`에 작업 단계와 실제 WPF 화면을 보관한다. 화면 자료는 개인정보 없는 시험 데이터다.

## 실제 동작

왼쪽에서 **교내 업무 서버 / 학교 소식 서버**를 선택한다. 상태·주소·시작·중지·관리자 로그인은 창을 줄여도 설정 스크롤 밖에 남는다. 최초 비밀번호는 시험 서버의 첫 설정 때만 표시한다. 운영 모드에서는 운영 설정 파일을 선택한다. 역할을 바꿔도 입력 중인 실행 설정을 보존한다. 관리 메뉴에서는 기존 교직원·학교 기능을 재사용하고 로컬 창으로 돌아와 서버를 제어한다.

프로그램 자동 실행과 서버 자동 시작은 구분한다. 시험 데이터 경로와 실행 기록은 접을 수 있다. 시작에 실패하면 해당 서버 화면을 선택하고 오류 기록을 펼친다. 창 X는 알림 영역으로 숨기며 완전 종료는 알림 영역 메뉴에서 한다.

기존 로컬 종료 이벤트·비밀번호 비저장·DPAPI 비밀 보호·운영 사전 점검·예약 작업 충돌 방지는 유지한다. 관리 본문의 진입·해제는 WPF의 [Loaded·Unloaded 수명 이벤트](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/events/object-lifetime-events)를 사용하며 화면 전환 시 이전 타이머와 하위 창을 정리한다. 새 네트워크 포트나 원격 셸 API는 추가하지 않는다.

## 로컬 검증

- 관리자 통합 네이티브 검증 43개: 기존 서버 가동 20개와 같은 창의 교직원·특별실 실제 저장, 검색, 주요 관리 화면, 역할별 인증·지원 메뉴 분리, 일반 교사 차단, 세션 회수·로그아웃·창 숨김·관리자 전용 설치 등 23개.
- 관리자 UI 검증 6개: 관리자 로그인·창 재사용·실제 부하 설정 저장·자동 로그인 복원·로그아웃 정리·일반 교직원 접근 거부.
- 기본 기능·보안·접속 상태·메신저 UI 회귀 93개: 실제 Windows 키보드 주입은 명시적으로 제외했다.

실제 학교 서버에 설치하거나 운영 데이터를 사용하는 시험은 포함하지 않는다. 설치본과 플랫폼별 CI 결과는 별도로 확인한다.
