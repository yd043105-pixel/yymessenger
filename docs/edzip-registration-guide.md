# 에듀집 등록과 학교별 운영 설정

2026-10-24 · 1.0.0 출시 전 · 교사 개인 개발 제품

이 안내는 등록 준비 자료다. 필수기준 충족 확인, 학교 승인 또는 보안 인증을 대신하지 않는다.

## 1. 등록하는 대상과 운영하는 학교

에듀집에는 **개발자가 제공하는 제품과 그 개인정보 처리 구조**를 설명한다. 여러 학교에서 사용할 수 있다고 설명하되, 아직 실증하지 않은 학교 도입 실적이나 대규모 다중 학교 서비스를 운영 중이라고 쓰지 않는다. 학교별 학운위는 해당 학교의 사용 목적·활성 기능·처리 항목·학교 책임자·위탁·실제 운영 환경을 검토한다. 에듀집 등록만으로 개별 학교의 심의가 끝나지 않는다.

현재 구현은 **학교별로 분리한 서버·데이터·계정·키·약관**을 운영하는 방식이다. 한 서버의 공용 DB에 여러 학교를 담는 SaaS 구조를 구현·검증한 상태가 아니다. 학교별 전용 설치 환경과 데이터 저장소를 준비하고, 한 Windows 계정에서 여러 학교를 억지로 실행하지 않는다. 기존 작업 스케줄러·데이터 루트·연결 키를 학교 간 공유하지 않는다.

개발·유지관리 담당자는 학교의 개인정보 보호책임자로 자동 지정되지 않는다. 학교 개인정보의 처리 주체·책임자는 학교가 확정한다. 개발자가 원격 운영·유지보수로 실제 개인정보를 처리한다면 그 관계와 접근 범위도 학교가 검토해야 한다. 일반 교사·학생·학부모가 학교명과 책임자를 임의로 입력해 운영 설정을 바꾸는 방식은 사용하지 않는다.

## 2. 관리자가 학교별로 설정하는 방법

1. 서버에 연결한 관리자 프로그램에서 **서버 운영 → 학교별 약관 · 개인정보 설정 초안**을 연다. 학교명·권리 요청 창구·학교 전화·학교 개인정보 보호책임자의 성명/직위/연락처를 입력한다. 모르는 책임자는 비워 두고 확인한다.
2. **학교 검토용 초안 파일 만들기**를 눌러 `C:\SchoolMessengerOperations\office\registration-policy.local.json` 등에 저장한다. 이 버튼은 `approvedForProduction:false`인 검토용 JSON만 만든다. 학교 약관 확정, 서버 적용이나 가입 승인을 수행하지 않는다.
3. 학교 개인정보 담당자와 함께 전문을 검토한다. 예시 문구·시행일·처리 근거·역할별 수집 항목·만 14세 미만 여부·보유/파기·제공/위탁/국외 이전·외부 서비스·권리 처리 담당을 실제 구성으로 확정한다. 본문에 학교명과 전화가 바뀌었다는 것만으로 검토를 완료하지 않는다.
4. 확정된 문서는 문서별 `version`을 바꾸고 전문을 보관한다. 학교가 운영용으로 확정한 뒤에만 `approvedForProduction`을 `true`로 설정한다. 개발자가 대신 승인 표시하지 않는다. `.local.json`은 공개 GitHub에 올리지 않는다.
5. 해당 서버의 `server-operations.local.json`에 다음 항목을 넣는다. 실제 파일이 존재하는 절대 경로를 사용한다.

```json
"registrationPolicyFile": "C:\\SchoolMessengerOperations\\office\\registration-policy.local.json"
```

6. 학교 소식 서버도 별도 약관을 준비하여 그 서버의 운영 설정에 해당 절대 경로를 넣는다. 업무 서버와 학생·학부모 서버의 처리 항목이 다르므로 문서 적합성을 각각 확인한다.
7. 사전 점검 후 계획된 서버 재시작 때 적용한다. 자동 구동 도구가 `Registration__PolicyFile`을 해당 자식 프로세스에 전달하고 종료 후 부모 환경을 복구한다. 값이 비어 있으면 다른 학교의 환경변수를 물려받지 않고 내장 초안으로 동작한다. 내장 초안의 Production 신규 가입은 차단된다.
8. PC 설정의 **약관·개인정보 안내**, 앱 **내 정보 → 약관·개인정보 안내**에 올바른 학교명·문의처·전문이 표시되는지 확인한다. **개인정보 열람·정정·삭제 요청**도 그 학교의 문의처를 표시한다. 오래된 동의 전문과 확인 이력은 새 전문으로 덮어쓰지 않는다.

메신저 제품명·아이콘의 브랜드와 개인정보 처리 주체인 학교명은 구별한다. 로그인 후 PC 창 제목·조직도와 앱의 학교 표시는 접속 서버가 제공하는 운영 학교명을 사용하고, 로그아웃하면 초기화한다. 앱의 모든 화면과 설치파일을 다른 학교 이름으로 자동 재브랜딩하는 기능은 이 설정의 범위가 아니다.

## 3. 교사 개인의 에듀집 등록 경로

공식 [체크리스트 등록 안내](https://edzip.kr/main-notice/6a17f7ebb8641362b8b5cabc)의 첨부 **등록 안내 PDF 5쪽**에 사업자가 아닌 교사 개인의 별도 입력 양식이 안내되어 있다. 기업 회원가입에 임의의 사업자 정보를 넣지 않는다.

공식 연결 양식: [사업자가 아닌 경우 필수기준 체크리스트 등록](https://forms.gle/aCa4mjvgtmovEf1eA).

2026-10-24 화면에서 확인한 항목:

| 입력/첨부 | 준비 내용 |
| --- | --- |
| 이메일 기록 | Google 계정 정보가 기록되는 안내를 본인이 확인 |
| 소속 / 직책 / 성명 | 실제 소속·직위·등록자 이름 |
| 공급자명 | 실제 개인 이름 또는 팀명 |
| 국문·영문 제품명 | 제품 소개안과 동일하게 기재 |
| 이메일·연락처 | 개발·관리 담당자의 실제 연락처 |
| 별도 공개 연락처 | 필요하면 학교가 공개를 허용한 업무 연락처. 미기재 시 휴대전화번호로 게시될 수 있음 |
| 체크리스트 | 공식 HWP 서식으로 작성 후 검토. **미충족 항목이 있으면 등록 불가**라는 화면 안내가 있음 |
| 개인정보처리방침 | 실제 제품의 처리 구조와 학교별 설정 절차를 설명하고 남은 항목을 확정한 파일 |
| 등록자 개인정보 동의서 | 공식 서식의 등록자 본인 검토·동의·서명. 앱 이용자 약관과 다른 문서 |
| 기타 증빙 | 시험 근거·설계·운영 안내. CSAP/ISMS-P는 실제 보유 시에만 첨부 |
| 게시글 본문 | 접속·설치 방식, 대상, 기능·제약, 지원 방법 |

검토용 초안을 완성본으로 올리거나 책임자·서명·인증을 만들어 넣지 않는다. 이 작업에서 양식 입력·업로드·제출은 수행하지 않았다. 학교별 변동 사항을 첨부하는 방식과 개인 공급자/학교의 역할 구분은 등록 확인 부서에 최종 문의한다.

## 4. 반드시 남겨야 하는 증거

필수기준은 5개 범주, 공식 서식의 세부 항목은 9개다. [작성용 대응표](edzip-checklist.draft.md)에서 코드 근거와 학교 확정 사항을 구분한다. 개인정보처리방침의 **책임자 정보, 실제 위탁·제공·국외 이전, 처리 근거·항목별 보유 기간, 시행일, 만 14세 미만 적용 여부/절차**는 기술 시험만으로 확정하지 않는다.

현재 Android는 Debug 시험 APK, iOS는 빌드용 소스다. Windows 코드서명, Mac의 최신 iOS 빌드와 실제 기기, 학교망·인증서·백신·메일·별도 암호화 백업·복원·UPS 시험은 실제 환경에서 기록해야 한다. 운영형 앱 종료 상태 푸시, NEIS 자동 데이터 연동, 학생 대량 등록은 완성된 기능으로 홍보하지 않는다.
