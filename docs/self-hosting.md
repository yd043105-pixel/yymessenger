# 교무톡 · 학교별 직접 운영

2026-10-28 · 출시 전 1.0.0

## 이름과 아이콘

제품 이름은 **교무톡**이다. Windows의 **교무톡**, **교무톡 관리자 및 서버**, 모바일의 **교무톡 교사용**, **교무톡 학교소식**으로 구분한다. 로그인 후 학교 이름은 해당 학교가 설정한 실제 이름을 사용한다.

아이콘은 파란 바탕에 말풍선과 펼친 책을 결합한 자체 벡터다. 문자·학교명 없이 Windows 실행 파일·창·작업표시줄·알림 영역·설치파일과 Android/iOS 앱·시작 화면에서 사용한다. 원본은 `src/SchoolMessenger.Shared/Branding/brand_mark.svg`, 모바일 적응형 앞면은 `appiconfg.svg`, Windows 다중 해상도 파일은 `brand_mark.ico`다. 수정 후 Windows에서 `scripts/Generate-BrandAssets.ps1`을 실행해 PNG/ICO를 다시 만든다.

기존 설치의 호환성을 위해 GitHub 저장소 이름, 설치 AppId, 모바일 패키지 ID, 실행 파일 이름, 내부 프로토콜·쿠키·암호화 목적 이름, Windows 자동 실행 항목과 데이터 폴더 식별자는 유지한다. 이름 변경으로 기존 계정·DB·키·자동 로그인 파일을 이동·초기화하지 않는다. 기존 설치 위치 이름에 Yeoyang이 남아 있어도 다른 학교 자료와 공유하는 저장소가 아니다.

## 각 학교가 관리하는 범위

| 대상 | 학교에서 담당할 내용 |
| --- | --- |
| 서버 PC/VM | 설치·가동·중지·자동 시작·망 분리·OS/백신/방화벽·인증서 |
| 학교 관리자 | 최초 관리자 비밀번호, 구성원·직책·업무 권한·학급·분반·보호자 관계 |
| 학교 정책 | 실제 학교명·문의처·약관·개인정보 책임 주체·보유/파기·운영 검토 기록 |
| 학교 데이터 | 교내 업무 서버와 학교 소식 서버의 DB·첨부·암호화 키·백업·복원 |
| 배포와 장애 | 학교가 검토한 설치본의 수동 업데이트, 정전·UPS·장애 알림·복구 시험 |

서버는 학교별로 독립 설치한다. 서로 다른 학교는 서로 다른 학교 식별자와 데이터·키·백업 폴더를 사용한다. 같은 학교의 교내 업무 서버와 학교 소식 서버는 같은 학교 식별자를 사용하되 역할·저장소·관리자 인증을 분리한다. 같은 PC/VM에 여러 학교 데이터를 한 폴더로 합치지 않는다.

개발자의 중앙 학교 검색은 공개 접속 목록만 제공한다. 검색 등록으로 학교 서버의 관리자 권한, 계정 명부·메시지·첨부 열람 권한을 개발자에게 부여하지 않는다. 오류/장애 메일 같은 외부 연동은 학교가 별도로 검토·설정한다. GitHub에 DB·명부·비밀키·운영 설정·실제 보안 증빙을 올리지 않는다.

## 도입 순서

1. 공개 저장소에서 소스 또는 제공된 설치본을 받는다. 현재 저장소는 `yd043105-pixel/yymessenger`이며 제품명을 바꿔도 저장소를 강제로 이전하지 않는다. 현재 1.0.0은 출시 전 시운행 상태다. 정식 릴리즈·자동업데이트·모바일 스토어 배포를 완료한 것으로 보지 않는다.
2. [설치·사용 순서](operation-order.md)에 따라 해당 학교의 교내 업무 서버와 필요한 학교 소식 서버를 설치한다. 학교가 최초 관리자와 이후 운영 권한을 관리한다.
3. `config/registration-policy.draft.json`과 [학교별 보안 검토](security-regulatory-controls-2026-10-28.md)를 참고해 실제 학교의 문서를 보호 폴더에 작성한다. 기본 약관은 학교명·문의처가 비어 있는 검토 초안이다. 기존 학교가 별도로 설정한 약관과 DB의 과거 동의 기록은 이름 변경으로 덮어쓰지 않는다.
4. 서로 다른 학교가 같은 `schoolId`를 쓰지 않도록 정한다. 역할별 HTTPS 주소, 인증서·망·백업·운영 설정을 확인하고 가상 계정으로 먼저 시험한다.
5. 공식 중앙 검색을 이용하려면 [학교 신청·개발자 승인](school-directory.md)을 진행한다. 승인은 **중앙 목록에 표시하는 절차**이며 학교 서버의 설치·가동 허가나 교육청 보안성 검토 승인이 아니다.
6. 교사 PC와 교사용 앱, 학생·학부모용 앱에서 학교명·지역으로 선택하고 역할별 로그인·비대상 접근 차단·알림·업무 기능을 시험한다.

## 학교가 자체 검색 목록을 운영하는 경우

자체 배포본은 `config/school-directory.json`의 `sourceUrl`에 학교가 검토한 HTTPS 목록 주소를 넣고 `schools`에 실제 학교 정보를 포함해 빌드할 수 있다. 이 파일은 각 앱과 PC 프로그램에 포함되며 다운로드한 목록이 배포 주소를 임의로 바꾸지 못한다. `sourceUrl`을 빈 문자열로 두고 포함된 `schools`만 사용하는 구성도 가능하다. 임의 예시 학교나 유효하지 않은 주소를 실제 등록으로 넣지 않는다.

공식 중앙 목록을 쓰지 않는 학교의 자체 목록·배포는 중앙 검색 등록 승인과 별개다. 다만 TLS 검증·학교 식별자·역할 확인·학교별 보안 검토를 유지한다. 학교의 자체 목록에는 학생/교직원 명부·계정·비밀번호를 넣지 않는다. 별도 등록이 끝나기 전 연결이 필요하면 관리자 안내에 따라 접힌 **연결 도움**에서 학교 주소를 설정한다.
