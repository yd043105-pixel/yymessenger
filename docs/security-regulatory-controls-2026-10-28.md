# 학교별 보안 도입 검토와 운영 통제

2026-10-28 · 출시 전 1.0.0 · 개발 점검 및 학교 검토용

## 원문과 적용 판단

이 문서는 다음 공개 원문을 기준으로 작성했다. 학교별 규정과 관할 교육청의 적용 판단은 별도 확인한다.

요청의 ‘행정안전부 고시’는 관련 조문에 해당하는 「행정기관 및 공공기관의 클라우드컴퓨팅서비스 이용 기준 및 안전성 확보 등에 관한 고시」로 해석했다. 다른 고시를 뜻한 경우에는 고시명·발령번호를 대조해야 한다.

| 요청 조항 | 확인한 의미 | 프로그램과 제출 자료의 대응 |
| --- | --- | --- |
| [행정안전부고시 제2025-79호 제11조제1·2항](https://www.law.go.kr/LSW/admRulInfoP.do?admRulSeq=2100000270616) | 국가 정보보안 지침·N2SF·국가 클라우드 가이드라인 준수 및 보안인증 서비스 우선 고려 | 서비스·처리 위치·관련 검토 증빙을 기록한다. 코드 점검으로 CSAP 취득을 주장하지 않는다. |
| [교육부예규 제82호 제41조제2항](https://www.law.go.kr/admRulInfoP.do?admRulSeq=2100000231430) | 국내 저장·관리, 공공 영역 분리, 이용 가능 서비스와 계약·사고 대응 등의 조건 | 엄격한 민간 클라우드 검토 경로에서는 국내 위치 선언과 관련 문서가 누락되면 기동하지 않는다. 실제 사업자 적합성은 학교가 확인한다. |
| 같은 지침 제14조 | 사업 계획단계의 보안성 검토 시기·절차 | 결정 문서와 사업 범위·검토 근거를 기록한다. 개발자의 자체 검사와 기관의 검토를 구분한다. |
| 같은 지침 제17조 | 사업 개요·계획·제안요청·망 구성·자체 보안대책 등의 제출 | [제출 자료 초안](security-review-submission.draft.md)의 다섯 부분을 실제 학교 자료로 확정한다. |

고시 제2조제2호의 공공기관 정의는 사립학교를 제외한다. 이를 모든 학교의 보안 의무 면제로 확대하지 않는다. 교육부 지침 제41조제7항의 교육현장 규정과 제16조의 검토 생략 가능성도 **학교가 적용 범위와 근거를 판단**해야 한다. 교직원 업무 메신저를 포함한 전체 시스템이 교육활동 예외에 해당한다고 자동 처리하지 않는다. 제14조의 사립대학 관련 단서를 사립고등학교에 그대로 적용하지 않는다.

국가 지침·N2SF·클라우드 가이드라인의 모든 통제 항목에 대한 운영 환경 실사를 완료한 결과가 아니다. 기관이 사용하는 판본과 사업 등급에 따라 추가 항목을 검토한다.

## 이번에 반영한 동작

1. Production 서버는 학교별 검토 파일을 읽은 뒤에만 데이터 저장소를 연다. 파일 없음·초안·다른 역할·만료·미래 검토일·중복 JSON 필드·누락 자료·증빙 해시 변경·허용한 수신 주소 변경을 거부한다. 시험 모드 Development는 운영 승인으로 표시하지 않는다.
2. 외부 연동은 목적·호스트·포트·메일 수신처를 기록과 대조한다. 오류 메일과 장애 알림은 서로 다른 목적이다. 학교 소식 연결과 메일 송신도 확인을 거친다. 실행 중 메일 수신처 변경이나 검토 만료는 승인된 기록으로 처리하지 않는다.
3. 외부 업체·처리 국가를 모르는 상태를 국내 처리로 간주하지 않는다. Cloudflare Tunnel과 개인 Gmail을 쓴다는 사실만으로 국내 저장·공공 전용 영역·CSAP 조건을 충족했다고 표시하지 않는다. 학교 소유 서버가 외부 중계를 이용하는 경우에도 해당 중계를 외부 서비스 목록에 포함한다.
4. 관리자 프로그램의 **운영 현황 → 계정·학교 → 보안 도입 검토 기록 확인**에서 적용된 기록을 조회한다. 일반 계정은 이 API를 사용할 수 없다. 증빙 경로·해시·메일 수신처를 조회 응답에 노출하지 않는다.

증빙의 SHA256은 파일 변경을 찾는 수단이다. 문서의 진위, 작성자의 권한, 사업자 인증의 유효성을 인증하는 전자서명이 아니다. **status를 approved로 바꾸는 행위만으로 법적 승인이나 보안인증이 생기지 않는다.**

기존 역할별 권한·HTTPS·세션 회수·CSRF·서버 간 서명·파일 검사·보관 만료·졸업 파기·복원 검토는 유지한다. 학교 망·호스팅·Cloudflare 계정·방화벽 설정을 자동 변경하지 않는다. DB·키·첨부를 삭제하거나 이관하지 않는다.

관리자 프로그램의 이 PC 시험은 부모 프로세스의 실제 SMTP 계정·오류 자동 접수·다른 학교 약관/검토 파일을 이어받지 않도록 분리했다. 시험에서 실제 메일을 발송하지 않으며 운영 설정은 선택한 학교 파일의 값으로 전달한다.

배포 패키지에는 빈 검토 초안만 포함한다. 학교의 실제 검토 JSON·증빙 참조·외부 연동 기록은 설치파일에 섞이지 않도록 검사한다. 실제 학교 자료의 모든 민감성을 자동 판별하는 도구는 아니므로 원본 증빙은 보호 폴더에 보관한다.

## 학교에서 준비할 순서

1. 운영 학교의 공립/사립 구분, 교육활동/행정업무 범위, 사용할 기능, 내부용/외부용 역할을 확정한다.
2. [제출 초안](security-review-submission.draft.md)을 채우고 학교 보안 담당자에게 적용 기준·검토 주체·생략 가능 여부를 확인한다. 필요한 교육청 검토는 학교가 의뢰한다.
3. 사업자·서비스 상품·계약·저장/인증/로그/백업/관리 위치·국외 처리·위탁/제공·사고 대응을 확인한다. 인증은 사업자 이름이 아니라 **사용할 상품과 영역의 실제 인증 범위·유효기간**을 확인한다. 인증서나 계약을 개발자가 만들어 넣지 않는다.
4. 학교에서 확정한 결정 문서와 제출 자료를 서버 PC의 별도 보호 폴더에 저장한다. 실제 이름·네트워크·계약·증빙을 공개 GitHub에 올리지 않는다. OS 접근 권한과 별도 암호화 백업을 설정한다.
5. 설치 폴더의 config/deployment-review.draft.json을 보호 폴더에 복사한다. 아래 필드를 실제 검토 결과에 맞게 작성한다. 초안은 작동하지 않는 값으로 제공한다.
6. 확정 문서의 SHA256은 PowerShell의 Get-FileHash -LiteralPath '문서의 실제 경로' -Algorithm SHA256으로 확인한다. 각 documents 항목에 로컬 파일 경로와 해시를 기록한다. 같은 통합 문서에 필요한 부분이 모두 있으면 그 파일을 여러 항목에서 참조할 수 있다.
7. 운영 설정의 securityReviewFile에 검토 JSON의 절대 경로를 넣는다. 역할별 파일을 구분한다. 관리자 프로그램에서 운영 설정을 선택하고 사전 점검을 수행한다. 약관·망 분리·인증서·백업·UPS·메일 수신 등의 기존 준비 조건도 별도로 충족해야 한다.
8. 문서·주소·수신처·사업자·망 구성 변경 때 영향 범위를 다시 검토하고 기록과 해시를 갱신한 뒤 서버를 재시작한다. 검토 기록과 증빙은 DB 자동 백업과 별도로 보호·백업한다.

## 검토 파일의 필드

| 필드 | 작성 기준 |
| --- | --- |
| schema / status | 1 / 학교가 실제 확정한 경우에만 approved. 기본은 draft |
| school / service | 실제 운영 학교 / office 또는 announcements |
| schoolId | 학교 운영 식별자. 학교 코드 또는 별도 고정 식별자를 정하고 운영 설정의 schoolId와 일치시킴. 학생 고유번호·사용자 ID와 다름 |
| basis | 아래 표의 검토 경로. 법정 인증 등급이 아님 |
| institutionType | 교육현장 경로는 education-site. 적용 근거 문서도 필요 |
| reviewAuthority | 실제 학교의 검토·결정 책임 주체. 개발자 이름으로 대신하지 않음 |
| reviewedAt / expiresAt | 실제 검토일과 학교가 정한 재확인 기한. 법령이 일률적으로 정한 유효기간이라고 설명하지 않음 |
| listenUrls | 실제 수신 주소 전체. https://0.0.0.0:8443 같은 명시적 주소를 사용하고 설정과 일치시킴 |
| storageCountries / managementCountries | 확인한 국가의 두 자리 대문자 코드. 미확인 값을 KR로 쓰지 않음 |
| documents | 일반 경로: decision·overview·plan·requirements·network·security. 교육현장 경로: decision·education-applicability·security의 path·sha256 |
| externalServices | 실제 연동의 purpose·host·port·recipient·provider·kind·processingCountries·evidenceId |

| basis | 추가 조건 |
| --- | --- |
| on-premises | 자체 서버 검토. 제3자 클라우드를 이 경로로 숨길 수 없음 |
| school-education-41-7 | 학교장 승인 decision, 교육현장 적용 범위 판단 education-applicability, 자체 보안대책 security를 기록한다. 해당 사업의 검토 생략을 적용하면 일반기관 제출 문서·CSAP 증빙을 일괄 요구하지 않는다. 업무 전체에 대한 면제를 자동 인정하지 않음 |
| private-cloud-41-2 | 국내 저장·관리·연동 처리 선언, domestic-location·public-separation·provider-eligibility·cloud-contract·csap-consideration·national-guidelines 증빙 필요 |

외부 연동 purpose는 tunnel(외부 중계), school-bridge(학교 소식 서버), error-mail(오류 메일), operations-mail(장애 메일), neis(해당 기능을 실제 도입할 때)다. host에는 프로토콜·경로를 제외한 정확한 호스트를, 메일 recipient에는 실제 검토된 주소를 입력한다. kind는 school-owned·third-party-cloud·public-data 중 실제 운영에 맞는 값을 사용한다. 증빙 목록과 연결하는 evidenceId도 필요하다. 단말 간 원격지원·개발 도구·앱 스토어 등 JSON 검사의 직접 대상이 아닌 흐름도 제출 자료에서 누락하지 않는다.

증빙 파일은 로컬 일반 파일이어야 한다. 네트워크 드라이브·UNC·연결된 경로를 허용하지 않으며 JSON은 256KB, 증빙당 8MB로 제한한다. 원본 증빙이 크면 학교가 검토한 축약본/분할본을 로컬에 보관하고 참조 범위를 문서에 적는다. 이 용량은 제품의 보호 한도이며 법정 용량 기준이 아니다.

## 진단과 남은 확인

합성 자료를 사용한 로컬 검사에서 검토 통제 64개, 관리자 네이티브 동작 46개, 기본 기능·보안·UI 회귀 93개가 통과했다. 약관 21개, 공지 25개, 서버 간 공지 연결 11개, 백엔드 강화 23개, 오류 메일 14개, 운영 29개, 역할별 저장소 분리 2개와 양쪽 서버의 민감 로그 차단 검사도 통과했다. 실제 학교 운영 자료·사업자 인증·모바일 실기기·Windows 키보드 주입 검증을 이 결과에 포함하지 않는다. 실제 메일을 발송하거나 학교 네트워크 설정을 변경하지 않았다.

security-review-missing은 검토 파일 미선택, security-review-invalid는 파일·증빙·실제 연동 대조 실패다. 세부 이유는 서버 실행 기록의 review-* 코드를 확인한다. 검토 파일 점검 모드는 --deployment-review-check이며 저장소·서버 리스너를 만들지 않는다.

독립 장애 감시 PC도 메일을 발송하려면 검토 파일·증빙과 점검용 서버 실행 폴더가 필요하다. executable은 해당 로컬 실행 파일을 가리키게 한다. 점검 모드는 서버를 가동하지 않는다. 실제 발송 시험은 운영 담당자가 학교에서 승인한 수신처로 진행한다.

운영 도구는 server-capabilities.json의 실행 파일·관리 코드 해시를 먼저 대조한다. 점검 모드를 모르는 이전 실행 파일을 실수로 기동하지 않기 위한 호환 검사이며 코드 서명이나 보안 인증이 아니다. 별도 감시 PC에 점검 도구를 옮길 때 이 파일을 포함해 서버 실행 폴더 전체를 복사한다. 기존 운영 설정에는 schoolId·securityReviewFile을 추가해야 한다. 이전 데이터와 설정을 자동 초기화하지 않는다.

프로그램은 문서의 내용·승인권자·CSAP 등록 정보·클라우드 실제 처리 국가·인증/로그/백업의 실제 배치·N2SF 전체 충족·학교 방화벽/백신·물리 분리·UPS·학교별 적용 법령을 자동 인증하지 않는다. 외부 중계나 OS 관리자가 바꾸는 설정도 앱 하나로 통제할 수 없다. 자체 검토 기록, 에듀집 자료, 학운위 심의, 교육청 보안성 검토, 서비스 인증을 서로 대체되는 절차로 취급하지 않는다.
