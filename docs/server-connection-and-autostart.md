# 서버 자동검색·이름 로그인·자동 구동

2026-10-23 · 배포 전 버전 1.0.0

Windows 메신저와 교내 업무 서버에 적용한다. 학생·학부모 외부 앱 서버를 검색하거나 업무 서버를 외부에 공개하는 기능은 아니다.

## 서버 PC: 자동검색 켜기

1. [기존 설치 순서](installation-and-test-order.md)대로 업무 서버를 한 번 수동으로 시작한다. 교내 HTTPS 주소와 신뢰할 수 있는 인증서가 먼저 필요하다.
2. 같은 서버 PC에서 메신저를 실행하고 준비한 HTTPS 주소로 별도의 관리자 계정에 로그인한다. 관리자 시스템의 **서버 운영** 화면이 열린다.
3. **교내 서버 자동검색 설정 → 교내 서버 자동검색 허용**을 체크한다.
4. 다른 교사 PC에서 접속할 HTTPS 기본 주소를 입력하고 저장한다. 인증서 이름과 주소 이름이 일치해야 한다. `/api` 같은 경로를 붙이지 않으며 `localhost`·`127.0.0.1`은 검색용 주소로 사용할 수 없다.
5. 약 1초 후 새 설정이 적용된다. 데이터 폴더의 `discovery.json`에 저장하고 다음 서버 시작에도 유지한다.

사진의 `10.85.88.101`은 기존 쿨메신저 서버 정보다. 새 서버와 인증서를 그 주소로 설정했는지 확인하기 전에는 새 프로그램 주소로 단정하지 않는다. 실제 주소를 소스나 설치파일에 임의로 넣지 않았다.

검색은 **UDP 45983**, 실제 로그인·자료 통신은 기존 HTTPS 포트를 사용한다. 필요한 경우 학교 네트워크 담당자가 업무 서버 실행 파일의 UDP 인바운드를 교직원망·로컬 서브넷에 한정하여 허용한다. 프로그램은 방화벽을 자동 변경하지 않는다. Windows의 전체 ‘네트워크 검색’이나 파일 공유를 켤 필요는 없다. 외부 인터넷에 UDP 검색을 개방하지 않는다.

다른 VLAN·무선 격리·방화벽 정책에서는 검색되지 않을 수 있다. HTTPS 주소 직접 입력은 계속 제공한다. 검색은 시작할 때 한 번 또는 버튼을 눌렀을 때 약 4초간 실행하며 인증서 확인에 최대 약 3초가 추가될 수 있다. IP 전체의 포트를 순회하거나 상시 탐색하지 않는다. 검색 응답은 512바이트 이하이며 발신 IP별 1초에 한 번만 응답한다. 계정·비밀번호·명단·메시지는 보내지 않는다.

검색 결과는 주소에 대한 힌트다. 메신저는 nonce·응답 네트워크·주소 형식을 검사하고 응답 PC에 직접 HTTPS 연결하여 인증서를 정상 검증한다. 첫 연결은 사용자가 학교에서 안내한 주소와 비교하여 확인한다. 유효한 인증서를 가진 타인의 서버도 있을 수 있으므로 표시된 학교 이름만 믿지 않는다. 이 과정에 로그인 정보는 보내지 않으며 저장된 서버를 다른 검색 결과로 자동 교체하여 로그인하지 않는다.

## 관리자: 이름 아이디와 초기 비밀번호

1. **교직원 계정 · 승인 → 교직원 사전 등록**에서 교사 이름을 입력하면 로그인 아이디에 자동 반영한다.
2. 동명이인은 `김교사.2`처럼 구분하여 당사자에게 안내한다. 같은 아이디의 중복 등록은 차단한다.
3. 새 교사 계정의 초기 비밀번호는 **12345678**이다. 첫 로그인에서 개인 비밀번호로 바꿔야 한다. 좌석 IP는 선택 관리 정보이며 로그인 아이디가 아니다.
4. **본인 이름 + 12345678**로 최초 로그인한 뒤, 관리자가 개별 전달한 활성화 번호·필수 약관 동의·새 개인 비밀번호와 확인 값을 입력한다. 개인 비밀번호는 12~128자이며 초기 비밀번호를 그대로 사용할 수 없다. 완료 후 본인 이름과 개인 비밀번호로 다시 로그인한다.
5. 기존 계정은 **계정 상태 · 좌석 · 초기화 → 해당 교사 → 좌석 · 초기화 관리**에서 이름 아이디를 확인하고 **계정 초기화 · 활성화 번호 재발급**으로 전환한다. 사용자 번호·업무 기록은 유지하고 모든 기존 로그인 세션은 회수한다. 새 활성화 번호를 개별 전달한다.

업데이트만으로 기존 아이디나 개인 비밀번호를 일괄 변경하지 않는다. 이전 버전에서 이미 활성화한 상시 공통 비밀번호 계정은 다음 로그인·세션 복원 시 개인 비밀번호 변경 화면으로 안내하고, 변경 전에는 메시지·첨부·채팅·설문·원격지원 등 업무 API에 접근할 수 없다. 기존 개인정보는 유지한다. 공통 비밀번호가 이미 다른 사람에게 알려진 운영 계정이라면 관리자가 활성화 번호를 재발급하여 본인 확인부터 다시 진행한다.

2026-10-23 정책 변경: **12345678은 초기 비밀번호로만 사용**한다. 개인 비밀번호 설정 전에는 업무 자료와 자동로그인을 사용할 수 없다. 비밀번호를 바꾸면 초기 비밀번호와 기존 세션이 무효화된다. 이후 PC 설정 메뉴와 교사용 앱의 내 정보에서 비밀번호를 다시 변경할 수 있다. 관리자 계정은 별도의 12~128자 비밀번호를 사용하며 초기 비밀번호 상태인 교사의 관리자 승격도 차단한다.

## 교사 PC: 자동로그인

1. 메신저 첫 실행 시 자동검색한다. 결과에서 학교가 안내한 주소를 확인하고 **이 서버 주소 사용**을 누른다. 찾지 못하면 주소를 직접 입력한다.
2. 최초 개인 비밀번호 설정을 마친 후 이름과 개인 비밀번호를 입력하고 **이 Windows 계정에서 자동 로그인**을 체크한다.
3. PC를 켤 때 메신저도 열리게 하려면 **Windows 로그인 시 자동 실행**을 체크한다.
4. 로그인 후 앱을 종료했다 다시 실행해 확인한다. 같은 Windows 사용자 계정이어야 한다.

비밀번호 대신 로그인 쿠키를 Windows DPAPI로 암호화해 저장한다. 유효기간은 최대 30일이며 로그아웃·관리자 초기화·비활성화·만료 시 다시 로그인한다. 공용 Windows 계정에서 자동로그인을 켜면 그 Windows 계정을 쓰는 사람이 메신저를 열 수 있다.

## 서버 PC: 재부팅 후 자동 구동

메신저 자동 실행과는 별개다. 서버는 Windows에 아무도 로그인하지 않아도 실행되도록 작업 스케줄러의 **컴퓨터 시작 시** 작업을 사용한다.

1. [서버 운영 준비 안내](server-setup-school-tunnel.md)에 따라 운영 설정 JSON과 같은 폴더의 `server-operations.secrets.xml`을 준비한다. 배포 ZIP의 `config/server-operations.example.json`은 양식이다. 실제 경로·인증서·운영 계정·백업·UPS·알림 준비를 입력해야 한다.
2. 예를 들어 설정을 `C:\SchoolMessengerOperations\office\server-operations.local.json`에 보관한다. 비밀 파일을 만든 **전용 표준 Windows 운영 계정**으로 관리자 메신저를 실행한다. 앱의 관리자 권한과 Windows 관리자 권한은 다르다.
3. **서버 운영 → 서버 PC 재시작 후 자동 구동 설정 → 운영 설정 파일 선택**에서 위 JSON을 고른다.
4. **설정 상태 확인 → 자동 구동 켜기**를 누른다. 미등록이면 기존 준비 점검 후 Windows 운영 계정의 인증 창으로 등록한다. 기존 작업은 계정·명령·설정 경로가 정확히 일치할 때만 활성화한다.
5. 업무 서버는 `YeoyangMessenger-office-Start`, 학교 소식 서버는 `YeoyangMessenger-announcements-Start`로 구분한다. 두 서버를 운영하면 각 운영 설정 파일로 등록한다.
6. 예정된 시간에 서버 PC를 재부팅한다. Windows 계정에 로그인하기 전, 다른 교사 PC에서 서버에 접속되는지 확인한다.

최초 등록에는 기존 감시 작업도 포함한다. 버튼을 눌러도 서버를 하나 더 실행하거나 PC를 재부팅하지 않는다. 비정상 종료는 1분 간격으로 최대 3회 재시작하며 무응답·정전·하드웨어 고장을 모두 해결하는 기능은 아니다. **자동 구동 끄기**는 다음 부팅의 시작 작업만 끄고 현재 서버와 감시 작업은 종료하지 않는다. Windows 운영 계정 비밀번호를 바꾸면 예약 작업 인증 정보도 갱신한다.

다른 배포 경로에서 등록한 작업은 덮어쓰지 않는다. 경로 불일치 시 원래 등록에 사용한 스크립트·설정·Windows 계정을 확인하여 전환한다. 다른 PC의 작업을 변경하거나 서버에 원격 명령을 보내는 API는 추가하지 않았다.

## 시험 범위

가상 계정·데이터, 루프백 통신, 예약 작업 모의 객체로 검사한다. 실제 학교 방화벽 변경·운영 작업 등록·서버 재부팅·인증서 저장소 변경은 자동 시험에서 수행하지 않는다. 실제 교직원 PC 두 대의 자동검색과 예정된 서버 재부팅 시험은 학교에서 최종 확인해야 한다.
